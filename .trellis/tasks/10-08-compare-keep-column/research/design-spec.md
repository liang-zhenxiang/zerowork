# 「留为会话」：对比屏完成态的收获动作 —— 设计规范

> 面向实现（可落到 JSX / 行为级）。依据：上一轮
> `.trellis/tasks/archive/2026-10/10-07-multi-model-compare/research/design-spec.md`
> （对比屏的完整施工图，本设计在它的语言里加东西）、`docs/DESIGN.md`（§2.1 文字三级 /
> §2.4 状态色只表状态 / §3.9 盒子预算 / §4 三态 / §6 禁止清单 / §7.6 状态不只靠颜色 /
> §7.9 hover 控件）、`.trellis/spec/renderer/index.md`、
> `src/renderer/src/app.css` 的 `.compare-col` 一带（`app.css:11020-11134`）与
> `.mini-btn` 一族（`:7156-7196`）、`src/renderer/src/app.js` 的 `CompareView`
> （`app.js:68540-68880`）与 `AssistantActions`（`:31942-31996`）、
> 以及唯一一张截图 `artifacts/multi-model-compare/compare-done-light.png`（完成态）。
>
> **本设计不新增任何 token、档位、颜色、动画、§5 例外；
> 并且比上一轮更进一步——零新类名、零新 CSS 声明。**
> 「留为会话」是**这一列**的动作，不是整屏的；全部形态由既有类承担。

## 0. 一句话结论

- **入口在列内底部操作条**——每列正文末端那条**常驻**的 `.entry-toolbar-left`
  （今天承载「复制」的那行，`app.js:68736`）——的第一个槽位：一颗 `.mini-btn`
  文字钮**「留为会话」**，**只在 `data-status="done"` 的列渲染**。
  「留为会话」与「复制」同族：都是「把这份答案拿走」的动作（复制拿走文本，
  留为会话拿走整轮问答），放同一行是零结构成本的天然归属。
- **点击之后按钮就地走完三段**：`留为会话`（可点）→ `正在留为会话…`（disabled）→
  `已留为会话`（`.mini-btn.saved` + `disabled`，`--ok` 色确认，持续态），
  同行多出一颗安静的 `去这条会话 →`（`.bar-btn.bar-btn-text`，点击走
  `resumeTask` 跳到那条新会话）。
- **成功不弹 toast**：就地持续态强于瞬态 toast（四列可各自留，toast 会叠；
  用户滚动比较回来还要认得出哪列留过）。**失败走既有 error toast**
  `没能留为会话：{原因}`，按钮回到可点 = 天然的重试入口。
- **反馈三件套全是既有先例**：`.mini-btn.saved:disabled`（settings 为
  「存上了」专门造的形态）、error toast 通道、`resumeTask` 跳转
  （「定位到来源会话」同款路径）。

## 一、诊断

### D1【不是问题】列内已有一条常驻操作行，入口槽位是现成的

每列的答案 entry 末端渲染 `AssistantActions`（`app.js:68731-68737`），它输出
`.entry-toolbar.entry-toolbar-left`——**常驻**（不是 hover 浮现的那套
`.entry-toolbar-right`），`margin-top: 12px`、`flex-wrap: wrap`
（`app.css:4339-4345`）。对比屏今天只传 `text`，所以这行里只有一颗「复制」图标钮。

三个判断：

1. **行是常驻的，入口才可发现**。「留为会话」是完成态的核心出口，
   藏进 hover 会让「这屏的答案能收走」这件事不可见。
2. **行内有现成的「文字动作领衔」槽位**：对话页这行是
   `[执行计划](bar-btn-text) [复制](bar-btn) …`（`app.js:31960`）——
   文字动作在第一个、图标动作随后。留为会话放进同一个槽位次序。
3. **行内已有「就地确认成功」的语言**：复制钮点击后 `IconCopy → IconCheck`
   就地互换（`app.js:31961-31970`）。就地反馈（而非 toast）在这行里有先例。

### D2【真问题】列头不是这个动作的家

`.compare-col-head` 是 sticky 的**表头**：身份（模型名）+ 耗时 + 用量读数。
往里塞一颗文字钮会同时踩三条上一轮立下的规则：

- **名字是身份，不许是被省略的那一个**（上轮 §2.3A）：4 列时每列 210px，
  行 1 已排「名字（可省略）+ 耗时」，再进一颗边框钮会把名字压到 ~100px。
- **四列读数落在同一条水平线**是本屏全部意义（`.run-metrics { width: 100% }`
  强制换行，`app.css:11106`）：列头是 `flex-wrap`，多塞一颗钮在窄列里会
  把**它自己**挤去第二行、顶乱读数行的起点。
- **表头不做动作区**：列头是读数区；四列异步完成时按钮在 sticky 头里
  逐个出现/消失，滚动时长答案时头恒在而按钮状态跳变，读起来像闪烁。

语义上也不对：**「收下这份答案」是内容终点的动作**——用户把答案读完才决定
留不留。对话页把「执行计划」放在计划读完后、正文下方，是同一个判断。

### D3【真问题】`AssistantActions` 是 per-entry 组件，「留为会话」是 per-column 动作

当前装配下每列恒为单 entry（一问一答、不跑工具，`app.js:68742-68747` 的注释
明文），per-entry 的操作行事实上就是列尾；但**语义上不许借用现成的
`showBranch` / `onBranch` 槽**——那是「分支出新会话」，上一轮已裁定本屏
不传（「这两个键是谎按钮」），今天也不能把「留为会话」塞进那个语义。

**处置**：给 `AssistantActions` 加一个可选的 ReactNode prop（渲染在「复制」
之前，即「执行计划」证明过的领衔槽位形态），由 `CompareView` 传列级内容。
零新类、零新 CSS；聊天页不传该 prop，行为不变。

### D4【不是问题】三个反馈通道全有先例，形态不必发明

| 需求 | 既有先例 | 取用 |
| --- | --- | --- |
| 「存上了」的视觉确认 | `.mini-btn.saved:disabled`（`app.css:7181-7187`）——settings 的 `useSavedFlash` 专门为它写的规则，注释原话「否则『存上了』这件事只剩一个变灰的文字」 | 直接复用；但用作**持续态**而非 1.5s 闪现（见 §2.3） |
| 失败反馈 | error toast（`showToast(error)`，导出失败先例 `app.js:69611`）；本屏已有 `对比没能开始：{原因}` 同构文案 | `没能留为会话：{原因}`，error 档 |
| 跳到那条会话 | 「定位到来源会话」（`app.js:67610`，`mini-btn` → `resumeTask`）；`resumeTask` 内部 `setView("chat")`（`:69532-69537` 注释）；箭头后缀先例「去设置里填 API Key →」（`:68699`） | `去这条会话 →` |

### D5【要如实写进规范】离开对比屏 = 一切重置，已留标记不例外

`CompareView` 条件挂载（`app.js:70133-70135`），状态在组件内 `useState`——
离开再回来，列、答案、**已留标记**全部归零。这不是缺陷：本屏的产品承诺就是
「不进历史」，**留下的事实由侧栏那条会话承担**（那才是单一事实来源），
对比屏自己从不记账。推论也要写明：同一列在重新进入后可以再留一次，
产生第二条会话——**每次点击都是一次显式选择，不去重、不合并**，
诚实于用户意图（真重复了，删一条会话即可，那是会话管理的既有能力）。

## 二、设计规范

### 2.0 共同约束（边界先说死）

1. **零新增 token / 档位 / 颜色 / 动画 / §5 例外**；`npm run check:theme-tokens`
   与 `check:design-exceptions` 不需要任何新条目。
2. **零新类名、零新 CSS 声明**（比上一轮「新类名只有 3 个」更进一步）。
   验收断言：本功能新增 CSS 为**空文件级**的零——若实现确需选择器钩子
   （例如测试定位），用 `data-*` 属性，不许新造类。
3. 复用的类**只有**：`mini-btn` `mini-btn saved` `bar-btn` `bar-btn bar-btn-text`
   `entry-toolbar` `entry-toolbar-left`，外加既有图标 `IconCheck`（本设计实际不用新图标）。
4. 「留为会话」永远不做整屏按钮（见 §五）。

### 2.1 结构：槽位与 DOM

```jsx
// CompareView → renderAnswerEntry → AssistantActions 增加一个可选 node prop
//（命名实现自定，如 keepSlot），渲染在「复制」之前 —— 即「执行计划」证明过的领衔槽位。

// ── done 列 · 未留（idle）──
<div className="entry-toolbar entry-toolbar-left">
  <button type="button" className="mini-btn"
          title="把这一轮问答留成一条独立会话，出现在侧栏、可继续对话"
          onClick={() => keepColumn(column.columnId)}>
    留为会话
  </button>
  {/* ↓ 既有：复制（本行今天就有，不动） */}
  <button type="button" className="bar-btn" aria-label="复制回答" … />
</div>

// ── done 列 · 保存中（saving）── 同一颗钮，disabled + 换文案：
  <button type="button" className="mini-btn" disabled title="正在留为会话…">
    正在留为会话…
  </button>

// ── done 列 · 已留（kept，持续态）──
<div className="entry-toolbar entry-toolbar-left">
  <button type="button" className="mini-btn saved" disabled>已留为会话</button>
  <button type="button" className="bar-btn bar-btn-text"
          title="打开留下的这条会话"
          onClick={() => onOpenKeptSession(column.keptSessionPath)}>
    去这条会话 →
  </button>
  <button type="button" className="bar-btn" aria-label="复制回答" … />
</div>
```

四条结构判断：

- **文字动作领衔、图标动作随后**：与对话页「执行计划 → 复制」同次序（`app.js:31960`）。
- **`.mini-btn` 而不是 `.bar-btn-text`**：本屏列体内已有 mini-btn 先例——失败列
  ErrorState 里的「重试」就是它；「留为会话」是完成态的核心出口，需要边框钮的
  实感，`bar-btn-text` 的安静档留给「去这条会话 →」（次要动作）。
- **文字钮、无图标**：mini-btn 在本仓是文字主导语言（重试 / 定位到来源会话 /
  去设置里填 API Key →），不为它引图标。
- **「去这条会话 →」是 `.bar-btn-text`**：它出现的时机是「状态已成」，行里
  已有一颗 ok 色的 disabled 钮承担视觉重心，跳转键走安静档；箭头后缀是
  「去……」类入口的既有写法。

### 2.2 状态表（列状态 × 保存子状态）

| 列状态（`data-status`） | 保存子状态 | 操作行的形态 |
| --- | --- | --- |
| `empty` / `queued` / `running` | — | **无入口**（只有复制；空列连复制也没有） |
| `failed` | — | **无入口**（ErrorState + 既有「重试」mini-btn） |
| `cancelled` | — | **无入口**（半截正文 + 既有 `.user-cancelled`） |
| `done` | 未留 | `.mini-btn`「留为会话」 |
| `done` | 保存中 | 同一颗钮 `disabled`，文案 `正在留为会话…` |
| `done` | 已留 | `.mini-btn.saved` + `disabled`「已留为会话」+ `.bar-btn-text`「去这条会话 →」 |
| `done` | 保存失败 | **回到「未留」**（钮可点即重试）+ error toast |

两条口径：

- **只在完成态出现**。取消列不给入口的理由：取消的半截答案是用户亲手掐断的
  判断材料，把它留成会话等于把半成品记成成品；真想要，让它跑完再留
  （重跑入口在输入卡）。失败列同理——没有可留的产出。
- **保存不锁屏、不阻塞新一轮提问**：保存是本地文件操作；若保存中用户重新
  提问，列重置为 `running`、操作行随旧内容消失——保存结果仍会以 toast /
  侧栏新会话的形式到达，状态是自洽的。

### 2.3 已留态（防重复 + 可追溯）

- **防重复点击由 `disabled` 本身承担**：`.mini-btn.saved:disabled` 规则只在
  disabled 时生效（`app.css:7184`），ok 色字 + ok 混边
  （`color-mix(in srgb, var(--ok) 40%, var(--border))`）正好覆盖
  `:disabled` 的灰字——这正是该规则被写下的理由（注释原话见 D4）。
  不进 Tab 序、`cursor: default`，全是 disabled 的既有语义。
- **用持续态而不是 1.5s 闪现**：settings 的 `useSavedFlash`（`SAVED_FLASH_MS
  = 1500`，`app.js:62972`）闪完就回；对比屏不能闪——用户要在四列间来回滚动
  比较，回来时必须还认得出**哪列已留过**。确认必须与列同寿命。
- **状态与动作分离**：「已留为会话」（状态，不可点）与「去这条会话 →」
  （动作，可点）是两颗元素。不合并成一颗「已留为会话 →」：
  其一，让 `.mini-btn.saved` 变成可点需要为它的**非 disabled** 形态新写 CSS
  （既有规则只覆盖 `:disabled`），破 §2.0 的零 CSS 边界；其二，状态混进按钮，
  「这条存了吗」会读成「这条能点」（§7.6：状态的第一顺位是形态与文字，
  可点性是动作的形态）。
- **列头读数位不动**：「已完成 12s」**不**改写成「已留为会话」——读数是
  对比数据（横向可比是本屏全部意义），「留没留过」是这一列的收获状态，
  归操作行。两个信息不共用一条通道。
- **「去这条会话 →」的行为**：`resumeTask(column.keptSessionPath)`——
  与资料库「定位到来源会话」同一条既有路径（内部 `setView("chat")`，
  `app.js:69532-69537`）。跳转即离开对比屏（重置，见 D5），按钮文案的
  「去」与箭头已如实预告。

### 2.4 失败态

- **唯一通道是 error toast**：`没能留为会话：{原因}`（`{原因}` 为 daemon 给的
  真实错误文本，与 `showToast(error.message)` 的既有口径一致）。
- **按钮回到「未留」形态**：列内容完好，再点一次就是重试——不需要专门的
  「重试」钮，按钮天然就是。
- **不做就地错误框、不做常驻红钮**：§4 的「错误就地呈现 + 重试」管的是
  **数据视图**的错误态；**动作失败**在本仓走 toast（导出 / 归档失败先例）。
  失败的是那一次落盘，不是这列答案——就地摆一块错误面会把「答案没问题」
  这一事实盖掉。toast 消失后按钮可点、列面干净，状态诚实。

### 2.5 用到的 token（全部既有，逐个写明）

| 用途 | token / 类 | 为什么是这一档 |
| --- | --- | --- |
| 钮底 / 边 / 字 | `--bg` / `--border` / `--text` | `.mini-btn` 自带（`app.css:7158-7170`）；抬升面上的一颗「实体」钮，与本屏失败列「重试」同款组合 |
| hover 底 | `--bg-hover` | `.mini-btn:hover:not(:disabled)` 既有（`:7172`）；这是真交互控件，借 hover 档名正言顺 |
| disabled 字 | `--text-secondary` | `:disabled` 既有（`:7176`）；「降一档」表达停用（§2.1） |
| 已留确认字 / 边 | `--ok` / `ok 40% + --border` | `.mini-btn.saved:disabled` 既有（`:7184`）；「已留为会话」是真成功状态，`--ok` 合法（§2.4） |
| 跳转键字 / hover | `.bar-btn-text`（`--text-list` 13px） | 次级动作走安静档；四态由 `.bar-btn` 一族既有规则承担 |
| 行内间距 | `.entry-toolbar-left` 自带 | `margin-top: 12px` + `gap: 6px` + `flex-wrap`，全是既有 |

### 2.6 交互四态 + 键盘可达性

**四态全部继承，本设计零追加**：

| 元素 | normal | hover | active | disabled |
| --- | --- | --- | --- | --- |
| 「留为会话」mini-btn | 白底细边 | `--bg-hover` | `scale(.98)`（共享块 `app.css:10769` 起，文字钮归 .98 组） | 灰字（保存中）；ok 字 + ok 边（已留，`.saved`） |
| 「去这条会话 →」bar-btn-text | 文字钮 | `.bar-btn` 一族 hover | `scale(.96)`（共享块 `app.css:10725` 起） | 无 disabled 态（路径失效即整行重渲染，不存在可点而死链的形态） |

过渡全部落在文件末尾两批共享规则（`:10725-10760` 按下态、`:10892-10990` 过渡），
**验收断言：本功能新增 `transition:` / `animation:` 声明数为 0。**

**键盘**：

| 步 | 元素 | 说明 |
| --- | --- | --- |
| … | 正文（可聚焦子项） | 既有 |
| n | 「留为会话」或「已留为会话 + 去这条会话 →」 | 真按钮，全局焦点环（2px `--text-secondary`）；DOM 序在「复制」之前，Tab 先到 |
| n+1 | 「复制」 | 既有 |

- **已留的 disabled 钮被 Tab 跳过**是正确语义（它是状态不是控件）；
  「去这条会话 →」紧随其后可达。
- **不加 `aria-live`**：与「复制」的 `IconCheck` 互换同口径（本仓对操作行的
  就地确认不做播报，靠可见文字与形态自释）——同一行内两种确认两种播报
  策略才是缺陷。

### 2.7 深浅两套主题

| 元素 | 浅色 | 深色 | 结论 |
| --- | --- | --- | --- |
| mini-btn 本体 | 白底 `#fff` + `--border` `#e6e6e6`，坐在 `--bg-raised` `#f7f7f7` 通道上 | `#1c1c1e` 底 + `rgba(255,255,255,.12)` 边，坐在 `#26262a` 上 | ✅ 与失败列「重试」同款组合，已上线形态 |
| hover | `--bg-hover` | 同（token 覆盖） | ✅ |
| 已留确认 | `--ok` `#0cbf5b` 字 + 40% 混边 | `--ok` `#32d74b` | ✅ token 双主题自动覆盖 |
| 「去这条会话 →」 | `--text` / `--text-secondary` 系 | 同 | ✅ |
| toast（失败） | `.toast-error`（`--danger` 图标） | 同 | ✅ 既有 |

`npm run check:theme-tokens` 零新条目：没有新颜色 token，也没有任何新增的
块外颜色字面量（连 `color-mix` 都只在既有声明 `.mini-btn.saved:disabled` 里）。

### 2.8 宽列 / 窄列（4 列 210px 时）

- 未留行 `[留为会话][复制]` ≈ 48px 文字 + 边距内距 + 28px 图标钮，单行无压力。
- 已留行 `[已留为会话][去这条会话 →][复制]` 在 210px 内可能**折行**——
  `.entry-toolbar-left` 自带 `flex-wrap: wrap`，其注释明文这是设计行为
  （「读数整段掉到第二行，而不是把行内元素挤出正文列」，`app.css:4340-4342`）。
  2/3 列单行。折行态**不需要任何新规则**。
- 通道等高由栅格 `align-items: stretch` 继续承担，操作行折行只影响本列内容高，
  不影响对比表的可读性（列头读数线不动）。

### 2.9 CSS 草案

## 三、文案终稿（可直接抄进实现）

| 位置 | 文案 |
| --- | --- |
| 按钮（done · 未留） | `留为会话` |
| 同上 `title` | `把这一轮问答留成一条独立会话，出现在侧栏、可继续对话` |
| 按钮（保存中，disabled） | `正在留为会话…` |
| 已留确认（`.mini-btn.saved` disabled） | `已留为会话` |
| 跳转键（`.bar-btn-text`） | `去这条会话 →` |
| 同上 `title` | `打开留下的这条会话` |
| 失败 toast（error） | `没能留为会话：{原因}`（`{原因}` = daemon 真实错误文本） |

### 按钮名为什么是「留为会话」

- **「留下来」**：作功能名好（四选一、谁留下，情感准确），作按钮名单看不知结果——
  留到哪？侧栏？收藏？且它的完成态要写成「已留下来」，歧义没解开。
- **「保存为会话」**：信息全但 5 字，且「保存」是文件系统口吻——本仓对会话
  说 导出 / 归档 / 分支，从不说「保存会话」；这个动作本质是**另起一条新会话**，
  不是保存覆盖。
- **「收下这答」**：「这答」是生造词，直接淘汰。
- **「留为会话」（采纳）**：4 字；动词「留」与功能名「留下来」同根，语境延续；
  宾语「会话」把**去向与结果**说清（这正是对比屏「不进历史、留的是新会话」
  这条承诺最需要被教会的一处）；状态对 `已留为会话` = 「已」+ 原短语，
  零翻译成本；失败 toast `没能留为会话` 同一短语三处一致。

## 五、明确不做

| 想法 | 理由 |
| --- | --- |
| 入口放列头（sticky 表头） | 见 D2：挤名字（名字是身份不许省略）、可能顶乱读数行的同一水平线、表头不做动作区；且「收下答案」是内容终点的动作，不是表头的事 |
| 成功 toast | 就地持续态强于瞬态 toast：四列可各自留（toast 会叠）、用户滚走再回来仍要认得出哪列留过；本行的复制确认（IconCheck 互换）也已是就地语言 |
| 整屏「全部留下」按钮 | 「留」是**这一列**的动作，是四选一/几选几的显式选择；一键全留等于把选择这个动作的意义取消，也和「留下的每条都是用户点名要的」这条产品口径冲突 |
| 把已留态做成可点的「已留为会话 →」单钮 | 既有 `.mini-btn.saved` 规则只覆盖 `:disabled`，启用态要新写 CSS（破零 CSS 边界）；且状态混进按钮，「存了吗」会读成「能点」（§7.6） |
| 给取消 / 失败列入口 | 取消的半截答案是用户亲手掐断的材料，留成会话等于半成品记成成品；失败列没有可留的产出 |
| 已留后改写列头读数（「已完成 12s」→「已留为会话」） | 读数是对比数据、横向可比是本屏全部意义；「留没留过」归操作行。两个信息不共用一条通道 |
| 保存中转圈（`.spinner`） | 本地文件分叉是几十毫秒的事，循环动画是为长等待造的；文字变化已足够，还免掉一个动效宿主（§10.3 的关停清单也不用碰） |
| 已留态加 `aria-live` 播报 | 与同行「复制」确认（IconCheck 互换 + title 变化）同口径：本仓对操作行的就地确认不做播报；同一行两种播报策略才是缺陷 |
| 跨屏记住「已留」标记 | 离开即重置是本屏既有行为与承诺（「不进历史」）；事实由侧栏会话承担，对比屏不记账。重复留产生的第二条会话是显式选择的结果，不去重（D5） |
| 新造任何类名 / 任何 CSS 声明 | 本设计达成零新类、零新声明；测试钩子用 `data-*` 属性 |
| ⌘K 命令面板加这条动作 | 面板动作是全局入口的「换一个入口」（`run` 只调既有全局通道）；「留为会话」依赖**哪一列**的上下文，没有全局语义 |
