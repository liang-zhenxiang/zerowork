## 这个 PR 做了什么

侧栏的会话列表**此前只有一种顺序：最近活动在前**。于是有必然的结果：越常用的会话
越会被新会话挤下去，任务区折叠到 5 行之后还会直接藏进「查看更多」——
「接着上次那件事做」每次都得先翻一遍列表。

现在会话行的 `⋯` 菜单里多了**「置顶 / 取消置顶」**：置顶的会话排到**它所属分区的最前**
（任务区，或它所在的那个工作空间），行首带一个图钉标记，**跨重启保持**。

## 为什么这么做（决定与理由）

| 决定 | 理由（完整版在 `.trellis/tasks/10-03-session-pin/design.md`） |
| --- | --- |
| 独立索引 `pins.json`，不写进会话文件 | 会话文件是 pi 的资产，写它要经过**活的** `SessionManager`；置顶只是纯展示偏好，不值得这种耦合。索引坏了最坏丢置顶，会话一根汗毛不少 |
| 置顶**只在分区内部**生效 | 侧栏是「任务 / 空间→会话」两层。全局置顶区会把行从它所属的工作空间**抽走**，用户会问「它怎么在这儿」；与 issue #73 的既有做法同构（VS Code 的 pinned tab 也是「排在原地最前，不搬家」） |
| 置顶项**不参与**折叠的 5 个名额 | 「钉住了却藏在『查看更多』后面」是这个功能最典型的失效形态，从窗口规则上根除 |
| ⚠️ 入口放 `⋯` 菜单，**不开第二个 hover 按钮** | `app.css` 里记着 2026-09-16 的刻意决定：「里面**只有一个「⋯」**……动作全收进 `.task-op-menu`」（四个 20px 图标并排在窄栏挤成一簇）。置顶是低频动作，不值得推翻它；而且**本机拿不到视觉验证**（见「未执行」），不适合动布局形态 |
| 不加每个分区的置顶数量上限 | 要防的失效形态已由窗口规则解决；加上限只是给一个自限行为再加一条拒绝路径与一套计数语义 |
| 不弹 toast | toast 在本项目的语义是**后台异步结果**；置顶的结果就在同一屏且可逆。失败路径照常弹 |
| ⌘K 排序、首页「最近会话」都不动 | 前者是检索排序（混进置顶会让「最匹配的不排第一」），后者的名字就是口径（两周没动过的置顶会话出现在「最近」里是撒谎）。两条都写进了任务文档的「非目标」 |

## 顺带修的一条既有缺陷（键盘可达性）

行内操作钮的容器 `.task-item-ops`（与空间组头的 `.space-group-actions`）用
`visibility: hidden` 隐藏 —— 它会把子树里的按钮**移出 Tab 序列**，于是
`:focus-within` **永远不可能触发**：会话行的「导出 / 重命名 / 置顶 / 归档 / 删除」
与组头的「+ / ⋯」对键盘用户完全关闭，而视觉上一切正常、截图断言也看不出来。
改为 `opacity` + `pointer-events`（后者是**硬要求**：只降透明度的话，透明按钮仍然
接得到点击，点行尾那一格空白就会误触一个看不见的按钮）。
规则写进 `docs/DESIGN.md` §7.9 与 `.trellis/spec/renderer/index.md` 的禁止清单。
