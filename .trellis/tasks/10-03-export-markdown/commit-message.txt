feat(session): 会话可以导出成 Markdown——把这次对话带走

会话此前只能导出成单文件 HTML（pi 的 exportToHtml）：自包含、能直接看，但带不走——
贴进文档、笔记、PR 描述都要 Markdown，而从 HTML 页面上复制出来的是带样式的 DOM。

四处落点：

1) 新增 session-markdown.js：把当前分支渲染成 Markdown 的纯函数，逐类对齐 pi 的 HTML
   导出认得的条目（用户、助手正文、思考、工具调用与结果、命令执行、压缩摘要、
   分支摘要、模型切换、产物交付），既不漏也不重复。
2) 新增通道 session:export-markdown，文件落在与 HTML 导出同一个 exports/ 目录。
3) 会话行 ⋯ 菜单里的「导出」改名为「导出为 HTML」，与新增的「导出为 Markdown」并列：
   此前要点完才知道出来的是 HTML，现在选择发生在点之前。
4) 条目取自活的宿主的 getBranch()：leaf 指针在内存里才是真值。自己 open 会话文件的话，
   pi 会把「最后一条条目」当成叶子——回退或分叉过的会话就会导出另一条分支，
   而这件事在界面上几乎无从察觉。

三条渲染口径：超长内容按与界面同一口径截断并标明原长度（否则一份十万字符的工具日志会灌进
用户正要发出去的文档里）、图片不内嵌 base64（只留占位）、代码围栏长度按内容算
（工具输出里出现三个反引号时，写死围栏会把整篇文档从那里截断）。

测试：15 条单元测试，其中一条用真实的 SessionManager 读预置会话文件做集成验证，
顺带锁住「只导出当前分支」；另有 GUI 用例（菜单两项并列、导出真的落盘且内容正确、
界面给的是成功反馈）与 ipc-functional 里从 Node 侧读回导出文件的断言。
反向验证两条都已真跑并还原：让 clamp 不截断 → 恰好 2 条红；把围栏写死成三个反引号 →
恰好 1 条红。

GUI 用例本机真跑过：export-markdown 3/3，全套 24 个 GUI 脚本合计约 370 条断言、0 FAIL。
