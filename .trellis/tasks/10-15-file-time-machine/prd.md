# PRD:「时光机」—— Agent 亲手改过的文件,都留一版

## 背景(为什么做)

Agent 每用 `write` / `edit` 工具改一个文件,daemon 在动手**之前**已经把那份
「改之前的内容」读进内存了 —— `session-host.js` 的 `readOverwriteTarget()`。
但它只被用来算一行「已修改 +12 −3」,**算完就丢**。于是:

> 用户看得见「它改了什么」,却**拿不回改之前的那一版**。

真实场景:一轮里 Agent 把你的 `周报.md` 改坏了、把整理好的表格覆盖成了半成品、
把能跑的数据清洗脚本改成跑不动的版本。此刻用户唯一的动作是「让 Agent 再改回来」——
既不保证能对得上,又是一次新的不确定性。没有 git 的办公目录连这根稻草都没有。

这条正是产品线的下一步:v0.6 是「把 Agent 干过的事**看得见、留得下**」,
v0.8 是「回来**续摊**」——那么轮到「退得回去」。

### 竞品核对(2026-10-15 检索)

- Cursor 的 checkpoint/restore、Windsurf(Cascade)的 **Named Checkpoints and Reverts**、
  VS Code 内置 **Local History** —— 「改动能退回去」已经是写代码这一侧的标配
- 而**同类本地 AI 桌面端**(Cherry Studio / Chatbox / LobeChat / Msty / AnythingLLM)里,
  把「**Agent 亲手改过的文件**」做成可按的版本历史与一键还原的,是空白
- 我们的**融合点**不是照抄一个「回退按钮」,而是把它接到本项目已有的身份上:
  每个版本都**挂在哪条会话、哪次工具调用**上;还原本身**写审计**

### 与既有能力的关系(不重复造轮子)

| 已有能力 | 它管什么 | 本功能与它的分工 |
| --- | --- | --- |
| git 工作树(`WorktreeChip`,代码场景可选) | **隔离**改动(在副本里干活) | 只覆盖 git 仓库;本功能覆盖**任意工作区**,含没有 git 的办公目录 |
| 会话「重新开始」(`restartSession`) | **会话级**回退(对话退到某一轮之前) | 不动文件;本功能是**文件级** |
| 资料库 / 导出 | 把产物**拿走** | 本功能把文件**退回去** |
| 工作轨迹条 | 显示这轮**改了什么** | 本功能在它旁边给出「**怎么退回去**」 |

## 期望(做什么)

### 1. 记录:每次**成功**的写入/修改,留下改动前的那一版

- 落点在 daemon 里 write / edit 工具的既有路径上 —— **复用已经读进来的
  `readOverwriteTarget()` 结果**,不新增任何读盘(`session-host.js:1023`)
- 只在**工具真实成功**、且这是「修改」而不是「新建」时记录;失败、被拦截、
  新建文件都不记(没被覆盖就没有旧版可留)
- 每条版本记下:该文件的**改动前全文** + `at` + `sessionId` + `tool`(write/edit)
  + 这次改动相对它的 `added` / `removed`
- 落在配置目录的 `versions/` 下(布局与上限见 `design.md`)

- **三条如实写下的边界**(是设计,不是「还没做」):
  - **只覆盖 Agent 用 write/edit 工具改的文件。** Agent 通过命令
    (`bash` / `powershell`)改的文件不在内 —— 那要在每次命令前后快照整个工作区,
    代价与收益不成比例
  - **只覆盖含 NUL 字节之外的文本文件**(二进制跳过,不假装记下了)
  - **单文件历史上限 20 版、单版体积上限 1 MiB**:超体积**跳过记录**;
    超版数**丢最旧**。界面要能把「这条被跳过了」说出来,不静默

### 2. 浏览:一个「文件历史」页面

- 侧栏新增入口「文件历史」(排在「资料库」之后),独立页面
- 左列是 **Agent 改过的文件**清单:文件名、所在目录、版本数、最后一次改动时间、
  来源会话标题
- 右侧是选中文件的**版本时间轴**:每个版本一个节点(时间 + **替换掉这一版的那次改动
  的行数变化** + 来源会话与工具),下接**该版本的只读预览**,再下接「还原到此版本」
  - 这是契约口径(`design.md` §3.1:每条版本记的是「这次改动相对它的 `added` /
    `removed`」),不是「相对上一版」。因此**最新一版没有行数变化** ——
    方案用它后面跟一句说明兜住,不给一个不存在的数字
- 三态齐备(加载 / 空 / 错误,`docs/DESIGN.md` §4)。空态如实说:
  「Agent 用写入/编辑工具改过文件之后,这里会留下历史版本」
- 视觉方案由 UI/UX 设计师 subagent 出稿(任务 `research/ux-proposal.md`),
  遵守 `docs/DESIGN.md` 的 token 档位与盒子预算纪律

### 3. 还原:一个要二次确认、会写审计的动作

- 「还原到此版本」→ 二次确认说清三件事:哪个文件、退到哪个时间点、
  **当前内容会先被存成一条新版本**
- 还原后:文件内容变成那一版;当前内容**先被记成一条新版本** ——
  所以还原本身也能再退回去,不是单向操作
- **写审计**:新增 `file` 类别 / `restored` 结果,进现有审计面板(设置 → 数据)
- **两种明确拒绝**(宁可拒绝,也不静默降级):
  - 目标文件所属会话**正在运行**时拒绝 —— 避免与正在进行的写入打架
  - 目标版本内容缺失 / 存储损坏时拒绝,并给出原因与逃生指引

## 非目标(本轮不做)

- 不做「Agent 通过命令改的文件」的快照(见上:成本与收益不成比例)
- 不做并排 diff 视图(本轮给行数变化 + 只读预览;真正的 diff 视图另行立项)
- 不做「会话内列出本次改了哪些文件」的第二入口(先做**文件**入口)
- 不做二进制 / 大文件版本,不做云同步,不做 git 集成
- 不做上限的可配置界面(20 版 / 1 MiB 是先写死的硬边界)
