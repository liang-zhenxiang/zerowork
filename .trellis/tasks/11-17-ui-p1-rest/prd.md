## 背景与需求

### 1. 首页输入卡在矮窗口掉出首屏

- 1280×860 下输入卡底边约 841（仅 19px 余量）；1280×679（CI 视口、13 寸笔记本可用高度）
  必然需要先滚动才能看到主输入框。
- 根因：`.home-inner` 的 `min-height: max(680px, 100%)` 与 `.home-main` 的
  `padding-bottom: 268px`（案例区预留）在矮视口下把内容顶出视口。
- 期望：`--home-case-reserve` 变量化（默认 268px）；`@media (max-height: 720px)`
  降到 160–180px 且 `min-height` 不再强制 680；输入卡在 1024×679 / 1280×679 下完整可见。
- **不改** §3.8 的 12:12:24:16 垂直节奏（那是 860 高下的正确答案）。

### 2. 统计页头部动作过多、两枚同款刷新图标

- 头部 5 个按钮：分享卡 / 本周摘要 / 导出 CSV / 刷新 / 重试首页；后两枚都用
  `IconRefresh`；空态下「分享卡」「本周摘要」仍可点。
- 期望：空态隐藏数据类动作（分享卡 / 本周摘要 / 导出 CSV）；「重试首页」不再用
  refresh 图标（与「刷新」区分），保留功能；空态仍可「刷新」。

### 3. 记忆空态「点击编辑添加」点不了

- `profile-view` 的空态文案邀请点击，但整块不可点；真正的入口只有右上角「编辑」。
- 期望：空态整块可点进入编辑（`role="button"`、`tabIndex=0`、Enter/Space 生效、
  焦点环、hover 提示）；或在不可点时改文案——**选前一种**，保留原承诺。

### 4. 侧栏空间组名被挤成 1–3 个字

- 组头是单行 flex：图标 + chevron + 名称 + 「当前」+ 计数 + 常驻操作区抢宽，
  名称只剩 1–3 字（「ze…」「季…」），右侧反而有空。hover 的 title 是完整 cwd，不是名字。
- 期望：组头改两行——第一行 `图标 + chevron + 名称（可省略）+ 当前徽标` 占满，
  第二行 `N 会话 · M 运行中` 缩进对齐名称；操作按钮仍右缘常驻（§7.9 不动）。
- 不改侧栏 264px 宽度。
