# GUI 环境已恢复（2026-10-16）

## 结论

先前的 GUI 阻塞**不是代码或依赖问题，是本会话执行环境的限制**，现已解除：
用户提供代理后 `export https_proxy/http_proxy/all_proxy`，
Electron 立刻能跑（`--version` → `v44.4.4`，exit 0），
macOS 自带的 `open /System/Applications/Calculator.app` 也从 `kLSNoExecutableErr`
变成 exit 0。

**先前的四个反证实验依然有效**（官方缓存解压的全新 44.4.4/44.4.3/44.3.0 全 134、
正在运行的百度网盘二进制也 134、macOS 自带 Calculator 报同一个错），
它们证明「不是文件损坏」；现在再补一条正向证据：**环境一变好，同一个二进制立刻可用**。

## 第一次真实运行就抓到一个真 bug

`gui-sections` 新增的断言第一次执行就红了 —— 正是它被写出来的目的：

```
[FAIL] 自动化：新建任务表单里有值守规矩，且与全局档位的关系如实呈现
       —— 表单里没有「值守规矩」这一组
```

**这条断言如果没写，这个 bug 会直接进主线**：值守规矩的四组控件压根没渲染出来，
而原有的「页面能打开、能渲染」断言全部照样通过（24/25 里其余全绿）。
「未执行过的断言」和「没有断言」在交付层面是同一件事 —— 这是本轮最直接的教训。
