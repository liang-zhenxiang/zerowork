# PRD：托盘值守（#422）

## 背景

竞品 WorkBuddy 卖「云端 7×24，关闭客户端也继续跑」。ZeroWork 是本地优先，
等价物是**关掉窗口后仍在托盘值守**：现在非 macOS 上 `window-all-closed` 直接
`app.quit()`，定时任务与长任务必须开着窗口；任务完成也没有系统通知。
对「定时任务 + 长任务」用户，这等于把最有价值的能力锁在窗口后面。

## 目标

1. **关窗不退出（可选）**：设置开启后，关闭窗口只隐藏到托盘，daemon 与会话继续；
   托盘菜单可显示窗口、看到运行中任务数、暂停/恢复值守、退出。
2. **完成通知**：会话一轮完成/失败时发系统通知；窗口在前台时不打扰；点击回到
   对应会话（窗口隐藏时先显示）。
3. **开机自启（可选）**：`app.setLoginItemSettings`，默认关。
4. **默认行为不变**：三项默认值分别为关 / 开 / 关；不开启关窗到托盘时，关闭窗口
   仍退出。

## 非目标

- Linux 支持（与平台支持范围一致）。
- 云端托管、移动端遥控。
- 通知中心历史 / 免打扰时段（本轮不做，保持小）。
- 托盘图标主题自适应之外的视觉定制。

## 约束

- **退出必须仍走既有收尾链路**：`before-quit` 的 `daemonShutdown` + 2.5s 兜底 +
  `writeCleanExitMarker`；托盘「退出」= `app.quit()`，不得新增绕过路径。
- 设置落盘在配置目录（不进 `preferences.json` 的 daemon 字段，避免两个写入方）；
  读失败按默认值，不阻塞启动。
- 通知内容不含敏感信息（不写会话正文）；不依赖 GitHub 脱敏之类外部机制。
- 通知不可用（权限拒绝 / 平台不支持）时**如实提示**，不静默假装发了。
- 不改变现有窗口/快捷键行为；`window-all-closed` 的 macOS 语义保持。

## 验收标准

- [ ] 设置页「通用」新增三项开关：关闭窗口时最小化到托盘 / 完成任务时通知 /
      开机自启；状态落盘、重启后保持。
- [ ] 开启「关闭窗口时最小化到托盘」后：关闭窗口 → 窗口不可见、进程与 daemon
      存活、托盘菜单可恢复窗口；**关闭该开关后行为恢复为退出**。
- [ ] 托盘菜单：显示主窗口 / 运行中 N 个任务 / 打开自动化 / 退出；
      「退出」走 `before-quit` 收尾（SessionEnd 预算不变）。
      （**不做「暂停值守」**：daemon 没有全局调度暂停，逐个暂停会改掉用户每条任务的
      `paused` 状态；这个语义需要单独设计，本轮用「打开自动化」给入口。）
- [ ] 完成通知：`run_finished`（completed / error）且窗口不在前台时发通知；
      前台不发；点击显示并聚焦窗口，并尝试切到对应会话。
- [ ] 开机自启：切换后 `app.setLoginItemSettings` 被调用且值可读回；平台不支持时
      给可读说明。
- [ ] 单测：设置读写/校验、关闭决策、通知决策（前台/后台/失败/开关）。
- [ ] e2e：真实 Electron 开启关窗到托盘 → 关闭窗口 → 主进程存活且窗口隐藏 →
      显式退出走收尾；设置页截图（亮/暗）。
- [ ] `CHANGELOG` 记「新增」；`docs/USAGE.md` 的「界面结构 / 设置」补一节。
