# PRD：跨 run 文本替换（#498）

## 背景

v1 只支持「完整落在一个 `w:t` 内、且全文唯一命中」的替换。但真实 Word 文档里一句话常被拆在多个 run（拼写检查、编辑历史、从 PDF / 网页粘贴），ADR-0001 明确记录这是真实文档的**常态**。当前遇到一律 `cross-run` 拒绝并让用户去 Word 手改 —— 这正是「AI 帮忙改文档」最该起作用的时候。

## 目标

1. 同一段落内、相邻 `w:t` 拼接后命中 `find`，且覆盖的 run 的 `rPr` **完全一致**（或都没有 `rPr`）时，合并定位并替换：新文本写入第一个被覆盖的 `w:t`，其余被覆盖的 `w:t` 文本清空；不删除 run、不动标签与属性。
2. 格式不同（`rPr` 不同）→ 仍拒绝 `cross-run`，理由与指引改成「命中跨了格式不同的 run」。
3. 判定边界：
   - 唯一性基于**拼接后的段落文本**；跨段落不拼接（段落边界是硬边界）。
   - 命中区间中间夹着 `w:tab` / `w:br` / `w:cr` 时拒绝 —— 视觉上不连续的文字不该被当作一句。
   - `w:t` 不在 `w:r` 内（结构异常）时拒绝并说明。
4. 写后自检覆盖新路径：每个 `w:t` 文本等于预期、段落拼接文本等于预期、其余条目逐字节不变。
5. 单 `w:t` 路径的行为与字节保持现状（现有测试全绿）。

## 非目标

- 格式不同的跨 run（v2 明确拒绝，给手改指引）。
- 跨段落拼接、结构编辑、页眉页脚（仍是后续）。
- 批量替换（#499）与上下文预览（#500）。

## 验收

- [ ] 夹具 A 的「跨 run 的文本」可被成功替换；替换后段落文本正确，`inspect_docx.py` 显示其余条目与版式特征不变
- [ ] 格式不同的跨 run 拒绝，错误码 `cross-run`，信息含「格式不同」与「Word 里手改」指引
- [ ] 跨段落的 `find` 不拼接 → `not-found`
- [ ] 拼接后多处命中 → `multiple-matches`（不因为跨 run 就放宽唯一性）
- [ ] 命中区间夹 `w:tab` / `w:br` → `cross-run` 拒绝
- [ ] 现有单 `w:t` 用例全部通过，不产生字节层面的回归
- [ ] 反向验证：去掉 `rPr` 比较 → 格式不同用例红
- [ ] ADR-0001 与工具描述同步：跨 run 从「v1 非目标」改为「v2 同格式支持」
