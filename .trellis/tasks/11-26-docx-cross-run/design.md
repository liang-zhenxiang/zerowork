# 设计：#498 跨 run 文本替换

## 一、定位模型

现有实现是「单个 `w:t` 文本包含 `find`」。v2 增加一层**段落内拼接定位**：

```
段落 w:p
  ├─ w:r  (rPr A) → w:t "跨 run 的"
  ├─ w:r  (rPr A) → w:t "文本"
  └─ w:r  (rPr B) → w:t "（加粗）"
```

1. 按最近的 `w:p` 祖先把 `w:t` 分组（保持文档顺序）；不在任何段落内的 `w:t` 自成一组。
2. 每组只拼接 `w:t` 的文本，得到「段落拼接串」。`find` 在**每组内**独立搜索。
3. 全文件出现总次数必须为 1：0 → `not-found`，>1 → `multiple-matches`（唯一性不因跨 run 放宽）。
4. 命中完全落在单个 `w:t` 内 → 走**现有路径**（字节改动最小，现有测试全部覆盖）。
5. 命中跨多个 `w:t` → 进入合并路径（下面三节）。

**段落边界不拼接**：`find` 的一半在一段、一半在下一段时不命中。

## 二、合并路径的接受条件

- 覆盖的每个 `w:t` 必须能向上找到 `w:r`（结构异常 → 拒绝）；
- 覆盖的 run 的 `rPr` **完全一致**（都无 `rPr` 也算一致）。比较用
  `ET.tostring(rPr, encoding="unicode")` —— 同一文档内同一格式的序列化稳定；
  属性顺序不同的等价格式会被保守拒绝（宁可拒绝，也不猜）。
- 命中区间跨过的 `w:t` 之间不能夹 `w:tab` / `w:br` / `w:cr`：
  视觉上不连续的文字不该被当成一句（用户从界面复制的一行可能实际含制表符）。

任一条不满足 → `cross-run`，信息写清是哪一条，并给「在 Word 里手改 / 缩短原文」的指引。

## 三、替换与文本映射

命中区间 `[s, e)` 映射到覆盖的 `w:t` 集合（按顺序）：

| 位置 | 新文本 |
| --- | --- |
| 第一个 `w:t` | 原文本前缀（`s` 之前）+ `replace` |
| 中间 `w:t` | 空串（保留 `w:t` 与 run，不删节点） |
| 最后一个 `w:t` | 原文本后缀（`e` 之后） |

- 只改 `w:t` 的内部文本；标签、`xml:space` 等属性、run 边界都不动。
- 跨 run 路径统一整段重新转义（`escape`）：多字节改动已经发生，追求「局部字节最优」没有意义；
  单 `w:t` 路径保留现有「规范转义时才局部拼接」的逻辑。
- 不删除被清空的 `w:t`：删除节点要处理 `w:r` 空壳、书签与内容控件，收益不抵风险。

## 四、自检

写后自检（`_verify_temp`）现有三项不变，`patch_part` 额外保证：

1. 每个 `w:t` 的文本等于预期清单（含被清空的）；
2. 目标段落的拼接文本等于「原段落文本替换命中区间」；
3. 其余段落的拼接文本不变。

引擎成功响应新增可选字段 `cross_run_merged: true`（单 `w:t` 路径为 `false`），
供 Node 端回执与测试断言；Node 契约对多余字段本就宽容，但会解析该字段放入返回值。

## 五、错误与文案

| 情况 | 错误码 | 文案要点 |
| --- | --- | --- |
| 覆盖的 run 格式不同 | `cross-run` | 「命中跨了格式不同的 run」+ 在 Word 手改 / 缩短原文 |
| `w:t` 不在 run 内 | `cross-run` | 「文档结构不支持定位」+ 手改 |
| 中间夹 tab/换行 | `cross-run` | 「原文中间夹着制表符或换行」+ 重新给出原文 |
| 跨段落拆开 | `not-found` | 现有文案（段落边界是硬边界，在文档里写明） |

`src/main/daemon/docx-replace.js` 的 `SEMANTIC_ENGINE_CODES` 已包含 `cross-run`，只需把文案从
「被 Word 拆在多个 run」改为「跨了格式不同的 run 或夹着换行」这类**只描述剩余拒绝面**的说法。

## 六、测试

- 夹具 A 的跨 run 段落：成功替换、段落文本正确、其余条目 sha256 不变、版式特征不变。
- 动态构造（JSZip，单元测试内）：
  - 两个 run 的 `rPr` 不同 → `cross-run`，信息含「格式不同」；
  - 中间夹 `w:tab` → `cross-run`；
  - `find` 跨两个段落 → `not-found`。
- 拼接后多处命中 → `multiple-matches`。
- 现有全部用例（单 `w:t`、页眉、表格）保持绿。
- 反向验证：把 `rPr` 比较改成恒真 → 格式不同用例红。

## 七、文档

- ADR-0001：把「跨 run」从 v1 非目标移入「v2 已支持（同格式）」，保留格式不同拒绝的理由。
- `docx_replace` 的 `description` / `promptGuidelines` / `promptSnippet` 同步。
- USAGE 的 docx 子段留到 #501 统一改（本轮不重复改两处）。

## 八、回滚

- 引擎改动在 `patch_part` 内，可由 `cross_run_merged` 字段与测试区分路径；
  回滚即 revert 单个 PR，不影响 v1 数据与建议格式。
