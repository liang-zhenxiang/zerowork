# 上手体验与同类产品对比调研

## Goal

作为维护者回答一个具体问题：**一个陌生人凭什么选 ZeroWork，而不是选别的？**

当前状态是「能力不弱，但上手路径不清晰」—— 下载之后要自己摸索：
配哪个模型、怎么建第一个工作区、能干什么，全靠翻文档。

## 背景（现状勘察的结论）

- **侧边栏 6 个导航项里 4 个是「敬请期待」占位**（`app.js:13229-13236` 的
  `NAV_ITEMS$1`，`ready: false` 点击走 `onTodo`）：
  「助理」「项目」「资料库」「更多」都不可用。**第一眼看到的是一个半空的导航**
- **首页 hero 的表现力不足**：`.home-title` 是 30px/600 的打字机标题，
  下面是 capability chips 与输入卡。有设计感，但**没告诉用户「你会用它做什么」**
- **首次运行可能是一片空白**：没有工作区、没有会话时的空状态引导程度未知
- **无 i18n 基础设施** —— 界面文字全部硬编码简体中文（这与「本地优先的中文办公产品」
  定位一致，**不是缺陷**，但限制了国际用户的进入）

## Requirements

- R1 **调研同类项目**，产出可执行的对比结论：它们各自把「第一次打开」做成什么样，
  哪些做法值得借鉴、哪些不适用于本项目
- R2 **首次运行体验**：空状态有引导，而不是一片空白；关键能力有可发现的入口
- R3 借鉴必须**融合改造**，不是照搬 —— 与本项目既有设计语言一致
  （见 `docs/DESIGN.md` 与 `.trellis/spec/renderer/index.md`）
- R4 结论沉淀进文档，作为后续路线的输入

## Acceptance Criteria

- [ ] 有一份**对比结论文档**，至少覆盖 3 个同类项目，每个都写清
      「它怎么做 / 我们为什么不照搬 / 我们能吸收什么」
- [ ] 首次运行（全新 `ZEROWORK_CONFIG_DIR`）有明确的下一步指引
- [ ] 新建的空导航项若仍不可用，**视觉上不制造「功能缺失」的错觉**
- [ ] 新增能力有测试覆盖，且不影响既有功能

## 约束

- **不引入需要联网才能工作的功能** —— 本项目是**本地优先**
- **不为了「看起来全」而增加不成立的承诺**（例如此前已决定不发 Linux 安装包，
  因为命令沙箱在 macOS/Linux 上直接拒绝执行）
- **不隐藏核心功能**（`docs/DESIGN.md` §6）
- 三态必须互斥且可辨：加载中 / 真空 / 错误（§4）

## 非目标

- **不做 i18n**。当前定位是中文办公产品，加多语言是独立议题，
  需要先有「国际用户」这个真实需求

## Notes

- 调研要**落到文件**，不要只在对话里说 —— 对话会被压缩，文件不会
- 同类项目指「本地优先的 Agent 桌面端」，调研时注意区分「纯聊天客户端」与「能执行任务的 Agent」
