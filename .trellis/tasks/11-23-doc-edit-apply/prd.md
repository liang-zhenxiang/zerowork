# PRD：修订写回——哈希守卫、版本快照与审计（#458）

## 背景

#456 已经能把 Agent 的写入变成待审建议，但还没有「接受」的落点。写回只有在三件事同时成立时才可信：**只应用用户选中的 hunk**、**原文变了就不套用**、**写之前留得住旧版本**。

## 目标

1. **按选中 hunk 写回**：给定建议 id 与 hunk id 列表，产出「原文 + 仅选中的改动」并写盘。
2. **哈希守卫**：写前重算当前文件 SHA-256，与建议的 `baseSha256` 不一致时拒绝写回，并给出「原文已变化，请重新生成」。
3. **版本快照**：写前把当前内容交给 `version-store`，可从文件历史还原。
4. **审计**：接受、拒绝、过期都写一条 `file` 类事件；不记录文档正文。
5. **拒绝**：丢弃整条建议、**不修改文件**；拒绝也要留审计。
6. **过期可见**：读取建议时同时给出 `stale`（当前文件哈希是否仍等于基准），供 #457 禁用「接受」。

## 非目标

- 不做 UI（#457）。
- 不做 docx（#460 决策前不碰二进制/复杂格式）。
- 不改变 #456 的生成与存储格式；只消费它。

## 验收标准

- [ ] 全部接受 → 文件等于建议的 `after`（逐字节）
- [ ] 部分接受 → 只含选中的 hunk，未选中的保持原文
- [ ] 原文被手动修改 → 写回拒绝、文件不变、审计记过期
- [ ] 拒绝 → 文件不变、建议删除、审计记拒绝
- [ ] 写回前生成版本记录，可从文件历史还原到接受前
- [ ] 接受后建议删除；不存在 / 已损坏的 id 报可读错误
- [ ] 审计不含文档正文；路径只记绝对路径或文件名（与既有 file 审计同口径）
- [ ] 单测覆盖：哈希守卫、部分/全部接受、拒绝零副作用、版本记录、审计、id 校验
