# 让 command-exec 的沙箱断言可证伪

## 问题（Issue #39）

`tests/e2e/command-exec.mjs` 的 B 条断言（「完全访问档下命令能跑起来」）
**在 macOS 上是假通过** —— 命令根本没执行，而断言被**模型复述命令的那段文字**满足了。

证据（插桩跑一次拿到的）：

```
切到完全访问档后，工具是 spawn powershell.exe ENOENT 直接失败
  （本机没有 PowerShell，命令根本没跑起来）

而 askModelToRun 找的 ORBIT5280，是被模型复述命令满足的 ——
最后一次回复尾部就是：
  「…现在就重新调用命令执行工具运行 echo ORBIT5280」
```

**「等到的条件」与「要断言的副作用」被同一段文字同时满足了。**

## 为什么这是本任务的重点

这正是 `.trellis/spec/testing/` 第 5 条讲的那类**无法证伪**的断言：

> **把被测功能整个删掉，它照样会绿。**

它看起来在验证「命令沙箱与执行链路」，实际验证的是「模型会不会把命令抄一遍」。
在 macOS（以及任何没有 PowerShell 的机器）上，它提供的是**虚假的安心**。

## Requirements

- R1 **先确定这条用例到底要验证什么**，再决定怎么断言。两种可能的结论：
  - **结论 A**：目标是「命令真的被执行了」→ 断言必须落在**可观察的副作用**上：
    审计日志里出现对应的 `command` 事件、或命令的真实输出回来了。
    **不能是模型文本里出现过那段命令**
  - **结论 B**：macOS 上这个前提（有 PowerShell）不成立 → **显式 `h.skip` 并写明原因**，
    而不是让它以「模型复述」的方式假通过
- R2 同一文件里 **check A 的等待条件**同样可疑（它等的也是「模型的那段文字」），
  而且它的返回值被丢弃（`void r`）。请一并判断与处置
- R3 **不得削弱其他断言**；`h.skip` 是允许的，但**必须写清原因**（报告里要能读出「跳过 N」）

## Acceptance Criteria

- [ ] 明确了这条用例的验收到底是什么，并写进文件头注释（**包括被否掉的方案**）
- [ ] **反向验证**：把「命令真的执行」这条链路破坏掉（或按结论 B 让它 skip），
      断言**必须**表现出「红」或「明确跳过」—— **不能仍然是绿的**
- [ ] 若判定某条在 macOS 上不成立 → 显式 skip + 原因，且报告里出现「跳过 N」
- [ ] `npm run lint:all` 全过；`test:gui:cmd` 单独跑通过（或其 skip 路径有据可查）

## 约束

- 只改 `tests/e2e/command-exec.mjs`（必要时可动它引用的 helper）
- **不动产品代码** —— 本任务是让测试诚实，不是改行为
- 不改 `resources/**`

## 难度

小到中。**难在判断，不难在改** —— 要先把「这条用例的验收是什么」想清楚。
