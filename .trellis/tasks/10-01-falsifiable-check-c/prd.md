# 让 command-exec 的 check C 可证伪

## 问题（Issue #55）

`tests/e2e/command-exec.mjs` 的 check C（`命令执行：受限档下绝不静默执行`）
**验的不是它标题里说的东西** —— 它是第三处「无法证伪的断言」。

## 证据（实测输出）

```
审批请求 0 次（含 powershell: false）；审计里被拦下: true
```

- `asked` **恒为 false** —— C 跑的时候档位还停在 **B 留下的 `danger-full-access`**
  （**C 自己从不切档**），这个档下不会弹审批
- `blocked` **恒为 true** —— 它的判据是 `audit.includes("blocked")`，
  而那条记录是 **check A 留下的**

也就是说：**它验证的其实是「A 写过一条 blocked」，与「受限档」无关。**
把「受限档拒绝执行」这条链路整个删掉，它照样绿。

## Requirements

- R1 **让 C 自己切到受限档**，断言「该档下命令没有执行」这个**可观察副作用**
  （而不是复用别人留下的审计记录）
- R2 反向验证��把「受限档拒绝执行」这条链路破坏掉，C **必须变红**
- R3 顺带排查：同文件里还有没有别的用例**依赖上一个用例留下的状态** ——
  这类隐式依赖本身就是脆弱点。有就一并修，没有就说明为什么没有
- R4 不得削弱其他断言

## Acceptance Criteria

- [ ] C 自己切档，不依赖前一个用例的状态
- [ ] 反向验证真做了，贴出输出
- [ ] R3 有明确结论（逐条排查，不是扫一眼）
- [ ] `npm run lint:all` 全过

## 约束

- 只改 `tests/e2e/command-exec.mjs`（必要时可动它引用的 helper）
- **不动产品代码**、不动 `resources/**`
- 注意：这个文件刚在上一个 PR 里被改过（B 断言已改成「看工具卡」），
  **沿用同一套手法**（等本轮新增的工具卡，而不是等模型文本）
