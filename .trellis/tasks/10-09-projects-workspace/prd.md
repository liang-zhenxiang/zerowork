# 项目工作区 Projects：把会话、产物与常驻指令装订成一本活页夹

## Goal

实装侧栏既有占位「项目」（`NAV_ITEMS$1` 的 `{ label: "项目", ready: false }`）。
**项目 = 会话 + 资料库产物 + 常驻指令**的组织层：给「同一件正在推进的事」一个家，
回答「这件事做到哪了、东西都在哪」。

## 为什么是它（选题依据）

- **侧栏占位是项目自己的既定路线**（「助理」「项目」「更多」三者未开放，「项目」先行）
- **市场空白**：ChatGPT Projects 验证了心智（会话+文件+常驻指令的持久工作区），
  但开源本地桌面端（Cherry Studio / Jan / Msty / AnythingLLM）均无此形态；
  ZeroWork 特有的「本地文件 + 工作空间 + 沙箱 + 资料库」能让项目比 ChatGPT 的更实在
- **与既有概念正交不打架**：工作空间管**文件系统**（cwd 目录），项目管**工作本身**
  （哪些会话属于这件事、常驻要求是什么）。一个项目可以跨工作空间，一个工作空间
  也可以服务多个项目
- 用户目标：界面美观第一 + 敢于创新。项目的视觉载体（卡片墙 + 项目色 + 进度感）
  有充分的发挥空间

## 概念边界（先钉死，防止做出两个打架的"文件夹"）

| 概念 | 管什么 | 不碰什么 |
| --- | --- | --- |
| 工作空间 | 磁盘目录（cwd），会话按它分组 | 不知道"这件事是什么" |
| **项目（新）** | 会话集合 + 常驻指令 + 产物聚合视图 | **不创建目录、不移动文件、不改会话的 cwd** |
| 资料库 | 所有会话交付过的产物（全局） | 项目视图只是**按来源会话过滤**它的数据，不另建索引 |

## Requirements

### R1 项目的增删改（projects.json）

- 创建（名称必填、非空）、重命名、删除（删除只解除组织关系，**不删任何会话与文件**，
  确认弹窗明说这一点）；项目色从分类色 token（--cat-1..6）自动轮转分配，可换
- 存储：`projects.json` 在配置目录，照 pin.js 形态（临时文件+rename 原子落盘、
  坏文件当空、结构校验）；**会话引用键 = resolve 后的绝对路径**（与 pin/archive 同一口径）

### R2 项目视图（ProjectView，新 view + 独立文件 projects-view.js）

- 入口：侧栏「项目」（ready 翻 true），overlay 模式挂载（照 LibraryView）
- 两级：项目卡片墙（名称、项目色、会话数、最近活动时间、常驻指令有无的标记）
  → 项目详情（该项目会话列表 + 产物区（按来源会话过滤资料库）+ 常驻指令编辑区）
- 会话行动作：点开即 resume（受益于 #162 的模型回落）；从项目移除（解除引用）
- 三态纪律（§4）：加载/空/错误互斥，错误就地 + 重试；空态文案要给出「第一步做什么」
- **美观**：卡片墙是本轮的视觉重心（设计师 agent 参与，方案见 design.md）

### R3 会话 ↔ 项目

- 会话行 ⋯ 菜单加「归入项目 / 换个项目 / 移出项目」（子菜单列出项目 + 新建入口）
- 一个会话同时只属一个项目（MVP 取舍：活页夹心智，一页只在一本里；
  多项目交叉留给后续版本，PRD 不做）
- 归入后：侧栏会话行加项目色点标记（不只靠颜色：加 title 文字提示）

### R4 常驻指令（每轮 systemPrompt 追加段）

- 项目详情里可编辑一段「项目指令」（多行文本，上限 2000 字）
- 注入方案 A（research 报告）：`composePromptWithMeta` 加 `projectInstructionsBody`
  追加段（与 memorySystemBody 同型），session-files 的 compose 回调按当前会话所属
  项目现读——改指令**下一轮即生效**，promptPreview 与诊断面板自动一致
- 没归入项目的会话：行为一步不变（零开销，不进注入路径）

### R5 明确不做（本轮）

- 首页「最近项目」区块、项目进度百分比、多项目交叉归属、项目归档、
  项目级默认专家/场景、项目导出——都是后续增量，不进本 PR

## Acceptance Criteria

- [ ] 单测：projects store 的 CRUD（含坏文件当空、原子写、结构校验）；
      会话归入/移出/换项目的映射纯逻辑；一个会话只属一个项目的约束
- [ ] 单测：指令段组装——有项目指令时 compose 出含该段的 systemPrompt
      （含分段标注），无项目时输出与现状逐字节一致（回归保护）
- [ ] e2e/GUI（真实启动 + 截图）：
  - [ ] 侧栏「项目」可点开，空态、卡片墙、详情浅色/深色截图各一张（像素断言）
  - [ ] 建项目 → 会话 ⋯ 菜单归入 → 项目详情看到该会话 → 点开能 resume
  - [ ] 编辑项目指令 → 该项目会话发一条消息 → mock 收到的请求里 systemPrompt 含指令段
  - [ ] 删除项目 → 会话还在（侧栏可见），只是没了组织关系
- [ ] 回归：全量 `npm run test:gui` 通过（含既有 31 套件）
- [ ] CHANGELOG `[Unreleased]` 记入 新增；docs/USAGE.md 增「项目」一节
- [ ] `npm run lint:all` 全过（含 check:theme-tokens：新颜色 token 亮暗双配）
