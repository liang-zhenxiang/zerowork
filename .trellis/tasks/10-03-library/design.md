# 技术设计：资料库

> 需求与口径见 `prd.md`；一手调研见 `research/feasibility.md`。
> 本文件只写「怎么实现」与「为什么这么选」。

## 1. 数据面

### 1.1 聚合函数放哪

放在 **`src/main/daemon/session-files.js`**，与 `listSessions()` 同层 —— 那里已经有
`getSessionsDir()`、逐行解析骨架（`parseSessionFile$1`，约 334 行）、
以及现成的「哪些会话是内部会话要跳过」的判据（`isInternalSessionFile`）。

**【2026-10-03 订正】原设计写的是「不新建模块、就地加进 `session-files.js`」——
这条前提是错的，实现时被推翻：**

`session-files.js` 在**模块顶层**就调 `requireParentPort()`（约 1389 行），
在 Electron utilityProcess 之外根本 import 不了。把聚合逻辑放那里，等于让它
**无法单测** —— 而 §4 明确要求解析 / 去重 / 截断是「可单测的纯逻辑」。
两条要求直接冲突，**单测优先**：没有单测的解析逻辑，正是最容易悄悄写错、
又最难在 GUI 里定位的那部分。

所以落成 `src/main/daemon/library.js`，并且**不复制 `session-files.js` 的私料**：
会话目录与「内部会话过滤」由调用方（`session-files.js` 的 handler）**注入**，
纯逻辑（parse / aggregate）不碰文件系统、可直接对临时目录里的会话文件断言。

> 这条订正本身值得留：研究文档给的「复用 `parseSessionFile$1`」看起来天经地义，
> 但**那个函数住在一个 import 进来就炸的模块里**。调研看的是「有没有现成的」，
> 没有看「它能不能被拿来用」——后者要靠实现时真的动手才知道。

### 1.2 数据形状

```js
libraryList() -> {
  artifacts: [{
    path,          // 绝对路径（与会话文件里存的一致）
    name,          // basename
    kind,          // 交付时刻判定：'local' | 'url'
    html,          // 交付时刻判定：是否 .html
    size,          // 交付时刻的字节数（快照，不是实时值）
    deliveredAt,   // 最近一次交付的 ISO 时间
    exists,        // 聚合时 statSync 的结果（实时）
    sessions: [{ id, path, title, cwd, modifiedAt }],  // 交付过它的会话，最近的在前
  }],
  truncated: bool, // 见 §1.5
}
```

**`size` / `kind` / `html` 是交付时刻的快照**，字段名与语义都要在 UI 里说清
（`exists` 才是实时的）。不混为一谈。

### 1.3 去重

**按 `path` 全局合并**。逐条扫到时：

```
同一 path 的第二条：不新增行；把它的 sessions 加进去；
若它的 timestamp 更晚 → 用它覆盖 size/kind/html/deliveredAt
```

「最近一次交付的元数据」比「第一次」更符合直觉：用户看到的是**这个文件现在长什么样**
（在交付那一刻），而不是它第一次被交付时的样子。

`sessions` **最近在前**，且**去掉重复的会话**（同一会话里先后交付两次不该出现两遍）。

### 1.4 `exists` 的计算

去重**之后**，对每个不同的 path 做一次 `statSync`（`try/catch`，失败即 `false`）。

**为什么在 daemon 侧算而不是渲染层逐个调 `statPath`**：
- 一次 IPC 一次往返，而不是 N 次
- `statPath` 的既有语义以**当前会话 cwd** 为边界（见 §2.1），而资料库的条目跨 cwd ——
  用它算 `exists` 会把「在别的工作区里好好待着」误判成「不存在」

N 是**去重后的条数**（本机实测全量会话只有 3 条产物），一次 `statSync` 的开销可忽略。

### 1.5 上限与「截断要说出来」

聚合结果设一个上限（`LIBRARY_MAX_ITEMS = 500`，按 `deliveredAt` 降序截断），
并返回 `truncated: true`。**界面必须把这件事说出来** ——
静默截断等于让用户以为「就这些」。

> 这条不是假想：本仓库对「静默丢东西」有明确纪律（命令面板的结果数就是这么处理的）。

### 1.6 健壮性

- **坏行跳过**：逐行 `JSON.parse` 失败就跳过（既有解析骨架已有此行为，复用即可）
- **坏文件跳过**：`readFileSync` 抛错（权限、被删）→ 该文件跳过，不影响其它会话
- **整个聚合不抛**：任何单文件问题都只影响它自己。页面上不出现「资料库坏了」

## 2. 跨工作区的预览边界（本设计最需要拿主意的一处）

### 问题

`readSessionArtifact` / `statSessionArtifact` 以**当前会话的 cwd** 为边界
（`resolve(cwd, path)` 后要求落在 `cwd + sep` 之内，否则抛「路径超出当前工作区」）。
而资料库的条目来自**不同会话、不同 cwd**，甚至可能落在任何 cwd 之外
（`present_files` 允许交付工作区外路径）。

### 决定：预览走**来源会话的 cwd**，不新开通道

- `previewBaseUrl(cwd)` **本来就接收 cwd**（preload `index.js:567`；daemon 侧
  `preview-server.js` 用 `resolveWithinRoot` 防越界）—— 用来源会话的 cwd 调它，
  是**既有能力**的既有用法，没有放宽任何边界
- **不**给渲染层开一条「指定任意 cwd 去读」的新通道 —— 那等于把
  「渲染层能读进程有权读的任何文件」变成常态。红线 4（不放宽安全约束）要求拒绝
- 落在**任何已知 cwd 之外**的产物：动作降级为「在文件夹中显示」
  （`revealWorkspace` 之类的既有通道），并**明确告诉用户为什么不能预览**
  （「这个产物在它自己的工作区之外，资料库不直接读它」），而不是给一个点了没反应的按钮

> 这条同时也是「宁可拒绝，也不静默降级」的落地：不预览要**说清楚原因**。

## 3. 渲染层

### 3.1 视图骨架

照 `SkillsView` / `AutomationsView`：`load()` 走 IPC → `busy` / `error` / 数据三态。
**不新造骨架**。

### 3.2 列表行

抄 `OverviewView`（产物面板里的那个列表）的行形态：图标 + 主文 + 次文 + 操作。
**不新造视觉**（§6「不复制视觉值」）。

每行：
- 主文：文件名
- 次文：大小 · 来源会话标题 · 相对时间 · （多会话时）「N 个会话交付过」
- 失效时：一个**不只靠颜色**的失效标记（§7.6：文字或图标形态）
- 操作：预览 / 在文件夹中显示 / 定位到来源会话

### 3.3 三种态

| 态 | 判据 | 内容 |
| --- | --- | --- |
| 加载中 | 数据为 `undefined` | `LoadingState`（骨架或转圈） |
| 真空 | `artifacts.length === 0` | `EmptyState` + **怎么产生产物的指引** |
| 错误 | IPC 抛错 | `ErrorState` + 重试 |

**空态文案要能教会人**：这个页面很可能是用户第一次见到它时是空的 ——
它得说清「产物从哪来」（让 Agent 做一件事，它会把成果文件交付出来），
以及一个能**直接去做**的入口（如「新建任务」）。

### 3.4 导航

`NAV_ITEMS$1` 里「资料库」改 `ready: true`，并在按 label 分派处加
`else if (label === "资料库") onOpenLibrary()`（与「专家·技能·连接器」同款）。
它同时从「规划中」组自动移出（那一组是按 `!ready` 过滤的）。

## 4. 测试设计

### 单元（`tests/unit/library-aggregate.test.mjs`）

聚合逻辑要是**可单测的纯逻辑**（解析 + 去重 + 截断），不掺 IPC。
若函数签名需要文件系统，用临时目录造会话文件（`tests/unit/mailbox-session-index.test.mjs`
就是「每个用例一个全新临时目录」的模式）。

覆盖：
- 逐行解析：正常条目 / 坏行跳过 / 空文件 / 不存在的文件
- 去重：同 path 两个会话 → 一行 + `sessions` 两条 + 取更晚的元数据
- **同一会话内先后交付两次 → `sessions` 里只出现一次**
- 截断：超过上限 → `truncated: true`，且保留的是**最近的**
- `exists`：把文件删掉后该条 `exists: false`，且**不抛**
- 不相关的会话（无产物条目）不产生空行

### GUI（`tests/e2e/library.mjs`）

真实启动 Electron：

| # | 断言 |
| --- | --- |
| ① | 侧栏「资料库」**可点**（不是 disabled），且已不在「规划中」组里 |
| ② | 全新环境：进入后是**空态**（不是加载态、不是错误态），且空态里有「怎么产生产物」的文字 |
| ③ | **造一次真交付**（照 `tests/e2e/artifact-present.mjs` 的造法，用 mock 模型）后重进资料库 → 列表出现该产物，**名称与来源会话标题正确** |
| ④ | 把产物文件删掉后重进 → 该条**被标为失效**（且没有消失） |
| ⑤ | 点「定位到来源会话」→ 真的进到那个会话 |
| ⑥ | 浅色 + 深色两套主题截图 + 像素断言 |
| ⑦ | 多会话交付同一路径 → **只有一行**且标出会话数（可与 ③ 合并构造） |

**反向验证**（写进文件头注释）：
- 把去重去掉 → ⑦ **变红**
- 把空态与加载态的判据合并（`undefined` 也渲染空态）→ ② **变红**
两条都真跑并还原。

## 6. 风险

| 风险 | 处置 |
| --- | --- |
| 聚合挂在热路径导致每次 run 都扫盘 | **不做推送**，只做拉式 invoke。测试里也不得引入「每次事件都刷资料库」 |
| 新增 IPC 忘了同步 shared/preload/daemon 三处 | 三处都要改；`npm run lint:all` 里有 IPC 一致性检查，改完跑 |
| 大量会话时首开变慢 | v1 实测数十毫秒；`truncated` 上限也顺带限制了渲染量。会话数真上来再谈缓存 |
| 把「产物」与「工作空间文件」混谈 | `docs/USAGE.md` 的旧口径要改掉，PR 里写明这是**缩小**口径而不是漏做 |
