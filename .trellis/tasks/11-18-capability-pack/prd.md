# PRD：能力包（#420）

## 背景

竞品 WorkBuddy 的专家市场与 SkillHub 靠云端分发能力；ZeroWork 的专家是内置的、
技能只能单个导入，没有「专家 + 技能 + 成员 + 模板」的可分享单元。用户把调好的
工作方式交给同事只能口头指导或拷目录，社区也无法贡献开箱即用的套装。

能力包是 ZeroWork 的差异化答案：**纯文件、可 diff、可 git 分享、导入前预览、
不依赖服务器**。

## 目标

1. 定义 `zerowork-pack` v1 格式（目录或 `.zwpack` zip），一个包 = 一个专家及其私有技能/成员。
2. 导入前预览：将安装什么、覆盖什么、包含哪些技能与连接器声明。
3. 安装 / 卸载 / 列表：装到用户配置目录，来源可追溯，卸载可回滚。
4. 导出：把**用户自己**的专家封装成包，带 SHA-256 文件清单。
5. 桌面端最小入口：导入按钮 + 预览弹窗 + 专家详情里的来源与移除。

## 非目标（本轮不做）

- 能力库画廊 / 搜索 / 领域分组 —— #421
- 连接器自动安装（涉及凭据与权限；本轮只做**声明**并在预览中展示）
- 提示词模板（`prompts/`）安装 —— v1 明确拒绝，避免第二个落盘路径与卸载追踪
- 内置专家的导出（第三方内容再分发授权未确认，见 `THIRD_PARTY_NOTICES.md`）
- 云端市场 / 远程 URL 安装

## 约束

- **不执行包内任何代码**：拒绝脚本与可执行文件；包只含声明式内容。
- 安全上限：路径穿越、绝对路径、符号链接、隐藏文件、zip bomb、文件数与体积上限。
- 不改权限模型与沙箱；导入不是提权。
- 失败必须可诊断：说清哪个文件、哪条规则、怎么修。
- Windows 大小写不敏感：同名/同路径按大小写归一判重。
- 默认行为不变：不导入任何包时，专家列表与现在一致。

## 验收标准

- [ ] `manifest.json` 校验：必填字段、`id` 与专家目录名/`expert.md` 的 `name` 一致、版本格式、`format`/`formatVersion`。
- [ ] `.zwpack` 与目录两种来源都能导入；导入/导出 roundtrip 单测通过。
- [ ] 拒绝用例：`../` 路径、绝对路径、符号链接、隐藏文件、脚本/可执行扩展名、超数量/超体积、缺 manifest、名称不一致。
- [ ] 导入后专家出现在 `listExperts()`（`source: "pack"`）并可被 `setExpert` 选中；卸载后消失。
- [ ] 导出：仅允许用户专家；产物含 manifest 与 SHA-256 清单；再导入 hash 校验通过。
- [ ] 导入预览返回专家摘要、技能清单、连接器声明、文件数与体积、冲突信息；不写盘。
- [ ] 真实 Electron e2e：stub 文件对话框 → 点导入 → 预览 → 安装 → 专家可用 → 移除。
- [ ] GUI 截图：预览弹窗（亮/暗各一张）。
- [ ] `npm run lint:all`、`npm test`、相关 e2e 全绿；`check:unicode` 通过。
- [ ] `CHANGELOG.md` 记「新增」；`docs/USAGE.md` 新增「能力包」一节。
