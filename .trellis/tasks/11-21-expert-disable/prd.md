# PRD：专家停用与恢复（#426）

## 背景

能力库（#421）有「专家」这一等公民，但没有「不用它」的中间状态：要么留着，
要么删掉。内置专家不能删、能力包卸载又会连文件一起删，而用户想表达的是
「这个专家我不想要了，但先别删」。

只把卡片藏起来不算停用：专家是可被会话选中的（`setExpert`），也参与每一轮的
提示词组装与私有技能解析。**仍能通过旧会话或 id 选中、人格照常注入，就是假的停用。**

## 语义（本轮定义清楚）

停用是**用户级偏好**（`preferences.json` 的 `disabledExperts`），不改专家定义、
不删文件、不碰能力包安装目录。

1. **选择面**：停用的专家不出现在任何选择器（首页/对话的专家菜单、设置里的
   提示词预览、命令面板）与能力库默认视图；能力库可「显示已停用」并恢复。
2. **选中守卫**：`setExpert(停用 id)` 拒绝，报错说明「已停用，请先在能力库恢复」。
3. **已绑定会话**：绑定**保留**（state 仍有 expertId），但从下一轮起
   **不再注入人格与其私有技能**，专家追加工具也不再生效；状态额外下发
   `expertDisabled: true`，界面在专家 chip 上标「已停用」并给恢复指引。
   恢复后绑定自动继续生效 —— 这比强制清空绑定更符合「临时关掉」的意图。
4. **不受影响**：团队/子代理按专家定义解析，不读这份用户偏好；能力库来源筛选、
   排序、计数把停用项计入（它们仍在库里）。

## 非目标

- 不做「删除内置专家」。
- 不改能力包卸载语义（卸载与停用是两个动作，本轮只加后者）。
- 不做按会话级别的停用（偏好是全局的）。

## 验收标准

- [ ] `preferences.json` 新增 `disabledExperts: string[]`；读侧逐条丢弃非法值，
      写侧去重；空数组时不落盘该键（与 `skillOverrides` 同口径）。
- [ ] `listExperts` 返回的条目在停用时带 `disabled: true`（其余字段不变）。
- [ ] 停用后：首页/对话专家菜单、设置提示词预览、命令面板都不再列出它；
      能力库默认不显示，打开「显示已停用」后显示并带标记。
- [ ] `setExpert` 对停用专家抛错，错误消息可操作；恢复后可正常选中。
- [ ] 已绑定该专家的会话：下一轮系统提示词不含其人格与私有技能，
      `session_state.expertDisabled === true`；恢复后恢复注入。
- [ ] 能力库详情可停用/恢复；停用不删文件，恢复后专家原样回来。
- [ ] 单测：偏好读写与去重、画廊筛选（默认排除/可包含）。
- [ ] e2e：真实 Electron 走「详情停用 → 菜单消失 → 状态标记 → 恢复 → 菜单回来」。
- [ ] 回归：`gui-expert-gallery`、`gui-settings`、`gui-smoke`、`gui-hooks`。
- [ ] `CHANGELOG` 记「新增」；文档写明停用与卸载的区别。
