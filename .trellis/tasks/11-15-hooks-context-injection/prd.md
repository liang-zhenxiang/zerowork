# PRD：hooks 上下文注入（可见的自定义消息）

- Issue：#385（v0.23.0）
- 分支：`feat/hooks-context-injection`
- 日期：2026-11-15
- 前序：#373 / PR #377、#387 / PR #388、#386 / PR #392

## 背景

生命周期 hooks 目前只能「记账」：stdout 进审计与试运行，不进上下文。用户想把
「今天的日期 / 当前分支 / 外部系统状态」在会话开始或每条消息前确定性带给模型，
只能靠提示词或 memory。

竞品最常用的形态正是 stdout 进入上下文。但**静默**注入是提示注入面 ——
本项目要的是**可见**的注入：一条明确标注「来自哪个 hook」的自定义消息，
不覆盖系统提示、不改写用户原文。

## 需求

### 注入行为

- 只对 `SessionStart` 与 `UserPromptSubmit` 生效（`Stop` / `SessionEnd` 的时机没有「下一条请求」，
  stdout 不注入；`PreToolUse` / `PostToolUse` 不变）
- 注入通道是 `before_agent_start` 的 `message` 返回值（pi 会把 `role:"custom"` 消息
  放在本轮用户消息之后）
- **只有退出码 0（allow）的 hook 输出会被注入**：失败 / 超时 / exit 2 的输出不可信，只留审计
- 空输出不注入；`SessionStart` 的输出**暂存到本会话第一条用户消息**一起投递，同会话只投递一次
- 长度上限：单条 hook 4KB、单次注入合计 8KB（按 UTF-8 字节截断到字符边界，截断处标注）
- 多条 hook 按配置顺序拼接；任一失败不影响其它 hook 的注入，也不影响会话

### 可见性（本次的核心）

- 注入消息在会话时间线里显示为独立卡片：「hooks 注入的上下文」，列出贡献的 hook id
  与事件，正文可折叠
- **重新打开会话后仍然可见**（视图投影要认这种消息，而不是只认 live 事件）
- 文案明确「由本地 hook 生成，不改变用户消息」

### 审计

- 注入字节数写进既有 `hook` 审计的 detail（事件、hook id、耗时 + 「注入 N 字节」）
- **审计不记录注入正文**；完整内容只在设置页「试运行」里看
- 截断发生时 detail 标注「已截断」

### 不做

- 不覆盖 / 修改 `systemPrompt`
- 不注入失败或非零退出的输出
- 不做 `tool` 型 / `file` 型 hook、hook 市场
- `SessionStart` 的输出不能在本轮之外「补投递」（例如会话一开始就没有用户消息时，输出随会话结束丢弃）

## 验收

- [ ] `SessionStart` / `UserPromptSubmit` 的 allow 输出进入模型请求（mock 端点可断言）
- [ ] 注入消息在时间线可见、可折叠，重开会话仍在；显示 hook id 与事件
- [ ] 失败 / 超时 / exit 2 的输出**不注入**，审计仍记 failed
- [ ] 单条 4KB、合计 8KB 截断生效，截断处有标注；注入字节数进审计
- [ ] 空输出、无配置、配置损坏时零行为变化（不注入、不报错）
- [ ] 单测（拼接 / 截断 / 失败隔离 / 暂存一次）、daemon 集成（请求体断言）、GUI（卡片 + 折叠 + 截图）
- [ ] `SECURITY.md` 补「上下文注入 = 提示注入面」；`CHANGELOG.md` 记「新增」
- [ ] `lint:all`、`npm test`、相关 GUI 套件通过

## 硬约束

- 注入必须**可见**：不出现「模型收到了但用户看不到」的路径
- 文本永远来自 hook（用户自己的代码），不来自模型输出，不做二次解释
- 不新增依赖；daemon 不 import electron
