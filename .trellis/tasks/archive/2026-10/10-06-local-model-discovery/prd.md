# 本机模型服务：探测到就能一键接上

> 调研依据见 `research/model-access.md`（代码侧事实）与 `research/design-review.md`（界面侧诊断）。
> 本文件只保留**结论、范围与验收标准**。

## Goal

把「装完 → 能用上」的第一步从**设置页里的一道填空题**，变成**首屏上的一次点击**：

应用自动探测**本机回环地址**上的常见 OpenAI 兼容模型服务（Ollama / LM Studio / vLLM / LocalAI / Jan 等）；
探测到就把首页上手清单第 2 步从「去选一个模型」改成「接上本机 Ollama（4 个模型）」，
点一下就建好服务商、选中模型、可以直接开聊。全程不出网、不下载任何东西。

## 背景：已核实的事实

### 事实 1：模型接入是本项目与同类产品差距最大的一环 —— 而且是**我们自己调研文档写下的**

`docs/ONBOARDING-RESEARCH.md` 的横向对比表里，「模型配置门槛」这一行：

| AnythingLLM | Msty | LM Studio | Jan | Cherry Studio | **ZeroWork（现状）** |
| --- | --- | --- | --- | --- | --- |
| 内置 Ollama；或填 Key | 一键装本地 AI | 下载即用 | 目录里下载 | CherryAI 默认带免费模型 | **必须手填 baseUrl + Key + 模型名** |

同一份文档的「我们能吸收什么」第 4 条已经把做法与边界写清楚了：
**「只做『探测本机已有的 Ollama』与『预填本地端点』，不做下载」**，
并把它列在「明确不做」之外（即：该做，且成本小）。**至今未实现。**

代码侧核实：`rg '11434|Ollama' src/` 只有 **1 处命中** ——
`src/renderer/src/app.js:63540` 的一句提示文案（`API_OPTIONS` 里 OpenAI 兼容那条的 `hint`
写着「多数国产网关、Ollama、vLLM；基址填到 /v1 那一层」）。**没有任何探测、没有预设、没有一键接入。**

### 事实 2：这一步正卡在第一屏 —— 首页上手清单第 2 步的按钮指了指一个 4 级表单

- 首页三步清单：`src/renderer/src/app.js:15195` `OnboardingChecklist`
- 第 2 步的文案与按钮：`guideText()`（`app.js:15165`）产出
  `{ title: "还没有选定要用哪个模型", action: "去选一个模型" }`，
  按钮落 `onOpenSettings("models")`（`app.js:15270` 附近）
- 判据是 `judgeModelReadiness()`（`app.js:15159`）——**只看 `model.available`，不看本机有没有可接的服务**

也就是说：一个已经装了 Ollama 的用户，在首屏看到的仍然是「还没有选定要用哪个模型 → 去选一个模型」，
点进去是「添加模型」表单，要自己知道该填 `http://127.0.0.1:11434/v1`。
**他知道答案才填得对 —— 而这正是我们要替他做的事。**

### 事实 3：写路径与探测能力**都已存在**，本任务主要是「接上」

- 写：`INVOKE.saveCustomProvider` → daemon `src/main/daemon/models.js:87` `upsertCustomProvider`
- 探测（单模型连通性）：`src/main/daemon/session-files.js:4440` 的 `INVOKE.testModel`，
  内部用 `probeModel(...)` + `withHardTimeout(...)`，**且明确约定「不 throw、用返回值表达失败」**
  （注释原文：*throw 会被 IPC 层裹成通用错误文案，丢掉 probeModel 精心归类的单行原因*）
- 拉模型目录：`INVOKE.refreshCatalog` 已能从 baseUrl 取回模型列表

**所以本任务不新建写路径、不新建协议实现**，只新增「按已知端口探一圈、把结果整理成可展示的形状」
这一段，以及两处界面的接线。

### 事实 4：不出网这件事必须写进登记表，而不是只在代码里成立

`EXTERNAL_REQUESTS.md` 第一节已有一条 **「5. 本地预览服务」**（`http://127.0.0.1:<随机端口>`，
「只监听本机回环地址，不出网」）。本任务新增的是**主动发起**的 loopback 请求 ——
形态与它不同（那条是监听，这条是请求），**必须单独登记**，写清：
只探回环、只探固定端口表、不扫网段、由什么触发、怎么关。

## Requirements

### R1 探测本机模型服务（daemon 侧）

新增一个模块（建议 `src/main/daemon/local-endpoints.js`），导出**纯函数为主**的能力：

- **候选表**：只含本机回环地址上的**常见 OpenAI 兼容端点**，每项写明服务名、端口、探测路径与出处：
  Ollama `127.0.0.1:11434`、LM Studio `127.0.0.1:1234`、vLLM `127.0.0.1:8000`、
  LocalAI `127.0.0.1:8080`、Jan `127.0.0.1:1337`（其余按调研结论增补，**每一项都要有出处**）
- **硬约束（写进测试）**：
  - 只允许 **loopback**（`127.0.0.1`）——**不得**出现 `0.0.0.0`、局域网网段或任何非回环主机名
  - **不做端口扫描**：只探候选表里写死的端口，不遍历区间
  - 超时短（单端点 ≤ 1s 量级），并发探测，**总耗时设上限**；未命中的端点安静失败
- **返回值形状**（IPC 契约，须在 `src/shared/ipc.js` 的注释里钉死）：
  每个候选至少给出 `{ id, label, baseUrl, reachable, models, error }`，
  且必须能区分这三种状态 —— **不许把「没探到」和「探到了但一个模型都没有」混为一谈**（`docs/DESIGN.md` §4 同族纪律）

### R2 一键接入（复用既有写路径）

- 新增 `INVOKE.probeLocalEndpoints`（探测）与「接入」动作；
- **接入 = 调既有的 `saveCustomProvider`**（不新开写路径），把探测结果转成一个合法的自定义 provider：
  `baseUrl` 规范化到 OpenAI 兼容那一层、`api: "openai-completions"`、模型列表来自探测结果
- 接入后**选中一个模型**并让界面反映出来（走既有 `setModel` / 会话模型字段，不新造状态）
- **不写任何凭据**：本机服务不需要 Key，`authHeader` 保持缺省
- 失败必须可诊断：接入失败要能说清是「端口能连但拉不到模型」还是「写配置失败」

### R3 首屏那一步：从「去选一个模型」变成「一键接上」

`OnboardingChecklist`（`app.js:15195`）第 2 步：

- 探测**命中**时：文案与按钮改为「接上本机 Ollama（4 个模型）」这类**带服务名与模型数**的说法，
  点击即完成接入并选中模型；完成后这一步立刻变成已完成（走既有 `judgeModelReadiness` 判据，**判据本身不动**）
- 探测**未命中**时：保持现状（「去选一个模型」），**不得**显示任何「没找到」的失败字样 ——
  绝大多数用户本来就没装本机服务，那不是错误
- **探测是异步的，且不得阻塞首屏**：探测结果没回来时，这一步显示现在的样子，回来后原地更新

### R4 设置 → 模型：让本机服务可发现、可重复接入

- 「服务商」区新增一块**本机模型服务**：探测结果列表（含未探到的候选项时**折叠在一句话之后**，不摊成一片红叉）
- 每一条可「接入」；已接入的显示为已接入状态，不重复添加
- **必须说明隐私边界**：一句话写清「只探测这台机器的回环地址（127.0.0.1）上的常见模型服务端口，不扫描网络、不出网」

### R5 文档与登记

- `EXTERNAL_REQUESTS.md` 新增一条（loopback 主动请求），写明地址形态、触发、可控性、位置
- `docs/USAGE.md`：模型接入一节补「本机模型服务」路径
- `CHANGELOG.md` 的 `[Unreleased]` → 「新增」，写清用户可感知的变化

## Acceptance Criteria

### 功能

- [ ] `npm run build` 后真实启动应用，能探测到一个**真实运行在本机回环地址上的 mock OpenAI 兼容服务**，
      并列出它的模型
- [ ] 从首页第 2 步一键接入后：该步变为已完成、当前模型被选中、**发一条消息能真的走通**（用 mock 端点）
- [ ] 设置 → 模型 能重复接入、能看到已接入状态
- [ ] **没有任何** 非回环地址出现在候选表里（静态断言 + 单测双向覆盖）
- [ ] 「探到但零模型」与「没探到」在界面上**可区分**（截图各一张）

### 测试（三层都要，且新增的每一条都要**反向验证**）

- [ ] **单元**：候选表形状与合法性（只 loopback / 端口合法 / 无重复 / 每项有 label 与出处注释）、
      响应归类（reachable+有模型 / reachable+零模型 / 连不上 / 非 200 / 超时 / 畸形 JSON）、
      baseUrl 规范化（`/v1` 与根路径两种入参都要能得到正确结果）、provider 构造、超时与并发上限
- [ ] **单元**：**把候选表里任意一项改成非回环地址，必须有一条用例变红**
- [ ] **GUI（真实启动 Electron + 真实截图）**：
      - 起一个 mock 本机服务 → 首页第 2 步出现「接上本机 X（N 个模型）」→ 点击 → 接入成功
      - 未起服务时：首页第 2 步保持现状文案，**且不出现任何错误字样**
      - 设置 → 模型 的两个状态各截一张图，并做像素断言
      - 浅色 / 深色各一张
- [ ] **GUI**：接入后发一条消息真的走通（复用既有 mock 模型服务的能力，**不许只看「没报错」**）
- [ ] 反向验证逐条执行：**把探测结果强行置空 / 把候选表改错 / 把「已接入」判据写反**，
      确认恰好相关的用例变红、其余不受影响

### 工程

- [ ] `npm run lint:all`、`npm test`、`npm run test:gui` 全绿，**既有用例一条不少**
- [ ] 新用例已加入 `package.json` 的 `test:gui` 链条，**并确认它在 `ci.yml` 的调用链里**（测试规范第 10 条）
- [ ] `npm run check:daemon-graph`、`npm run check:theme-tokens`、`npm run check:docs` 通过
- [ ] 全仓 U+FFFD 扫描为 OK（`AGENTS.md` 的中文内容质量命令）
- [ ] 界面改动全部走既有 token 与既有类名；**不新增视觉档位**；改动同步 `docs/DESIGN.md`（若确需）

## 约束（不许违反）

- **不引入任何运行时依赖**（探测用 Node 内置 `fetch` / `net`）
- **不改 `resources/**`**
- **不下载任何东西**、不内置模型、不申请任何权限、不做端口范围扫描
- **不放宽任何权限或沙箱约束**（红线 4）
- 不为 lint 通过而大规模重排 `app.js` / `app.css`（红线 6）
- 探测**不得**在应用启动时自动发生 —— 只在这两处界面需要它时触发

## 明确的后续项（本任务不做）

| 项 | 为什么不做 |
| --- | --- |
| 一键下载 / 安装 Ollama 或模型 | `docs/ONBOARDING-RESEARCH.md`「明确不做」第 2 条：联网下载大体积产物，且我们不做模型分发 |
| 局域网内其他机器上的模型服务 | 那已经不是「本机」，会把隐私边界从回环扩到内网 —— 与本项目的威胁模型冲突 |
| 自定义 CSS / 主题皮肤 | 与 `docs/DESIGN.md` 的档位纪律冲突（调研报告「不要抄」第 6 条） |
| 消息内容全文检索 | 另一个独立缺口（新用户无历史可搜，价值随使用量增长），另开 Issue |
