# 覆盖率基线与门禁，并收掉 #30（测试总纲）

## 背景：#30 是 2026-09-30 的一份「测试总纲」，五条期望

拆开逐条核实之后，**四条已经做到**，只有一条还欠着：

| #30 的期望 | 今天的状态 | 证据 |
| --- | --- | --- |
| 单测补到核心纯逻辑 | ✅ 34 个单测文件（当时 5 个），覆盖权限判定 / 定时任务 / 会话读写与分支 / IPC 契约 / 路径与配置 | `ls tests/unit/*.test.mjs` |
| e2e 加截图 + 像素断言 | ✅ e2e 里 **137 处** `h.shoot()`；`shoot` 默认做「不是一片纯色」的像素断言 | `tests/e2e/lib/harness.mjs` 的 `shoot` |
| 失败可诊断：截图上传为 artifact | ✅ CI 的 GUI job 有 `上传测试截图`（`if: always()`，`artifacts/`） | `.github/workflows/ci.yml` |
| 一条命令跑全部 | ✅ `npm run test:all` = `lint:all` + 单测 + e2e | `package.json` |
| **覆盖率有度量 + 不倒退** | ❌ **没接入** | `vitest.config.mjs` 里没有 coverage |

所以本任务做的是**把欠的那条补上**，然后按证据收掉 #30 —— 而不是把一份「都已经做完了」
的清单继续挂在里程碑里当背景噪声。

## 决定：覆盖率只统计**单测这一层该负责的代码**

先量了两遍（实测，不是估）：

| 统计范围 | 行覆盖 | 耗时 | 判断 |
| --- | --- | --- | --- |
| `src/**`（含渲染层那几个 30 万行级 bundle） | **1.78%** | 3 分 04 秒 | 不可用：e2e 跑在**另一个 Electron 进程**里，vitest 根本看不见它，算进来只是个把数字压平的噪声 |
| `src/main/daemon/**` + `src/shared/**` + `tools/**` + `scripts/**` | **15.66%** | 12 秒 | 可用：这正是「能写单测就别写 e2e」那条规范里的单测地盘 |

阈值 = **实测基线**（15.66 / 15.45 / 12.46 / 15.98）**减约 1 个点**：

- Issue 原话是「设一个**当前实际值**的基线…**不写一个达不到的理想值**」——
  daemon 是十几个大文件，15.66% 这个数字不好看，但它诚实，且它的作用是**不倒退**
- 留一个点是为了吸收平台差异：覆盖率只在 **ubuntu leg** 上强制（CI 两个 leg 各跑一次，
  两个平台按同一套数字判定会变成假红），而 Windows leg 照旧跑单测守它该守的东西

## 期望

- [x] 收掉 #30：把五条期望逐条对应到今天的状态（上面那张表就是关闭评论的底稿）

## 不做

- **不追覆盖率数字**：本任务只装「不倒退」的门，不为了好看去补测试 ——
  该补的测试由具体功能与缺陷驱动（这几轮的 #147/#148/#150 都是这么来的）
- 不把 e2e 纳入覆盖率统计（技术上看不见，写进配置注释里免得后人再试一遍）
