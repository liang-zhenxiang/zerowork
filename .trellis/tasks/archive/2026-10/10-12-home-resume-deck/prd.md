# PRD:首页开工导航——把「最近会话」升级为「继续推进」工作台

## 背景(为什么做)

ZeroWork 的核心工作循环是「交代一件事 → 它做完 → 交付」。但真实办公节奏里,
**「回来续摊」与「发起新任务」同等高频**:早上打开 app,昨晚跑的周报改到哪了?
上周的数据分析还差最后一步——用户此刻要做的是**接着干**,不是从头想新 prompt。

现状(2026-10-12,main@a1f3903):首页输入卡上方有一块 `HomeRecentSessions`
(`app.js` 15262 行附近):**纯文字行**(标题 + 相对时间),没有任何「干到哪了」的上下文。
用户要判断「哪个活儿推进到哪了」,必须逐个点进去看——首页作为「开工第一屏」,
没有承担起「导航」的职责。

竞品核对(2026-10-12 检索):Claude Desktop / ChatGPT Desktop 的会话列表均为
「标题 + 时间」形态,**没有**「交接摘要」(一句干到哪了)的设计;这是空白,
也是「本地办公 Agent」独有的机会——数据全在本机,摘要零成本、零隐私顾虑。

### 与既有功能的关系(不重复造轮子)

- **TurnNavRail**(会话内右侧轮次轨):解决「会话内回溯」,本功能解决「会话间导航」,
  粒度与场景互补
- **命令面板**(⌘K):可搜索跳会话,是「找」的主动路径;首页续摊区是「回」的被动路径
  (回来就看到,不用想关键词)
- **侧栏任务列表**:全量管理;首页只放最活跃的 3-4 张卡,是「开工导航」不是「清单」
- **HomeRecentSessions 将被本功能替换**(同一槽位,同一数据源升级)

## 期望(做什么)

### 1. 续摊卡(替换 HomeRecentSessions)

每张卡承载:

- **交接摘要**(核心增量):一句「干到哪了」。数据优先级:
  1. 会话 `running` → 摘要呈现「正在做什么」(最后已知动作)
  2. 最后一次交付(`artifacts_presented`)距今最近 → 「已交付 <文件名>」
  3. 否则 → 最后一条 assistant 文本截断(≤ ~60 字)
  摘要为纯投影,不在发送/接收路径上做任何额外工作
- **标题**(现有 deriveSessionTitle)
- **元信息行**:相对时间 · 消息/轮数 · 工作区或项目名
- **活状态**:`running` 的会话在卡上有「不看颜色也读得出」的进行中信号
  (DESIGN.md §7.6:形态 + 文字,如脉冲点 + 「进行中」字样)
- 整卡可点 → 复用现有 resumeSession/resumeTask 通道续摊;卡上不提供管理动作
  (归档/钉住管理留在侧栏,首页只做导航)

### 2. 数量与收纳

- 首页最多显示 **3 张**(按 modifiedAt 排序;视觉定稿 3 张,见 research/ux-proposal.md §1.4
  ——4 张会在 768/800 逻辑高度把输入卡推到折叠线附近,主角被配角挤走)
- **不做「查看全部」入口**(2026-10-12 评审修订):侧栏默认展开且任务全量列表
  常驻侧栏,命令面板可搜会话——首页再加入口属于重复导航,砍掉

### 3. 共存与空态

- **新用户(无会话)不渲染该区**——保持现状(上手清单是主角)
- 上手清单收起后(三步完成),该区成为输入卡上方的主体,布局不跳动
- 该区遵守 DESIGN.md 主列纪律:不新增带边框的内容卡层级,
  视觉方案由 UI/UX 设计师在 research/ux-proposal.md 出稿并评审合流

### 4. daemon 侧投影(新)

- 新增 `sessionDigest` 投影:输入若干 session path,输出每张卡的摘要数据
  (`{ kind: "running"|"delivered"|"text", text, at, deliveredName? }`)
- **不进 listSessions 热路径**(该列表每次 run 边界都推,不能加读文件开销);
  由渲染层对首页可见的 ≤4 张卡按需拉取
- 摘要来源:优先内存桶(bucket.conversation.entries,运行中/最近会话零 IO);
  无桶的落盘会话经 `SessionManager.open(path).getEntries()` 读尾部(设条数上限,
  防大会话全量解析;超大时摘要退化为「N 轮对话」)

## 验收标准

- [ ] 首页出现「继续推进」区:卡片含交接摘要、标题、元信息行;视觉方案经
      UI/UX 设计师评审迭代(评审意见与处置记录在任务 research/ 下)
- [ ] running 会话的卡有不依赖颜色的进行中信号;run 结束后卡片状态随之更新
      (sessionListPush → 重新拉 digest 的链路通)
- [ ] 点击卡片续摊成功(既有 resume 链路,e2e 验证)
- [ ] 无会话时该区不渲染;与上手清单共存不破布局(e2e 截图对比)
- [ ] daemon digest 有单元测试(三种 kind 的优先级、截断、大文件退化、无桶/有桶两条来源)
- [ ] 新增 e2e:真实启动 app,mock 跑完会话 → 回首页 → 断言卡片与摘要 → 点击续摊;
      各状态留截图(浅色;暗色至少一张,验证无字面量色逃逸由 check:theme-tokens 守住)
- [ ] `npm run lint:all`、`npm run test`、`npm run test:gui` 全绿;
      CHANGELOG [Unreleased] 记入「新增」
- [ ] docs/USAGE.md 首页相关段落同步更新

## 非目标(本轮不做)

- 会话搜索/筛选/批量管理(命令面板与侧栏已覆盖)
- 自动化任务动态(独立的「即将发生」区,另行立项)
- 交接摘要的「未读」概念(无已读状态,不造)
- 「今日焦点」等按自然日分组(先做平铺按时间,分组等真实反馈)

## 入手位置

- `src/main/daemon/session-files.js`——digest 投影(与 listSessions 同文件,
  复用 bucketsById / SessionManager.open)
- `src/shared/ipc.js` + `src/preload/index.js`——INVOKE 与桥接(照 sessionList 模式)
- `src/renderer/src/app.js`——HomeRecentSessions 替换(卡片区渲染,挂现有数据流)
- `src/renderer/src/app.css`——卡片样式(Token 内,遵守主列纪律)
- `tests/unit/`——digest 单测;`tests/e2e/home-resume-deck.mjs`——新 e2e

## 难度

中。跨 daemon / 契约 / 渲染三层,但每层都是既有模式的复用;风险集中在
「digest 读文件的成本控制」与「首页布局纪律」两处,均有明确对策(条数上限 / 设计评审)。
