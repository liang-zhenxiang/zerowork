# 视觉方案:首页「继续推进」工作台(续摊卡)

> 任务:10-12-home-resume-deck | 状态:待评审
> 依据:`docs/DESIGN.md`(硬约束)、`app.css` 现状(home-recent / home-guide / composer-slot 段)、
> 首页截图(docs/images/home-light.png、artifacts/tour/01-home.png)。
> 本文中的「§」均指 docs/DESIGN.md。

---

## 0. 一句话定位

**输入卡是唯一的主角;「继续推进」是主角上方的一块次级面,里面的行不是盒子,是便签。**
「同事交接的温度」由摘要文案本身承担(「等你过目」「已交付」),**不由任何装饰承担**——
不加引号、不加左边线、不加图标化前缀。宁可让一句话自己说话。

核心决策一句话:**整个区仍是 home-recent 那块「填色无边的次级面」,升级的只是行内的
信息层级,不新增任何盒子**(§3.9)。竞品(Claude / ChatGPT Desktop)没有「交接摘要」,
这是本方案的差异点;差异点放在**内容密度**上,不放在视觉重量上。

## 1. 布局结构

### 1.1 区块(替换 `.home-recent`,新类名 `.home-resume`)

骨架与 `.home-recent` / `.home-guide` 完全同族——次级辅助面(§3.7):

```css
.home-resume {
    display: flex;
    flex-direction: column;
    gap: var(--space-2);        /* 区头 → 首卡、卡与卡之间 */
    margin-bottom: var(--space-5);  /* 与输入卡的间距:沿用「输入卡上方的次级面」既有口径 */
    padding: var(--space-4);
    background: var(--bg-raised);
    border-radius: var(--radius-md);
    /* 无边框:次级面的身份靠底色,边框是内容卡的(§3.7) */
}
```

### 1.2 区头

```
继续推进
```

- 区名一行,`--text-meta`(12px)+ `--text-secondary`——与 `.home-recent-head`
  同档,分组标题的既有口径。左对齐纯文本行,不需要任何布局规则。
- **不设「查看全部」入口**(2026-10-12 评审裁决,PRD「期望 §2」已同步修订):
  侧栏默认展开、任务全量列表常驻侧栏,⌘K 命令面板可搜会话——首页再加一个入口
  属于重复导航。且区头无可点元素后,这块的点击目标只剩「整卡续摊」一件事,
  与「首页只做开工导航」的定位更贴。

### 1.3 卡(行)内部层级

每张卡是 `button`(整卡可点、键盘可达),**透明底行**,不是子盒子:

```
第一行  [pin] 会话标题………………(省略)          ● 进行中      ← 身份行
第二行  交接摘要,至多两行,超出截断                            ← 灵魂行
第三行  工作区名 · 12 轮 · 2 小时前                            ← 注脚行
```

```css
.home-resume-card {
    display: flex;
    flex-direction: column;
    gap: var(--space-1);        /* 三行之间:4px,信息是一个单元 */
    padding: var(--space-2);
    border-radius: var(--radius-sm);
    text-align: left;
    transition: background-color var(--dur-fast) var(--ease-standard),
                transform var(--dur-fast) var(--ease-standard);
}
```

行与行(卡与卡)之间的呼吸 = 容器 `gap: var(--space-2)`(6px)+ 卡自身上下
`padding: var(--space-2)`(6px)= 12px,大于卡内行距 4px——**组间 > 组内**,
两行不会读成同一句(§3.8 的推论在卡内复用)。

### 1.4 卡片数量:定 3 张

PRD 给的区间是 3-4,设计定稿 **3**,理由:

- 每卡三行约 84-104px,3 卡 + 区头 + 容器 padding ≈ **320px**,与上手清单展开态
  高度相当——新老用户的首页主列高度不因这块产生「新老两个版本」;
- 4 张时 hero(在 `.home-main` 里垂直居中,`padding-bottom: 252` 预留案例槽)在
  常见笔记本高度(768/800 逻辑分辨率)会把输入卡推到折叠线附近——**主角被配角挤走**;
- 第 4+ 张的「收纳」由侧栏与命令面板的既有能力承担(侧栏全量常驻、⌘K 可搜),
  **首页不做任何收纳交互**——没有「查看全部」入口,也没有折叠/展开(裁决记录
  见 §1.2)。首页只做「开工导航」,不做「清单」。

## 2. 卡内各元素的视觉处理

### 2.1 标题(身份行)

- `--text-list`(13px)+ `--text`(100%),与清单待办、侧栏任务行同档——「身份」
  用全页最实的一档正文,但仍低于输入卡(§3.4 口径)。
- `flex: 1 1 auto; min-width: 0;` 单行省略(沿用 `.home-recent-title` 手法)。
- **钉住标记**:标题**前缀**一枚 inline SVG 图钉,复用 `.task-pin-mark` 的全部语言
  (`--text-secondary`、`margin-right: var(--space-1)`、`vertical-align: -0.18em`)。
  位置约定同侧栏:**标记压在标题之前,因为行尾会被省略号裁掉**(见 `.task-branch-mark`
  注释)。实现上建议把 `.task-pin-mark` 的选择器扩为
  `.task-pin-mark, .home-resume-pin` 共用一条规则——不复制视觉值(§6)。
  它是**展示性标记**(「我钉住了它」),不可点;管理动作留在侧栏(PRD)。

### 2.2 交接摘要(灵魂行)——本方案的核心增量

- **字号/颜色**:`--text-list`(13px)+ `--text-secondary`(50%)。与标题同字号、
  降一档色(§2.1 的「降一档」):读起来是「标题下面那句补充」,不与身份行争重,
  也比注脚行实一档。
- **行数上限 2 行**,`-webkit-line-clamp: 2`(`.case-title` 同款既有手法);
  实际文案多为一句(≤60 字,PRD),两行是防御上限。
- **行高 1.6**(§2.6 正文基准)——它是卡内唯一可能折行的多行文本。
- **无前缀、无引号、无斜体**:「已交付 Q3-复盘.md」里的文件名也**不染 `--accent`**——
  整卡可点,文件名单独染链接色会暗示「可以单独点开这个文件」,那是谎言
  (点击行为 = 续摊,不是打开文件)。温度感来自文案语气,不来自样式。
- **摘要位的加载与缺失**(§4 的落点在卡内,不在整区,见 §5):
  - digest 未到:摘要位渲染一条同尺寸骨架(13px、`min-height: 1lh`,
    `GUIDE_SKELETON_TEXT_STYLE` 同款手法),数据到达时「同一片区域被填上」;
  - digest 失败/退化:显示 fallback「最近 N 轮对话」(N 取 `listSessions` 的
    `messageCount`,字段现有)——**不是空、不是挂着骨架**,卡片高度稳定,
    且错误态不伪装成加载态。

### 2.3 活状态(进行中信号)——§7.6 的完整落实

**形态 + 文字,双通道,颜色是第三层补充:**

```
●(呼吸点,6px) 进行中          ← 标题行右端,flex: none 不参与省略
```

- **呼吸点**:6px 圆点,`background: var(--text-secondary)`,
  `animation: tool-pulse 1.1s ease-in-out infinite`——**逐字复用**
  `.trace-seg-live` / `.tool-dot.running` 的既有语言:「还在跑」在工具行、轨迹条、
  续摊卡上是同一套语言(§10.3 已登记该动画语义,本次是第三宿主,见 §8)。
  **不借状态色**:呼吸点只表「进行中」,语义由相邻文字承担(§7.6 原文口径)。
- **文字**:「进行中」三字,`--text-meta` + `--text-secondary`。reduced-motion
  关停动画后,点停在静态实心,文字仍在——关掉的只是「呼吸」,「进行中」语义完整。
- **位置即信号**:标题行右端(卡片的「状态位」),`flex: none` 保证永不被省略号
  裁掉(侧栏把标记放标题前是**行内前缀**场景的取舍;卡是块级布局,右端有专属槽位)。
- hover 时**保持可见**(同 `.task-pin-mark` 的理由:hover 正是用户去看
  「这卡是什么状态」的时刻,此时抹掉状态等于状态在需要时消失)。
- running 卡的**摘要内容**同时呈现「正在做什么」(digest 的 running 分支),
  与徽标互为印证——三个独立通道(位置/形态/文字),任一缺失都读得出。

### 2.4 元信息行(注脚行)

- `--text-meta`(12px)+ `--text-secondary`,与 `.home-recent-time`、`.home-guide-note`
  同族——时间戳与注脚的既有口径。**不用 `--text-faint`**:那是禁用态与最弱图标的
  档位(token 注释原文),正常可读的元信息不降两档(§2.1)。
- 排列:`工作区名 · 12 轮 · 2 小时前`,单项之间 `gap: var(--space-1)` + 「·」
  分隔符(文字分隔符随文案走,比装饰性分隔线克制)。
- 与摘要的层次:同色(50%),**靠字号分档(13 vs 12)+ 摘要可两行/注脚恒一行**。
  在 848px 主列里可辨;如果实现后实测分层不足,优先把摘要升为可两行的完整句
  (内容差异自然拉开),而不是给注脚换色。
- 超长工作区名单行省略(整行 `min-width: 0` + 末项时间 `flex: none`)。

## 3. 与上手清单的共存

三种首页形态,主列从上到下:

| 用户形态 | 主列(能力 chips 之下) | 间距 |
| --- | --- | --- |
| 新用户(无会话) | 上手清单 → 输入卡 | 现状 12/12/24/16 不动(§3.8) |
| 老用户(有会话、清单未完成) | 上手清单 → **继续推进** → 输入卡 | 清单→推进 16,推进→输入卡 16 |
| 老用户(清单已收起) | [上手清单 mini-btn 行] → **继续推进** → 输入卡 | 同上 |

- **次级面之间的间距统一 `--space-5`(16)**:沿用 `.home-recent` 注释里已立的口径
  「两块都是输入卡上方的次级面,节奏一致」。§3.8 的 12/12/24/16 讲的是
  「标题→胶囊→chip→清单→输入卡」,续摊区插入在「清单→输入卡」之间,**不改变
  已标定的四段**,新分段复制同档位——主列不出现第五种间距值。
- 两块次级面不合并为一块:引导与导航是两件事,背景断开(16px 白缝)正好让它们
  各自成立。
- **清单收起时顶上来**:allDone 后清单缩成 `.context-row` 里的 mini-btn(现状行为),
  续摊区自动上移占位——**无过渡动画**(布局属性不参与过渡,§5.1;高度变化靠
  `.home-main` 的 flex 居中自然吸收,与现状清单三态换槽同一手法,§3.9 实例)。
- mini-btn 行与续摊区之间:16,同上口径,不单独决策。

## 4. hover / active 四态(§3 纪律)

| 态 | 卡(`.home-resume-card`) |
| --- | --- |
| normal | 透明底 |
| hover | `background: var(--bg-hover)`(全站唯一 hover 底) |
| active | hover 底 **+ `transform: scale(.98)`**(§3.1 卡片级) |
| focus | 全局焦点环(button 天然获得;§7.1 `--text-secondary` 同色环) |
| disabled | 不适用(卡片无不可用态;会话永远可续摊) |

(区头为纯文本,区内唯一可点元素就是卡——四态表只此一列。)

- 过渡统一 `--dur-fast` + `--ease-standard`(§3),已在卡的 `transition` 里写全
  (`background-color` + `transform` 两个属性)。
- 不做卡的「浮起」(阴影/位移):浮起是浮层语言,次级面里的行用底色回应就够——
  卡浮起来会与输入卡的「唯一渐变槽 + 唯一 `--shadow-input`」争层级(§3.9)。
- 摘要、徽标、钉住标记在 hover 下**不变色不隐藏**:hover 是阅读时刻,不是装饰时刻。

## 5. 空态与加载(§4)

- **空态确认:整区 `return null`,保持现状。** 无会话 = 新用户,首页主角是上手清单,
  这块不渲染(PRD 明确;与现状 `HomeRecentSessions` 的 `sessions.length === 0 → null` 一致)。
- **整区不挂骨架**:列表数据(标题/时间/轮数)来自既有 `sessionListPush` 流,
  通常先于首屏就绪;「数据还没回来」沿用现状「不渲染」口径。这块是**列表**而非
  固定结构,给列表挂「先出空块再填行」的骨架反而制造整块替换——§4 反对的形态。
- **§4 的落点在卡内摘要位**(见 §2.2):骨架 → 真文/退化为「最近 N 轮对话」,
  三态互斥可辨,高度稳定。
- **运行结束**:run 边界 `sessionListPush` → 重拉 digest → 摘要与徽标就地更新,
  无离场动画(§5.8:同性质元素不做出场动画)。

## 6. 暗色主题

**本方案零暗色专属规则、零新 token。** 所有取值引用既有 token
(`--bg-raised` / `--bg-hover` / `--text` / `--text-secondary` / `--radius-*` /
`--dur-*` / `--ease-*`),暗色块已有同名覆盖,`check:theme-tokens` 的
「同名 token 对 + 字面量逃逸」两项检查自动接管:

- 次级面:`--bg-raised` 暗色 #26262a,卡 hover `--bg-hover` 7% 白——层次方向与
  亮色一致(抬升面更深、hover 更亮一档),无需干预。
- 呼吸点:`--text-secondary` 在暗色块换为 55% 白,自动成立。
- 无渐变、无 `color-mix` 新写法、无 scrim 需求。

e2e 按验收标准留一张暗色截图即可。

## 8. 纪律对照与登记事项

### 遵守的既有纪律(逐条)

| 纪律 | 本方案怎么落 |
| --- | --- |
| §2 档位纪律 | 零新档:间距只用 1/2/4/5,字号只用 meta/list,色只用 text/secondary,圆角只用 sm/md,时长只用 --dur-fast |
| §2.0 双块同构 | 零字面量色、零暗色专属规则,token 对检查自动覆盖 |
| §2.1 文字三级 | 标题 100% / 摘要与注脚 50%(降一档),不用 faint |
| §2.4 状态色只表状态 | 「进行中」不用状态色表达,呼吸点中性灰 + 文字;分类信息(工作区)不染色 |
| §3 四态过渡 | --dur-fast + --ease-standard,卡 scale(.98);区内无其它可点元素 |
| §3.7 / §3.9 盒子预算 | **不加任何盒子**:整区一块次级面,区内是透明行;不加边框、不做浮起 |
| §3.8 主列节奏 | 新分段复制 --space-5,已标定的 12/12/24/16 不动 |
| §4 三态 | 摘要位骨架/退化文案互斥可辨;整区空态 null 保持现状 |
| §5.1 布局属性不过渡 | 无 width/height 过渡;清单收起的高度变化由 flex 居中吸收 |
| §5.8 进出场不对称 | 无离场动画;run 结束就地换内容 |
| §6 禁止清单 | 无新类名复制视觉值(pin 标记扩既有选择器)、无原生 select、不隐藏核心功能 |
| §7.1 焦点指示 | 卡与入口都是 button,天然获全局焦点环 |
| §7.6 状态不只靠颜色 | 进行中 = 位置(右端状态槽)+ 形态(呼吸点)+ 文字(「进行中」)三通道 |

### 需要登记/更新的两处(实现时落)

1. **§10.3 「工作轨迹的运行呼吸点」条目扩写**:`tool-pulse` 增加第三宿主
   `.home-resume-live-dot`(首页续摊卡的进行中信号),与 `.trace-seg-live` /
   `.tool-dot.running` 同语言;**§10.3.1 第 ② 组(无限循环动效)同步加该选择器一行**
   (app.css 文件末尾的 reduced-motion 块,约 12012 行处)——关停后停在静态实心点,
   「进行中」由文字承担,终态正确。
2. **`.task-pin-mark` 选择器扩展**:与新的 `.home-resume-pin` 共用一条规则
   (改选择器不改值),在规则注释里补一句「首页续摊卡同款」——避免两处漂移。

### 无需登记的项(说明为什么)

- 无新间距/字号/颜色/圆角/时长档 → 不动 §2 表;
- 无布局属性过渡 → 不进 §5 受控例外表;
- `-webkit-line-clamp` → `.case-title` 既有手法,非新登记项;
- 摘要骨架 → `Skeleton` 组件 + `GUIDE_SKELETON_TEXT_STYLE` 手法复用,非新动效。

## 9. 实现移交清单(给 renderer 层)

- `app.js`:替换 `HomeRecentSessions` 为 `HomeResumeDeck`(渲染 3 张 + 区头,
  **无收纳入口**——裁决见 §1.2);摘要位骨架/退化文案逻辑。
