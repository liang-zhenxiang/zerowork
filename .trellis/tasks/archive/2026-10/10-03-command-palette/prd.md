# 命令面板：一键盘直达任何地方（⌘K）

## Goal

给 ZeroWork 加一个**全局命令面板**：按 ⌘K / Ctrl+K（或点侧栏入口）唤起，输入几个字
就能跳到任何地方或执行任何动作 —— 不用先想「这件事在哪个菜单里」。

这是「好用、想用」的核心承载：它是一个**新用户能一眼看懂的入口**
（「这里能搜到一切」），也是**老用户不再用鼠标的理由**。

## 背景：为什么是这个功能

**已核实的事实**（不是推测）：

1. 仓库里搜不到任何命令面板实现：`command-palette` / `commandPalette` / `cmdk` /
   `⌘K` / `Ctrl+K` 在 `src/renderer/src/app.js` 里出现次数均为 **0**。
2. 现有快捷键只有零散几处（`⌘.` 折叠侧栏、团队视图的 `Ctrl+O`/`Ctrl+T`），
   **没有集中的「键盘体系」**，用户无从发现它们。
3. 侧栏有 6 个导航项、设置里有 9 个分组、首页有 6 个场景与 8 个能力胶囊、
   12 条案例、专家 / 技能 / 连接器 / 自动化各自是独立列表 ——
   **入口已经很多，但彼此之间没有统一的「去哪儿」通道**。
4. 侧栏 4 个导航项是「规划中」（`ready: false`）。**面板里绝不能出现它们** ——
   那会把「功能缺失的错觉」从侧栏扩散到面板（`docs/ONBOARDING-RESEARCH.md`
   已就这一点做过明确判断）。

## Requirements

### R1 唤起与关闭

- `⌘K`（macOS）/ `Ctrl+K`（Windows）全局唤起；再按一次关闭
- `Esc` 关闭，焦点回到唤起前的元素（复用既有 `useModalFocus` 行为）
- 侧栏提供**可发现的常驻入口**（键盘快捷键不能是唯一入口）

### R2 搜索范围（首版）

面板里可搜到的条目分两类：

| 类别 | 内容 | 数据来源 |
| --- | --- | --- |
| **动作** | 新建任务、打开设置（各分组）、切换外观（浅色/深色/跟随系统）、折叠/展开侧栏、检查更新、打开诊断 / 统计 | 渲染层本地状态 + 既有 `window.kami.*` |
| **实体** | 会话、工作空间、专家、技能、连接器、自动化任务 | `listSessions` / `listWorkspaceGroups` / `listExperts` / `skillsSnapshot` / `mcpConfigGet` / `listAutomations` |

- **导航**类条目只收 `ready: true` 的项，未开放项**必须被排除**（见背景第 4 条）
- **每个动作可带「已绑定的快捷键提示」**，贴在条目右侧 ——
  面板同时成为快捷键的学习入口（VS Code 的做法，见调研 §2）。
  当前无提示的动作留空，不做假提示
- 首版**不做**：文件搜索、跨会话全文检索、拼音首字母匹配、自定义键位、
  类型前缀（`>` / `i` / `p`）、命令别名、第二层上下文动作面板

### R3 匹配与排序

排序链**照 Raycast 的优先级次序落到本项目的规模**（调研 §一「给 ZeroWork 的融合结论 B」）：

1. **精确命中**（标题完全相等）
2. **前缀命中**（标题以查询开头）
3. **子串命中**（标题包含查询）
4. **子序列命中**（模糊：查询字符按序出现在标题中）
5. **关键词 / 副标题命中**（标题里没有、但关键词或副标题里有 ——
   例如输入「深色」能命中标题为「切换外观」的动作）
6. 以上同分时：**类别权重**（动作优先于实体）→ **原顺序稳定**

- 大小写不敏感；中文按子串匹配，英文按子序列匹配
- 查询为空时：显示**常用动作 + 最近会话**（不是一片空白，也不是一堵墙）——
  这两类数据都是现成的，**不引入新的持久化**
- **不在首版引入 frecency（频率 + 近因的自学习排序）**：它需要新增一条持久化通道，
  而本项目的持久化有「单一真源」纪律（`preferences.json` 是真源，localStorage 只做首帧镜像）。
  作为**明确的后续项**记录在 `design.md`，不塞进这一版
- 结果上限截断，并在有更多结果时**明确告诉用户还有多少条**（不是静默截断）

### R4 键盘与鼠标等价

- `↑` `↓` 移动选中，`Enter` 执行，`Esc` 关闭
- 鼠标悬停同步选中项；点击等同 Enter
- **中文输入法组合期间**按 `Enter` 不得提交（`isComposing`）—— 中文产品的必需项
- 底部常驻键位提示（Esc / ↑↓ / Enter），让快捷键**可被学会**

### R5 无障碍

- `role="dialog"` + `aria-modal="true"` + 焦点陷阱（与设置面板同口径）
- 输入框 `aria-activedescendant` 指向当前选中项；列表 `role="listbox"`，
  条目 `role="option"` + `aria-selected`
- **状态不只靠颜色**：选中项的表达式除底色外还有可读信号（§7.6）
- 结果数量变化时向屏幕阅读器播报

### R6 视觉

- 必须**看起来像这个产品的一部分**：只用 `app.css` 的既有 token，
  不新造颜色 / 间距 / 圆角档位，不复制视觉值
- 入场 / 退场动效走既有 `--dur-*` 与缓动 token，**进出场不对称**（§5.8），
  `prefers-reduced-motion` 下关停并登记进 `docs/DESIGN.md` §10.3.1
- 不引入布局属性的过渡（§5.1）

## Acceptance Criteria

- [ ] `⌘K` / `Ctrl+K` 能唤起与关闭面板，`Esc` 关闭且焦点回到唤起位置
- [ ] 侧栏存在常驻入口，点击可唤起
- [ ] 输入中文与英文都能搜到对应条目；排序符合 R3 的优先级链，且同分时顺序稳定
- [ ] 关键词命中生效（标题里没有的词也能搜到，如「深色」→「切换外观」）
- [ ] **未开放的导航项不出现在结果里**
- [ ] `↑`/`↓`/`Enter`/`Esc` 与鼠标悬停、点击行为一致
- [ ] 输入法组合期间 `Enter` 不提交
- [ ] 面板结构带 `role="dialog"` / `listbox` / `option`，`aria-activedescendant` 正确
- [ ] 选中项在**不看颜色**时也能辨识（有非颜色的状态载体）
- [ ] 空查询、有查询、无结果三种形态各自可辨，且「无结果」不被当成「加载中」
- [ ] 带快捷键提示的动作，提示贴在条目右侧且与真实键位一致（不做假提示）
- [ ] 浅色与深色两套主题下渲染正确（截图 + 像素断言）
- [ ] `npm run lint:all`、`npm test`、新 GUI 用例全绿；既有 GUI 用例一条不少
- [ ] `CHANGELOG.md` 的 `[Unreleased]` 记入「新增」
- [ ] `docs/DESIGN.md` 登记面板动效；`docs/USAGE.md` 写明快捷键

## 约束

- **不引入新依赖**（面板不装库；模糊匹配自己写，逻辑放可单测的纯模块）
- **不放宽任何安全约束**（面板里的动作走既有 IPC，不新开通道）
- 首版不做：文件搜索、跨会话全文检索、拼音、自定义键位、持久化的 frecency 排序、
  类型前缀、命令别名、第二层上下文动作面板（各自的理由写在 `design.md` 的「明确的后续项」）
