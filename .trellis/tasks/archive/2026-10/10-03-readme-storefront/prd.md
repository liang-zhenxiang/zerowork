# README 门面：让 GitHub 首页自己会卖货

## Goal

**仓库现在零张截图。** 一个陌生人点进来，看到的是一屏徽章 + 一屏文字。

对桌面应用来说，README 就是**门面**：用户在下之前，只能看到这一页。
本任务把「他能看到什么」从「一段自述」变成「他自己看得见的样子」。

## 背景：已核实的事实

- `README.md` 与 `README.en.md` 里的图片只有**徽章**（`grep -n '!\[' README.md`
  只有 5 条，全是 shields.io 的 CI/Release/License 徽章），**没有任何界面截图**
- 仓库里非 `resources/`、非 `artifacts/`、非 `build/` 的 PNG 只有
  `src/renderer/src/assets/logo.png` 与 `out/renderer/assets/logo.png`
- 但**截图资产其实一直在产**：`artifacts/**` 下每个 GUI 用例都有自己的截图目录
  （`smoke/` `theme/` `widget/` `focus/` `recent/` …）。问题是它们：
  1. 是**测试的副产物**，拍的是用例关心的状态，不是「产品最好看的样子」
  2. 不被任何文档引用，等于不存在
  3. 目录不进库（`artifacts/` 在 `.gitignore` 里），**外部访客看不到**

## Requirements

### R1 一份可复现的截图流水线

- 新增一个脚本（`tools/shoot-storefront.mjs` 之类），**真实启动 Electron**、
  驱动到一个**有代表性的状态**，输出 README 要用的图
- **可复现**：任何人 clone 下来跑同一条命令，得到同一组图。
  这与 `tools/build-icons.mjs`（图标生成流水线）是同一套做法
- 用**既有的 mock 模型**（`tests/e2e/mock-model-server.mjs`）造出会话内容 ——
  **不依赖任何真实模型端点、不出网**
- 输出落到仓库内的一个固定目录（如 `docs/images/`），**进库**

### R2 要拍哪几张（首版四张，不多拍）

| 图 | 状态 | 它要回答访客的什么问题 |
| --- | --- | --- |
| 首页（浅色） | 全新环境 | 「它长什么样、我能从哪开始」 |
| 首页（深色） | 同上，切深色 | 「有没有深色」「是不是同一套设计」 |
| 会话 + 产物 | mock 模型跑一轮，右侧产物面板打开 | 「它到底能不能干活」——**这张是转化率最高的一张** |
| 命令面板（⌘K） | 面板打开、有输入与结果 | 「它是不是一个好用的工具」 |

- **尺寸**：以笔记本常见宽度为准（约 1440×900 CSS px），不要拍 2560 宽的开发机尺寸
  ——图在 README 里会被缩放，太宽只会让内容变小
- **重量**：单张尽量控制在数百 KB 内；四张合计不超过约 1.5 MB。
  超了就降宽或换压缩，**不要为了清晰把仓库撑大**

### R3 README 正文改造（中英同步）

两份 README 都要：

- 顶部（徽章之下、正文之前）放**首屏截图**——访客第一眼看到的应该是产品本身
- 一节「它能做什么」，用 2-3 张图 + 短句讲清能力，**不要写成功能清单**；
  每条都要落到「用户的什么麻烦被解决了」
- 「快速上手」写清：下载 → 首次运行怎么打开（**未签名应用的指引必须在这里，
  这是既有承诺**，见 `.trellis/tasks/10-01-first-run-guidance`）→ 配一个模型 → 发出第一条
- 沿用既有的**结构约定**：不新造章节体系、不重复 Roadmap（Issue #21 是路线的单一事实来源）

### R4 图不会烂掉

- 图片路径由 `scripts/check-docs.mjs` 的相对链接校验覆盖 —— **确认它确实覆盖图片**，
  没覆盖就补上（断图与断链在这条检查里应该一样是红）
- 脚本头部写清：**什么时候该重跑**（界面发生明显变化时），以及跑了之后要提交什么

## Acceptance Criteria

- [ ] `node tools/shoot-storefront.mjs` 能在**干净的 clone** 上跑通，产出四张图
- [ ] 四张图都进库且在 `README.md` / `README.en.md` 里被引用
- [ ] 图片总重 ≤ 1.5 MB，单张宽度 ≤ 1600px
- [ ] 截图里**不出现**：真实姓名、真实路径、API Key、内网地址、任何凭证（红线 8）
- [ ] 截图里的版本号是**构建期真值**，不是写死的旧版本
- [ ] `npm run check:docs` 通过，且**断图会被它判红**（反向验证：临时改坏一个路径，确认变红）
- [ ] 中英两份 README 都改到，且**不是机翻**——英文那份按英文习惯重写，不逐字对译
- [ ] `npm run lint:all` 全绿；不改任何 `src/**` 代码
- [ ] `CHANGELOG.md` 的 `[Unreleased]` 记入「变更」（文档层面，用户可见）

## 约束

- **不引入依赖**（截图复用既有 Playwright 与 harness；不做图像处理就别做）
- **不改任何产品代码** —— 这是门面任务，不是功能任务。若发现产品缺陷，
  **另开 Issue**，不要顺手改
- 不动 `resources/**`
- 与既有约定冲突时以 `docs/DESIGN.md` 与 `AGENTS.md` 为准

## 明确的后续项（本任务不做）

| 项 | 为什么 |
| --- | --- |
| 演示 GIF / 录屏 | 需要额外工具与体积预算，且动图在 README 里容易失控；先看静态图的效果再说 |
| 官网 / 落地页 | 本项目没有服务端，也不打算有；GitHub 首页就是门面 |
| 把截图纳入 CI 做像素比对 | 门面图**应该**随设计变化而变，卡死它会让每次改界面都要更新基线 —— 与「测试防退化」的目的相反 |

> 本任务是**轻量任务**：规划产物只需本 PRD。执行清单按 R1→R2→R3→R4 的顺序推进。
