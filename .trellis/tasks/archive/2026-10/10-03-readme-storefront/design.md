## 1. 截图流水线 `tools/shoot-storefront.mjs`

### 为什么要脚本而不是手动截图

手截的图**没人能重拍**：界面一改，图就过期，而过期的图没人知道该换成什么样。
脚本化之后「重跑一条命令」就是全部成本 —— 与 `tools/build-icons.mjs` 同一套做法
（图标的生成流水线本来就是脚本产出的）。

### 怎么拍

复用既有 e2e 骨架（`tests/e2e/lib/harness.mjs`），**不另起一套启动逻辑**：

```
createHarness({ name: "storefront" })   // 隔离目录，不碰真实用户数据
  h.launch()                             // 真实启动 Electron
  win.screenshot({ path, scale: "css" }) // ← 关键：按 CSS 像素拍，不按设备像素
```

- **`scale: "css"` 是这套方案的关键**：本机 dpr=2，默认会拍成 2880×1800（单张数百 KB）；
  按 CSS 像素拍就是 1440×900，**清晰度够 README 用，体积降一个数量级**。
  harness 的 `h.shoot()` 不暴露这个参数，所以脚本直接调 `win.screenshot`。
- **窗口尺寸**：先设成笔记本常见宽度再拍（`app.evaluate` 改 BrowserWindow 尺寸，
  或 Playwright 的 `win.setViewportSize`）。**必须确认应用不会把尺寸写回并复用它** ——
  若应用持久化窗口 bounds，就在隔离配置目录里跑（harness 本来就是隔离的）。
- **不联网**：会话内容用 `tests/e2e/mock-model-server.mjs` 造，**不依赖任何真实模型端点**。
  唯一会出网的是首页案例封面（`static.workbuddy.cn`）—— 它在有网时拍出来才好看；
  断网时是图标兜底，**也是可接受的产出**，脚本要说明这一点而不是假装没有。

### 拍哪四张（见 `prd.md` R2）

| 文件 | 状态 |
| --- | --- |
| `docs/images/home-light.png` | 全新环境首页 |
| `docs/images/home-dark.png` | 切深色后的首页 |
| `docs/images/conversation.png` | mock 模型跑一轮 + 右侧产物面板打开 |
| `docs/images/command-palette.png` | ⌘K 打开、输入若干字、有结果 |

**顺序**：先截图再断言（仓库既有纪律）——但这份脚本的「断言」是**产物契约**：
四张图都存在、尺寸正确、**不是纯色**（复用 `tests/e2e/lib/png.mjs` 的 `imageStats`）。
一张全白/全黑的图如果静默产出并被提交，比不产出更糟。

### 脚本自己也要有守卫

`tools/` 下的脚本不受 `lint:all` 之外的保护，容易被改坏而没人发现。做法：
**脚本退出码非零即失败**，并且在 `check:docs` 里断言四张图存在（见 §3）。

## 2. README 改动的形状

### 结构（中英两份同步）

```
徽章
├─ 一句话定位
├─ 首屏截图（home-light.png）        ← 访客第一眼看到的是产品
├─ 它能做什么（3 条，每条一句用户的话 + 一张图）
├─ 快速上手（下载 → 首次运行怎么打开 → 配模型 → 第一条）
├─ 安装（既有段落，保留）
└─ …（既有段落全部保留，只增不改）
```

### 硬约束

- **不新增章节体系**：沿用既有的标题层级与顺序，只**插入**产品展示那一段
- **不重复 Roadmap**：路线的单一事实来源是 Issue #21，README 指向它即可
- **首次运行指引必须仍在显著位置**：`check-release-notes.mjs` 会校验 README /
  README.en / USAGE 三处的指引（6/6 条），**改完必须仍然通过** —— 这是既有承诺，
  不是为了本次任务才有的
- **英文版不是机翻**：按英文表达习惯重写那几段，不逐字对译

### 图片引用的写法

用相对路径（`docs/images/home-light.png`），**不要**用 `raw.githubusercontent.com`
的绝对地址 —— 仓库改名/转移时会整批断掉，而相对路径由 `check-docs` 守得住。

## 3. 让图不会烂掉

`scripts/check-docs.mjs` 现在校验「相对链接能否落到真实文件」。**先核实它是否覆盖
图片引用**（`![alt](path)` 与 `<img src>` 两种形态）：

- 若已覆盖 → 什么都不用改，只补一条反向验证记录（把路径改坏，确认它变红）
- 若未覆盖 → 扩到覆盖，并同样做反向验证

**为什么这条比「记得更新截图」重要**：图片路径写错时页面**不报错** ——
GitHub 上就是一个破图图标，而维护者本地看不见（他看的是编辑器预览）。
这类静默失败正是静态检查该管的。
