# 资料库：把「交付过的产物」做成一个真页面

> 一手调研（数据来源、代价、可复用件、边界）见 `research/feasibility.md`。
> 对应的 Issue 是 **#115**。本文件只保留需求、口径与验收标准。

## Goal

侧栏的「资料库」至今是 `ready: false`，而 **`docs/USAGE.md` 已经承诺了它**
（「交付成功之后『资料库』里会出现对应的卡片」）。**文档与实现不一致** ——
用户照着文档去找，会发现那一项按不动。

这不是加一个新功能，是**把已经承诺过、也在界面上占了位的那个位置做成真的**。

## 背景：已核实的事实

| 项 | 结论 | 出处 |
| --- | --- | --- |
| 产物数据在哪 | 各会话 `.jsonl` 里的 `customType: "artifacts_presented"` 条目，**存绝对路径**，字段 `path` / `size` / `html` / `kind` + `focusFile` + `timestamp` | `research/feasibility.md` §1.4（贴了磁盘原文） |
| 有现成的聚合路吗 | `listSessions()` **不含**产物；产物目前只在**单会话视图**里重建 | §2.1 / §2.4 |
| 全量扫盘代价 | 本机 14 个会话文件 / 3.3 MB，逐行 JSON.parse 在**数十毫秒级**；而且 `listSessions` 本身**已经**在每个 run 边界把每个文件整份流式读完 | §3 / §2.2 |
| 界面可复用什么 | 列表抄 `OverviewView`；整页骨架抄 `SkillsView` / `AutomationsView`；预览复用 `kindOf` + `previewBaseUrl` + `openPreview2`；定位来源会话复用 `resumeTask` | §4 |
| 怎么挂真页面 | `NAV_ITEMS$1` 改 `ready: true` + 在按 label 分派处加一个分支 | §4.2 |

## 口径（六个待定项的定论；理由见 `design.md`）

| 问题 | 定论 |
| --- | --- |
| 跨工作区产物怎么预览（既有读取以**当前会话 cwd** 为边界） | 预览走**来源会话的 cwd**（`previewBaseUrl(cwd)` 本来就接收 cwd）。**不新开「渲染层指定任意 cwd」的读取通道** —— 那是放宽安全边界。落在该 cwd 外的产物降级为「在文件夹中显示」+ 明确的不可预览说明 |
| 含不含定时任务（run 会话）的产物 | **v1 不含**，与 `listSessions` 的内部会话过滤口径一致；另立后续项 |
| 显示快照还是实时值 | 列表显示**交付时刻**的 size/kind（那是事实），另带一个聚合时算出的 `exists` 实时标记 —— 一个答「当时多大」，一个答「现在还在不在」 |
| 缓存 | **v1 不做**（数十毫秒 + 只在用户打开时拉一次）。理由写在 `design.md`，以免下一轮重新论证 |
| 只列产物还是也列工作空间文件 | **只列产物**。`docs/USAGE.md` 现在的「工作空间文件与产物」超出实现，一并改掉 |
| 去重语义 | **全局按 path 合并**：同一文件只出一行，保留最近一次交付的元数据，并显示「N 个会话交付过」 |

## Requirements

### R1 数据

- 新增**拉式** IPC（用户打开页面时才拉，不挂推送、不进热路径）
- 按 path **全局去重**，保留最近一次交付的元数据
- 每个条目带来源会话信息（会话路径 / 标题 / cwd / 最后活动时间）与一个 `exists` 标记
- **坏会话文件不能让整页崩**（逐行 JSON 解析要能跳过坏行）

### R2 界面

- 新视图 `library`；列表行**与既有列表同一套视觉**（抄 `OverviewView` 的行形态）
- 三种态**互斥且可辨**：加载中 / 还没有产物 / 出错可重试
- **空态要教人怎么产生产物** —— 这是本页最可能的首次见面
- 失效条目（`exists: false`）在列表里**明确标出**，不是等用户点开才发现
- 动作：**预览**（走来源会话 cwd）、**定位到来源会话**
- 侧栏「资料库」从「规划中」组移到已就绪

### R3 测试

- **单元**：聚合逻辑（逐行解析 / 去重语义 / 失效标记 / 坏行与坏文件不炸）
- **GUI**：真实启动 —— 空态、**造一次真交付后列表出现该产物**、失效标记、
  「定位到来源会话」跳转、深浅两套主题截图
- **反向验证**：把去重去掉 → 对应用例变红；把空态与加载态合并 → 对应用例变红

### R4 文档

- `CHANGELOG.md` 的 `[Unreleased]` → 「新增」
- `docs/USAGE.md` 的「资料库」一节改写成与实现一致（只列产物、失效条目怎么处理）
- Roadmap（Issue #21）同步

## Acceptance Criteria

- [ ] `npm run lint:all`、`npm test`、`npm run test:gui` 全绿，既有用例一条不少
- [ ] 新 IPC 的**非法/异常路径**有明确行为（坏会话文件跳过而不是抛；空目录返回空列表）
- [ ] 侧栏「资料库」可点且进入新视图；「规划中」组少一项
- [ ] 空态、加载态、错误态**三者可辨**，且空态含「怎么产生产物」的指引
- [ ] 造一次真交付后，列表出现该产物，且**来源会话信息正确**
- [ ] 同一路径被两个会话交付时**只出一行**，并标出交付过它的会话数
- [ ] 产物被删除后，条目**标出失效**而不是静默消失或留下死链
- [ ] 「定位到来源会话」真的跳到那个会话
- [ ] 浅色 + 深色两套主题的截图各一张，人工看过
- [ ] **反向验证**两条都真跑并记录（去重 / 空态与加载态合并）
- [ ] `CHANGELOG.md`、`docs/USAGE.md`、Roadmap 均已更新

## 约束

- **不放宽安全边界**：不新开「渲染层指定任意路径去读」的通道；预览仍走既有
  `previewBaseUrl` + `resolveWithinRoot`
- **不出网**：只读本地会话文件与本地文件（`EXTERNAL_REQUESTS.md` 无需新增条目）
- 不改 `resources/**`；不为 lint 通过而大规模重排 `app.css`（红线 6）
- 不顺手做「工作空间文件浏览」（那是另一个功能，明确不在 v1）
