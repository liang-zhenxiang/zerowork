# 视觉方案:文件时光机(文件历史版本与还原)

> 任务:10-15-file-time-machine | 状态:待评审
> 依据:`prd.md`(需求与边界,权威)、`design.md`(数据契约与已有决定)、
> `docs/DESIGN.md`(硬约束)、`.trellis/spec/renderer/index.md`(渲染层规范)、
> `app.css` 现状(`.settings` 页壳 / `.auto-list` / `.code-block` / `.trace-seg` /
> `.state-*` / `.timeline-row.selected` 段)与 `app.js` 既有页面(`LibraryView` /
> `StatsView` / `ProjectView`)。
> 本文中的「§」除特别注明外,均指 `docs/DESIGN.md`。

---

## 0. 一句话定位

**一页只有一个盒子:右侧的「版本时间轴 + 只读预览」是那张内容卡;左侧文件清单是
一块没有边框的索引列,不是第二个盒子。**

再把主语说清楚一次:**时间轴是主角,但它靠「时间方向 + 节点形态 + 当前选中态」立起来,
不靠装饰**。每个版本是一行可点的**透明行**,不是一张小卡;节点是 10px 的圆点加一条
1px 竖线,颜色只走三级文字色与 `--border`。整页**不新增任何间距 / 字号 / 颜色 /
圆角 / 时长档位,不新增任何动画**(§2 档位纪律、§10.3 登记)。

与竞品的差异点(PRD 已论证:同类本地 AI 桌面端这一格是空白)落在**每个版本都挂着
「哪条会话、哪次工具调用」**上 —— 这份「来源」由时间轴第二行承载,同样不靠装饰。

## 1. 信息架构与页面骨架

### 1.1 侧栏入口

- 「文件历史」排**「资料库」之后**(PRD 期望 §2 与 design.md §4 均已定),写法照
  「诊断」「统计」的独立 `.nav-item`(它们在 `NAV_ITEMS` 数组外单独渲染一行),
  因此**不改 `NAV_ITEMS$1` 数组本身**,只在它后面追加一项。
- 图标新增一枚内联 SVG(`IconHistory`,表盘 + 回溯箭头的常规时钟图),写法照
  `IconChart` / `IconStats` 的一行式本地定义 —— 图标不是 token,不进 §2 档位表。
- 入口开合与侧栏折叠行为完全继承 `renderNavItem` / `.nav-item`,不加任何新交互。

### 1.2 页面骨架:左列清单 + 右列时间轴与预览

页壳整体复用 `.settings`(`settings-head` 返回键 + 标题 + 右侧「刷新」),
照 `LibraryView` / `StatsView` 的既有写法。**两处是本页独有的覆盖**:

```css
/* 900px 是设置页的「阅读列宽」;本屏是主从两列,套 900 会把右列压窄。
   与 .settings-body[data-projects] / [data-compare] 同一条覆盖手法(属性选择器,
   不改 .settings-body 本体)。container-type 让窄窗口退让走容器查询而非媒体查询 ——
   侧栏开合会改变可用宽(264px 摆动),窗口宽是另一个量([data-compare] 的既有理由)。 */
.settings-body[data-file-history] {
    max-width: none;
    container-type: inline-size;
}

.fh-layout {
    display: grid;
    grid-template-columns: minmax(220px, 280px) minmax(0, 1fr);
    gap: var(--space-6);
    align-items: start;
}
```

两列的**身份分工**是整个方案的第一条硬决定(§3.9 盒子预算):

| 列 | 身份 | 依据 |
| --- | --- | --- |
| 左列 · 文件清单 | **无边框索引列**(直接坐在页面上,行 hover `--bg-hover`、选中 `--bg-raised`) | 它是导航,不是内容;给它一块底色面板就等于在右卡旁边立第二个盒子 |
| 右列 · 时间轴 + 预览 + 还原 | **全页唯一的内容卡**(`--bg` + `1px --border` + `--radius-md`) | §3.9「一个页面只允许一个内容卡级的主盒子」;§3.7「内容卡:圆角 `--radius-md` + 底色 `--bg`」 |

右卡**内部**只有两种成分:透明行(时间轴节点)与**一个内框工具**(只读预览,
`.code-block` 族)。预览是「被框起来的工具」,不是又一个内容卡
(§6「内容卡之外的框只给真正需要框的工具」;对话里的 `.code-block` 就是先例)。

### 1.3 窄窗口怎么退让

用**容器查询**分三档(容器是 `.settings-body[data-file-history]` 的可用宽,
不是窗口宽 —— 侧栏开合、面板展开都会改它):

| 容器宽 | 形态 | 说明 |
| --- | --- | --- |
| ≥ 880px | 两列:清单 280 + 右列 `1fr` | 基准形态 |
| 620–880px | 两列:清单 `minmax(200px, 220px)` + 右列 `1fr` | 右列变窄,预览靠 `overflow-wrap: anywhere` 收;不藏任何信息 |
| < 620px | **单列**:清单收成一行「文件选择条」,时间轴与预览全宽在下 | 见下 |

< 620px 的「文件选择条」= 一枚 `mini-btn` 形态的按钮,显示**当前文件的文件名 ·
版本数**,点击**弹出现有的自定义菜单**(`.pop-menu` 语言)列出全部文件 ——
**不用原生 `<select>`**(§6 禁止清单)。它由 `data-narrow` 状态切换挂载:

```css
@container (max-width: 620px) {
    .fh-layout { grid-template-columns: minmax(0, 1fr); gap: var(--space-5); }
    .fh-index { display: none; }
    .fh-picker { display: inline-flex; }   /* 默认 display: none */
}
```

## 2. 左列:文件清单

### 2.1 区头与截断说明

```
文件历史 · 12 个文件          ← 区头:--text-meta + --text-secondary(分组标题既有口径)
文件较多,这里只显示最近改动的 200 个。   ← 仅 truncated 时出现,同 .stat-hint 口径
```

区头照 `.home-recent-head` / `.proj-section-title` 的既有口径(纯文本行,无需布局规则)。
截断说明的句式**逐字照抄资料库**(`LibraryView` 的「产物较多,这里只显示最近交付的
500 条。」)—— 同一件事在两页用同一句话,用户不必重新学。

### 2.2 行的信息层级

每行是一个 `button`(整行可点、键盘可达),**透明底行**,不是子盒子
(`--radius-sm`、上下 `padding: var(--space-2)`),三行结构:

```
第一行  [文件图标] 周报.md ······································  3 版   ← 身份行
第二行  市场部/2026Q4 ·····················································      ← 位置行
第三行  2 小时前 · 市场部周报 ·································  已不在   ← 注脚行
```

- **第一行**:文件名 `--text-list` + `--text`,单行省略(`flex: 1 1 auto; min-width: 0`);
  行尾版本数 `--text-meta` + `--text-secondary`,`flex: none` 不参与省略。
  文件名前一枚 `FileTypeIcon`(既有组件,`size: 14`)—— 与资料库、目录树同族,
  不新造图标体系。
- **第二行**:所在目录(`dir`,相对工作区或末两段),`--text-meta` + `--text-secondary`。
  目录路径长,整体单行省略并带 `title` 全文。
- **第三行**:`formatRelativeTime(lastAt)` · 来源会话标题 · (可选)状态标记,
  `--text-meta` + `--text-secondary`。**不用 `--text-faint`** —— 它是禁用态与最弱图标的
  档位,正常可读的注脚不降两档(§2.1)。
- **来源会话解析不到时**:显示「来源会话已不在」,不显示裸 sessionId(对用户无意义)。

### 2.3 文件已被删除(`exists: false`)

**不隐藏、不静默**。三处如实说:

- 列表第三行末追加「**文件已不在**」(`--text-secondary`,与 `ProjectView` 里
  `a.exists === false ? "文件已不在"` 的既有措辞逐字一致 —— 同一件事同一句话);
- 右侧卡片头追加一枚「文件已不在」文本标记(`--text-meta` + `--text-secondary`,
  **不借状态色**:这不是错误状态,是文件当前的事实,§2.4);
- 还原确认句里补一句「文件已不在,还原会重新创建它」(design.md §5 明示这是设计行为)。

### 2.4 有 N 次改动没留下版本(`skipped > 0`)

- 列表第三行追加「**· N 次未记录**」(同一档位),让「这文件有缺口」从清单就能看见;
- 卡片内在时间轴上方补一条说明行(见 §3.8),写清原因。

### 2.5 四态(§3 纪律)

| 态 | 行(`.fh-file-row`) |
| --- | --- |
| normal | 透明底 |
| hover | `background: var(--bg-hover)`(全站唯一 hover 底) |
| active | hover 底 + `transform: scale(.98)`(§3.1 卡片级) |
| focus | 全局焦点环(`button` 天然获得,§7.1) |
| selected | `background: var(--bg-raised)` + `--radius-sm`(**逐字复用** `.timeline-row.selected` 的既有口径,不新造选中语言) |
| disabled | 不适用(文件行永远可点) |

过渡统一 `--dur-fast` + `--ease-standard`(§3),
只声明 `background-color` 与 `transform` 两个属性。

## 3. 右侧:版本时间轴(主角)

### 3.1 方向与默认选中

- **方向:旧 → 新,自上而下**(`design.md` §2 明确 `versions` 数组旧→新排序且
  「与时间轴渲染方向一致」;渲染层**不再二次倒序**)。
  这与本项目既有的时间语言一致:工作轨迹条、诊断页 `.timeline` 都是自上而下顺时序。
- **默认选中最新一版**(数组末位),并在挂载后把它滚进视野 ——
  用户打开这一页十有八九是为了「退回最近的那一次改动」,落地时就该站在那儿。
- **一句必要的说明**(时间轴下方一行,`--text-meta` + `--text-secondary`):
  「这里每一版都是**某次改动之前**的内容;当前磁盘上的内容不在其中,还原之后它会作为
  一条新版本出现在末尾。」—— 不说这句,「3 个版本」为什么不是「文件被改了 3 次」
  就说不通。

### 3.2 节点形态与连接

不使用 chip 流,使用**行 + 左侧刻度槽**(每行一个 `grid-template-columns: 20px 1fr`):

```css
.fh-node {
    display: grid;
    grid-template-columns: 20px minmax(0, 1fr);
    gap: var(--space-3);
    padding: var(--space-2) var(--space-2) var(--space-2) 0;
    border-radius: var(--radius-sm);
    text-align: left;
    background: transparent;
    transition: background-color var(--dur-fast) var(--ease-standard),
                transform var(--dur-fast) var(--ease-standard);
}
/* 刻度槽:圆点 + 贯穿槽宽的 1px 竖线。竖线用伪元素,不占额外 DOM。 */
.fh-node-mark { position: relative; display: flex; justify-content: center; }
.fh-node-mark::before {          /* 连接线:贯穿整个槽高;首末行由行级类裁掉半截 */
    content: "";
    position: absolute;
    top: 0; bottom: 0;
    width: 1px;
    background: var(--border);
}
.fh-node-dot {
    position: relative;          /* 盖在竖线上 */
    width: 10px; height: 10px;
    margin-top: 4px;             /* 与首行文字基线对齐 */
    border-radius: var(--radius-full);
    background: var(--border);
    transition: background-color var(--dur-fast) var(--ease-standard);
}
```

- **连接线**是 `--border` 的 1px 竖线,首行上半段与末行下半段用行级类
  (`.fh-node.first` / `.fh-node.last`)裁掉 —— 线是「时间在流动」的记号,不是装饰。
- **连接线不做任何动画**(不扫光、不生长):`width`/`height` 过渡是 §5.1 的禁区,
  `transform` 版又会与「时间轴是静态事实」的语义打架。**零动画是本方案的选择,不是遗漏**(见 §9)。

### 3.3 每个节点要同时说清三件事

节点右槽三行,层级照首页续摊卡的三行结构(同一套「身份 → 灵魂 → 注脚」逻辑):

```
第一行  10-15 14:32 ··································  write · 市场部周报   ← 身份行
第二行  被一次 +12 −3 的改动替换                                              ← 变化行
第三行  3 小时前                                                              ← 注脚行
```

- **身份行**:绝对时间 `--text-list` + `--text`;右端「工具 · 来源会话标题」
  `--text-meta` + `--text-secondary`(会话标题过长时**从会话名一侧省略**,
  时间戳 `flex: none` 永不裁)。工具名走 `--font-mono`(与 `.trace-seg-count` 同一手法:
  同字号同色,靠等宽字形与文字区分)。
- **变化行(灵魂)**:`+X −Y` 沿用**既有 `.tool-change` 口径** ——
  `--font-mono` + `--text-meta`,`+` 走 `var(--ok)`、`−` 走 `var(--danger)`
  (全站三处 `.tool-change` / `.changes-summary` / `.preview-item-meta` 已同款)。
  **符号本身承担语义**(§7.6:不看颜色也读得出 `+`/`−`);若终审认为 §2.4
  「状态色只表状态」不容此解,降级方案是整行 `--text-secondary` 单色,语义不丢。
- **措辞口径**(由 `file-history-core.js` 产出,可被 vitest 直测,design.md §4):
  - 该版**之后**还有改动:`被一次 +12 −3 的改动替换`;
  - 该版是**最新一版**(其后没有记录的改动):`这是最近一次改动之前的样子`;
  - 注脚行:相对时间(`3 小时前`),由既有相对时间工具产出,不在渲染层拼字符串。

### 3.4 四态(§3 纪律)+ 键盘可达

| 态 | 节点(`.fh-node`) | 圆点 |
| --- | --- | --- |
| normal | 透明底 | `--border` 实心 10px |
| hover | `background: var(--bg-hover)` | `--text-secondary` |
| active | hover 底 + `transform: scale(.98)` | 同上 |
| focus-visible | 全局焦点环(`--text-secondary` 同色,§7.1) | 同上 |
| **selected** | `background: var(--bg-raised)` + `--radius-sm` | `--text` 实心 12px + `box-shadow: 0 0 0 3px color-mix(in srgb, var(--text) 8%, transparent)`(一圈极淡的扩环,**只强化选中,不新增颜色**) |
| **disabled**(`broken`) | `opacity: .55`、`cursor: default`、无 hover 底(§3.4「禁用行只改透明度,不置灰背景」) | `--border` 空心(外圈 1px,内里透明) |

选中态是**双通道**:行底(`--bg-raised`)+ 圆点形态(实心放大 + 扩环)。
**不只靠颜色**(§7.6)—— 即使打不出颜色,圆点的实心/空心与大小差异仍然可辨。

键盘可达(**有意不用 listbox 语义**):

- 时间轴整体是一个语义列表(`role="list"`),每个节点是真实的 `<button>` 包在
  `<li role="listitem">` 里,**天然进 Tab 序列**,不需要 roving tabindex。
  数量上限 20(design.md 硬边界),Tab 走完可接受;这不是需要方向键管理的长列表。
- `Enter` / `Space` 选中该版并预览;**不做**方向键在节点间移动 —— 那要套 listbox 语义,
  会与「节点本身就是按钮」打架。
- 被 `broken` 的节点是 `disabled` 的 `button`(仍可被聚焦读取,但不可激活)——
  **不能用 `tabindex="-1"` 把它整个藏出键盘**:藏起来 = 键盘用户看不见这文件丢了一版
  (§7.9 的反面教训)。

### 3.5 节点容器与长列表

时间轴自己是一个**限高滚动区**,不把整张卡撑成几屏:

```css
.fh-timeline {
    max-height: min(36vh, 300px);
    overflow-y: auto;
    scrollbar-gutter: stable;   /* 与 .settings-body 同口径:内容跨过限高时不横向抖 */
}
```

- 上限 20 版 × 每版约 60px ≈ 1200px,限高后滚动是必要条件。
- 加载时用 `Skeleton` 填**同尺寸、同类名**的节点行,整块 `role="status"`(§4)。

### 3.6 只读预览区

**排版口径:一律等宽正文,不做 markdown 渲染。**

- 理由:版本存的是文件的**原始字节**(`<id>.txt`,UTF-8 原文),可能是 `.md`、
  `.csv`、`.json`、`.py`、`.txt` —— 渲染成 markdown 只在 `.md` 上成立,对其余类型
  反而误导(把 `# 标题` 当标题、把表格分隔线吃掉)。等宽是**对「原文」唯一忠实的呈现**。
- 容器与头行**复用 `.code-block` 族**:`.code-block`(1px `--border` + `--radius-md`
  + `--bg-hover` 底)与 `.code-block-head`(`--bg-raised` 底 + 底边线)。
  头行左侧是版本标签(时间 + 大小 + 「只读」),右侧是「复制」(走既有
  `.code-block-copy` 图标钮语言)。**不为本页新造对话框、不新造代码框。**
- 正文排版:

```css
.fh-preview-body {
    margin: 0;
    padding: var(--space-3) var(--space-4);
    max-height: min(50vh, 420px);
    overflow: auto;
    font-family: var(--font-mono);      /* 与 .markdown pre code 同族 */
    font-size: var(--text-meta);
    line-height: 1.6;                    /* §2.6 正文基准 */
    white-space: pre-wrap;
    overflow-wrap: anywhere;
    tab-size: 4;
    color: var(--text);
}
```

### 3.7 长文截断口径(写死,不留实现者自由发挥)

**不做字级截断,做行数级限高 + 滚动**,并在头行显示真实字节数:

- 单版体积上限 1 MiB(design.md 硬边界),1 MiB 纯文本约 1–2 万行,
  `max-height: min(50vh, 420px)` + 内部滚动即可,不需要「只显示前 200 行」这类二次截断;
- **绝不用 `-webkit-line-clamp` 截正文** —— 那会让「这版到底是什么」永久不可见,
  与「时光机」的承诺相反;
- 头行永远显示 `formatBytes(size)`(如 `12.4 KB`)与「只读」,让用户知道自己在看
  多大的一份东西;
- **不做**「内容为空」的特殊态:0 字节版本在契约里合法(文件被清空过),
  预览体渲染为空白,头行大小显示 `0 B`,这已经说清了(空白 + `0 B` = 内容就是空,
  不是没加载)。

### 3.8 时间轴上方的说明行(如实说,不静默)

在 `.fh-timeline` 之上、卡片头之下,按条件插入 `--text-meta` + `--text-secondary`
的说明行,**一条一行,永不折叠**:

| 条件 | 文案(原文) |
| --- | --- |
| `skipped > 0` | 「另有 N 次改动没有留下版本:文件超过 1 MiB,或不是文本文件。」 |
| `skipped > 0` 且存在 `broken` | 上一条 + 「其中 M 版的内容已不在,不能还原,但时间点仍在。」 |
| (始终) | 时间轴下方的方向说明(§3.1) |

`broken` 的节点自身也在节点行里明说(见 §6 表格)。

## 4. 「还原到此版本」

### 4.1 按钮位置与层级

**按钮放在只读预览的头行右端**,与「复制」并排:

```
┌ .fh-preview-head(复用 .code-block-head)──────────────────────────────────┐
│  10-15 14:32 · 12.4 KB · 只读            [⧉ 复制]   [还原到此版本]        │
└───────────────────────────────────────────────────────────────────────────┘
```

- 为什么在这里,而不是卡片头、也不是时间轴里每行一枚:还原**作用的对象就是正在预览的
  那一版**,按钮必须贴着它。放进卡片头会让人不确定「拿哪一版去还原」;
  放进每个节点会变成 20 枚按钮,且与「点节点 = 选中」抢点击。
- 用 `mini-btn`(**不是** `primary-btn`):整页的主操作是「浏览」,还原是正文之上的
  二级动作;`primary-btn` 的实心黑会把视觉重点从版本内容上拽走。它复用的是全站
  二级按钮语言(资料库 / 项目详情里同类动作一律 `mini-btn`)。
- **不用 `--danger`**:还原会先把当前内容存成一条新版本(可逆),§2.4 不允许把
  「可逆动作」涂成危险色。危险色留给「删了回不来」的动作。

### 4.2 二次确认的形态:**就地确认条,不用模态**

**否掉模态的理由**:模态背板(`--overlay` 40%)会把用户**正要核对的「目标版本正文」
压在下面**。这个确认的全部价值就是「你看着目标、再决定」—— 遮住它等于把决策依据拿掉。
PRD 要求二次确认说清三件事,**就地确认条能在一句话里说完三件事且不遮挡预览**。

点击「还原到此版本」后:

```
┌ 预览头(不变)─────────────────────────────────────────────────────────────┐
├ .fh-confirm(--bg-raised · --radius-sm · 无边框)───────────────────────────┤
│ 把「周报.md」还原到 10-15 14:32 的样子?现在的内容会先存成一条新版本,        │
│ 之后还能再退回来。                              [取消]  [确认还原]         │
└───────────────────────────────────────────────────────────────────────────┘
```

```css
.fh-confirm {
    display: flex;
    align-items: center;
    gap: var(--space-3);
    padding: var(--space-3) var(--space-4);
    background: var(--bg-raised);   /* 次级面:一把椅子,不是一个盒子(§3.7 无边框) */
    border-radius: var(--radius-sm);
    font-size: var(--text-meta);
    color: var(--text-secondary);
}
.fh-confirm .fh-confirm-text { flex: 1 1 auto; min-width: 0; }
```

- 确认条插在预览头与预览体之间;**预览头右端的触发按钮在确认态消失**,不出现
  「两个还原按钮」。
- 「确认还原」用 `mini-btn`(不是 `primary-btn`),理由同 §4.1;
  「取消」是同一档 `mini-btn`。
- 进入 / 退出确认态**不给动画**(§5.8 只约束「同性质元素」的进出场;这里是内容就地
  替换,与首页清单三态换槽同一手法 —— 换形态不换槽)。

### 4.3 确认文案(原文,逐字)

```
把「<文件名>」还原到 <MM-DD HH:mm> 的样子？现在的内容会先存成一条新版本，之后还能再退回来。
```

三个事实**按顺序**落进这一句:

1. 哪个文件 → 「<文件名>」;
2. 退到哪个时间点 → 「<MM-DD HH:mm>」(与节点身份行同一格式);
3. **当前内容会先存成一条新版本** → 「现在的内容会先存成一条新版本,之后还能再退回来」。

`exists: false` 时句尾追加「文件已不在,还原会重新创建它。」

### 4.4 还原之后

- 成功:关闭确认条 → 就地 toast(既有 `.toast` 语言)`已还原到 10-15 14:32`,
  并**重新拉一次清单与时间轴**(还原本身会追加一条新版本,时间轴末尾会多出
  「你还原之前的内容」那一版 —— 这正是「还能退回来」的可见证据,必须当场刷新出来)。
- 失败(daemon 返回 `reason`,design.md §3.1):**就地呈现,不 reject**。
  确认条位置替换为一行错误(复用 `ErrorState` 的视觉:1px `--danger` + 8% `--danger` 底):

| `reason` | 文案 |
| --- | --- |
| `running` | 「这个文件所属的会话正在运行,等它跑完再还原。」(附「重试」) |
| `missing` | 「这一版的内容已不在(存储缺失或损坏),无法还原。其余版本仍然可用。」(无重试) |
| `no-such-version` | 「这一版已经不在了,时间轴已刷新。」(自动刷新) |
| `write-failed` | 「写入失败:<原始错误摘要>。文件未被改动。」(附「重试」) |
| `unknown` | 「还原失败:<信息>。」(附「重试」) |

> 若渲染层已能从会话列表判断该会话在跑,可在预览头先给一条 `--text-secondary`
> 说明并把按钮置 `disabled`(§3.4:禁用只改透明度);daemon 的 `running` 返回值
> 仍是**唯一权威** —— 两者不冲突,前者只是提前告知。

## 5. 三态:加载 / 空 / 错误(§4)

判据逐字照 §4:**加载 = 数据 `undefined` / 真空 = 数据 `[]` / 错误 = 就地呈现并给重试**。
三态**互斥**,数据到达前**绝不显示「无历史」**。

### 5.1 加载中(数据为 `undefined`)

- **左列**:用 `Skeleton` 填 4 行**与真行同尺寸、同类名**(`.fh-file-row` /
  `.fh-file-name`),整块 `role="status"` + `aria-label="正在读取文件历史"` ——
  逐字照 `TASK_SKELETON_*` / `GUIDE_SKELETON_*` 的既有手法(数据到达时是
  「同一片区域被填上」,不是整块替换)。
- **右列**:`LoadingState`(既有组件)文本「正在读取文件历史…」。
- 骨架**不给动画**(不扫光):扫光是 §10.3 已登记的动画族,本方案零新增动画,
  `Skeleton` 现有实现也不含动画,维持现状即可。

### 5.2 真空(`files.length === 0`)

复用 `EmptyState`(既有组件),**文案原文**:

```
标题:还没有文件历史
说明:Agent 用写入 / 编辑工具改过文件之后，这里会留下每次改动前的版本，随时能退回去。
图标:IconHistory,size 22(与资料库 / 项目的空态图标同档)
```

- **不给 `action` 按钮**:资料库空态给「新建任务」是因为那里有「创建产物」这个动作;
  本页空态的下一步是「回会话里让 Agent 改一个文件」,它**不发生在这一页**。
  在这一页放一枚跳转按钮是「假入口」(点了还是离开本页),不如把话说清。
- 左列、右列**同时**显示这一块(单列布局下只有一份),不做「左空右空两处重复」。

### 5.3 错误(IPC 抛错)

复用 `ErrorState`(原因 + 「重试」),整块在 `.settings-body` 内呈现,左列不再渲染
(结构未就绪时不摆空槽,§4「错误态与『数据还没回来』在视觉上必须可区分」)。
`ErrorState` 的红色 1px 边框 + 8% 底是**全站唯一的就地错误语言**,不在本页另造。

### 5.4 选中文件的版本读取失败

清单已到、某一文件的 `versions:read` 抛错:**只把右列换成 `ErrorState`**,
左列保留(用户还能切去别的文件),`onRetry` 只重拉 `readFileHistory(key)` ——
失败范围与重试范围一致。

## 6. 边界情形的表达(汇总:一律不许静默)

| 契约字段 | 在哪说 | 原文 / 形态 | 颜色 |
| --- | --- | --- | --- |
| 清单 `truncated: true` | 左列区头下 | 「文件较多,这里只显示最近改动的 200 个。」 | `--text-secondary` |
| 文件 `exists: false` | 左列注脚行 + 右卡头 + 还原确认句 | 「文件已不在」/「文件已不在,还原会重新创建它。」 | `--text-secondary` |
| 文件 `skipped > 0` | 左列注脚行 + 时间轴上方说明行 | 「· N 次未记录」/「另有 N 次改动没有留下版本:文件超过 1 MiB,或不是文本文件。」 | `--text-secondary` |
| 版本 `broken: true` | 节点自身(第三行) | 「内容已不在,这一版不能还原」 | 节点 `opacity: .55` + 圆点空心 |
| 还原 `running` | 确认条位置 | 见 §4.4 表 | `--danger`(`ErrorState`) |
| 还原 `missing` | 确认条位置 | 见 §4.4 表 | `--danger` |

失败动作;危险色留给人**此刻按下的动作**。它靠**形态**(空心点 + 整行淡出)与
**文字**(「内容已不在」)独立成立(§7.6)。

## 7. 暗色主题

**本方案零暗色专属规则、零字面量颜色、零新 token。** 全部取值引用既有 token,
暗色块(`[data-theme="dark"]`)已有同名覆盖,`check:theme-tokens` 的
「同名 token 对 + 字面量逃逸」两项自动接管:

| 用到的 token | 暗色下从哪来 |
| --- | --- |
| `--bg`(内容卡底)、`--bg-raised`(选中行 / 确认条 / 代码头行)、`--bg-hover`(hover 底) | 暗色块已覆盖(`#1c1c1e` / `#26262a` / 7% 白),层次方向与亮色一致 |
| `--border`(卡片边、连接线、圆点常态)、`--text` / `--text-secondary` / `--text-faint` | 暗色块已覆盖 |
| `--ok` / `--danger`(仅用于 `+` / `−` 与就地错误) | 暗色块已覆盖 |
| `--dur-*` / `--ease-*` / `--radius-*` / `--space-*` / `--text-*` 档位类 | 不随主题变,只在 `:root` 定义 |

选中圆点的扩环用 `color-mix(in srgb, var(--text) 8%, transparent)` —— **与主题无关**
(`--text` 在暗色下是 92% 白,掺出来是极淡的亮环,方向正确);
`.trace-seg:hover` 与 `.diff-add` / `.diff-del` 已是同一写法,不是新机制。

暗色验证按 PRD 验收标准:**至少一张暗色截图**(`tests/e2e/file-history.mjs`)。

## 9. 纪律对照与登记事项

### 9.1 遵守的既有纪律(逐条)

| 纪律 | 本方案怎么落 |
| --- | --- |
| §2 档位纪律 | 零新档:间距只用 2/3/4/5/6,字号只用 meta/list,文字色只用三级 + ok/danger(仅 +/- 与就地错误),圆角只用 sm/md/full,时长只用 `--dur-fast` / `--dur-base` |
| §2.0 双块同构 | 零字面量色、零暗色专属规则;`check:theme-tokens` 自动覆盖 |
| §2.1 文字三级 | 主文 `--text`、元信息 `--text-secondary`、禁用 `--text-faint`;正常可读的注脚**不降两档** |
| §2.4 状态色只表状态 | 还原按钮**不用 danger**(可逆);`+` / `−` 沿用既有 `.tool-change` 口径(符号独立承担语义);「文件已不在」不染色 |
| §2.6 正文基准 | 预览体 `line-height: 1.6` |
| §3 四态 | 文件行、时间轴节点均 normal/hover/active/disabled 齐全,过渡统一 `--dur-fast` + `--ease-standard` |
| §3.1 按压缩放 | 行类元素 active 叠 `scale(.98)` |
| §3.4 禁用 | `broken` 节点只改 `opacity`,不置灰背景 |
| §3.7 / §3.9 盒子预算 | **全页只有一个内容卡**;左边无边框、确认条无边框、预览是内框工具 |
| §4 三态 | 加载(左骨架 + 右 LoadingState)/ 空(EmptyState 原文)/ 错误(ErrorState)互斥可辨;数据未到不显示「无历史」 |
| §5.1 布局属性不过渡 | 连接线是 1px 静态线,无 `width`/`height` 过渡 |
| §5.8 进出场不对称 | 本页无进出场动画(确认态就地换内容,与首页清单三态换槽同手法) |
| §6 禁止清单 | 无原生 `<select>`(窄窗用 `.pop-menu`);无硬编码颜色;不新造对话框 / 代码框(复用 `.code-block`) |
| §7.1 焦点指示 | 所有可点元素是 `button`,天然获全局焦点环;焦点环不得抹掉 |
| §7.6 状态不只靠颜色 | 「选中」= 行底 + 圆点实心/放大双通道;「broken」= 空心点 + 文字 + 淡出;`+` / `−` 有符号 |
| §7.9 hover 浮现 | 本页无 hover 浮现的行内操作钮(整卡 / 整行可点),不涉此条 |
| renderer spec 一 | 不改渲染层产物命名,不做大规模重排(新增 CSS 追加在文件末尾附近) |

### 9.2 需要登记 / 更新的项

**无。** 逐条说明为什么:

1. **不新增 token 档位** —— 间距 / 字号 / 文字色 / 圆角 / 阴影 / 时长全部落在 §2 现有
   档位内;节点圆点直径(10/12px)、刻度槽宽(20px)、面板限高(如 `min(36vh,300px)`)
   是**组件尺寸**,与 `.tool-dot`(6px)、`.proj-dot-inline`(8px)、
   `.code-block pre`(`max-height: 60vh`)同性质,**不是档位**,不进 §2 表;
   `.settings-body[data-file-history]` 的 `max-width: none` 是**页壳覆盖**,
   逐字照 `[data-projects]` / `[data-compare]` 的既有先例。
2. **不新增动画** —— 时间轴无入场、连接线无生长、确认条无滑入、骨架无扫光。
   因此**不进 §10.3 登记,也无需加入 §10.3.1 关停清单**。
   (若实现阶段临时决定给「切换文件时的时间轴」加入场淡入,那才需要按 §10.3 登记,
   并在 §10.3.1 第 ③ 组加一行、终态停在基础态即「正常可见」——
   **但本方案的选择是不加**,理由见 §3.2。)
3. **不动 §5 受控例外表** —— 没有布局属性过渡,编号 ③④⑤ 一条不碰。
4. **颜色字面量** —— 零。所有颜色走 token;`color-mix(in srgb, var(--text) X%, transparent)`
   是 `app.css` 既有写法(`.trace-seg:hover`),不触发 §2.0 的字面量检查。

### 9.3 需要**别人**配合的两处(不是设计规范登记,是跨文件同步)

1. **审计面板的类别标签**(design.md §3.5 已点明):`app.js` 约 65198 行有一份手工
   同步的 `AUDIT_CATEGORY_LABELS` / `AUDIT_OUTCOME_LABELS` / `AUDIT_CATEGORIES` 副本,
   **daemon 与渲染层两处都要改**,否则面板按白名单过滤时会把这条静默丢掉。
   已核对:加入 `file` 后类别共 **5 个**(`command` / `sandbox` / `runtime` / `audit` /
   `file`),**未超过 §10.3「分类色板只有 6 槽」的上限**,不需要任何配色登记。
2. **新侧栏图标 `IconHistory`** —— 一枚本地内联 SVG,与 `IconChart` / `IconStats`
   同为一行式定义,不是新组件、不是新 token。

## 10. 备选与取舍

| 被否掉的备选 | 否掉的理由 |
| --- | --- |
| **左列也做成一块 `--bg-raised` 次级面**(与右卡并列两块面) | §3.9:一页只该有一个视觉重点。两块并排面板会让整页像「没做完」——每个盒子都更轻。左列是**索引**(导航),让它退成无边框的行,右卡才立得住。 |
| **时间轴倒序(最新在最上)** | 本项目的时间语言是**顺时序自上而下**(工作轨迹条、诊断页 `.timeline` 皆然);`design.md` §2 也明确数组旧→新「与渲染方向一致」。渲染层二次倒序会让「数组序 ≠ 渲染序」,埋下维护坑。改成**默认选中最新一版并自动滚到它**,在不破坏方向的前提下达到「落地即站在最新处」的目标。 |
| **每个节点是一枚 `.trace-seg` 那种横向 chip** | chip 流表现不了「时间方向」与「当前选中」,而正是这两件事构成本功能。且 chip 的静态底(`--bg-chip`)与 hover 加深规则是为「可点的分段」设计的,套到时间轴会与行选中态(`--bg-raised`)打架。 |
| **还原用模态二次确认** | 模态背板会**遮住用户正要核对的目标版本正文**。这个确认的价值就是「看着目标再决定」(§4.2)。就地确认条把三件事说在一句话里且不遮挡预览,还保持了上下文连续。 |
| **在时间轴末尾追加一个「当前内容」节点** | 契约里没有「当前内容」这个版本(`versions:read` 只按 id 返回历史版正文,design.md §3.1),渲染层无法凭空造一条。用**一行文字说明**替代它的语义(§3.1),将来契约真提供当前内容时再考虑升格。 |
| **左列与右卡各自独立滚动(master-detail 双滚动)** | 双滚动条 + 粘性定位在本项目既有的 `.settings-body` 单一滚动容器里会引入新的滚动语义(§7.8 要求与既有口径一致)。本方案让**整页一个滚动容器**,仅时间轴与预览体因天然限高而各自滚动 —— 滚动层级清楚,也就不需要粘性定位。 |

## 11. 给实现者的验收口径

下面 6 条都可由 e2e 断言或人工截图核对(与 PRD「验收标准」的 e2e 一项对齐):

1. **全页只有一个带边框的盒子。** 在「文件历史」页上统计「有 `border` 且底色为
   `--bg`」的顶层容器,结果**恰好 1 个**(卡内的 `.code-block` 这类内框工具除外)。
   配套断言:`.fh-index .fh-file-row` 的 `border-width` 为 `0`。
2. **时间轴节点四态与选中态可断。** 节点 normal 时底色透明;hover 后为 `--bg-hover`;
   点选后**即** `.fh-node` 命中 `--bg-raised` 且 `.fh-node-dot` 为实心(`--text`);
   disabled 节点(`broken`)`opacity < 1`、`cursor: default`、点击无变化。
3. **每个节点同时含「时间 + 那一段 +X −Y + 来源」。** 截取节点文本断言:能同时找到
   绝对时间(`MM-DD HH:mm`)、`+<n>` 与 `−<n>` 两个等宽数字、以及来源会话标题;
   **最新一版**的节点不显示 `+X −Y` 而显示「这是最近一次改动之前的样子」。
4. **还原是二次确认,且确认文案说全三件事。** 点「还原到此版本」后,**不出现**
   `role="dialog"` 的模态;出现 `.fh-confirm`,其文本同时包含文件名、目标时间
   (`MM-DD HH:mm`)与「先存成一条新版本」这句原话;点「取消」后确认条消失且磁盘文件
   **未变**。
5. **边界情形都不静默。** 逐项构造:①某文件 `exists:false` → 左列与卡头都能看到
   「文件已不在」;②`skipped>0` → 左列有「N 次未记录」且卡内有原因说明行;
   ③`truncated` → 左列顶部出现「只显示最近改动的 200 个」;
   ④`broken` 版 → 节点文案含「内容已不在」且该节点不可激活。
6. **三态互斥 + 暗色可读。** 数据未到时**不出现**「还没有文件历史」(加载态只出骨架 +
   `role="status"`);空态文案逐字等于 §5.2 的标题与说明;错误态出现重试按钮。
   截图验收:浅色一张(基准)、**暗色至少一张**,核对卡片边、连接线、选中圆点在暗色下
   都仍可辨(不出现亮片、不出现「选中与未选中同色」)。

## 附:与 PRD / design.md 需要对齐或存疑的点(不硬做,交评审裁决)

1. **一处需要产品裁决、而非实现的冲突**:PRD 期望 §2 描述时间轴是「时间 + **相对上一版**
   的行数变化 + 来源会话与工具」;而 `design.md` §3.1 契约里 `added` / `removed` 是
   「**这次改动相对它的**增删行数」,即**替换这一版的那次改动**的 diff
   (本任务书也按此表述为「这一版之后被多大的改动替换」)。两者方向相反。
   本方案按 **design.md**(契约权威)实现:节点显示「被 +X −Y 的改动替换」;
   建议同步修订 `prd.md` 那句,否则实现者会照 PRD 写成另一件事。
2. **最新一版没有 `+X −Y`**:按契约,最新一版之后没有**已记录**的改动,所以它显示
   「这是最近一次改动之前的样子」而非数字。若产品希望它显示「相对当前磁盘内容」的差异,
   需要契约新增字段(本轮不做)。
3. **不需要任何 token / 动画登记** —— 若评审认为时间轴需要一段入场动画,那是**本方案
   主动否掉**的(§3.2):请先改设计意图,再按 §10.3 登记并进 §10.3.1 第 ③ 组关停清单,
   终态停在基础态(无动画时即「正常可见」)。
