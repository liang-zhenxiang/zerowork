# PRD：诊断健康评分环 + 首页场景 Bento 卡

- Issue：#268（剩余两项）
- 分支：`feat/diagnostics-health-bento`
- 日期：2026-11-08

## 背景

Issue #268 原文列了十项视觉功能，前十二轮已完成七项，本 Issue 已收窄为剩余两项。两项的共同点是：
**信息已经存在，但需要用户自己逐项读**——诊断页是一列纯文本状态，首页场景是四个小胶囊 + 一个下钻菜单。

## 期望

### 一、诊断健康评分环

把「诊断」页顶部从纯文本状态升级为一个可扫读的评分环：

- 0–100 分，分项各 25 分，四项：
  1. **模型可用**：`settingsSnapshot()` + 现有 `judgeModelReadiness()`
  2. **内置运行时**：`runtimesSnapshot()`
  3. **最近任务成功率**：`statsSnapshot()` 最近 20 次已结束任务
  4. **全局快捷键**：`globalShortcutStatus()`
- 环旁列出四个分项：名称、状态（正常 / 扣分 / 无法判断）、得分
- 环下方给**一句**改进建议，优先指向扣分最多的那一项；全绿时说明「没有需要处理的项」
- 无法读取某一项时如实显示「无法判断」并按 0 计，**不得静默跳过**（项目原则：宁可拒绝，也不静默降级）

### 二、首页场景 Bento 卡

- 首页现有的能力胶囊行改为**不等宽 Bento 网格**，呈现 `resources/welcome/chips.json` 的**全部 8 个胶囊**（work 4 + code 4）
- 每张卡：图标、名称、一句描述、模板数量；点击与现有胶囊一致——打开下钻面板，列出该场景的模板 / 提示词
- 跨场景点击也要可用：面板内容按胶囊自身的数据计算，不依赖当前场景过滤
- 不改变首页的垂直节奏（`.capability-row` 底边距仍为 24px），`gui-smoke` 的节奏断言必须继续通过
