# PRD：OOXML run 级修补引擎（#479）

## 背景

ADR-0001 已证明：只替换一个 `w:t` 内的文字时，OOXML 修补只改目标部件，其余条目逐字节一致。本 Issue 把实验脚本做成**生产引擎**，并提供 Node 封装；工具接线与 UI 在 #481/#482，不在本轮。

## 目标

1. `resources/docx-engine/patch_docx.py`（python3 标准库）：
   - 参数：`--in`、`--out`、`--part`（默认 `word/document.xml`）、`--find`、`--replace`；
   - 仅接受：目标文本完整落在一个 `w:t` 内、在该部件内唯一命中；替换不改变 run 边界；
   - 保留 zip 条目顺序、时间戳、压缩方式、权限位；临时文件 + `os.replace` 原子替换；
   - 写后自检：重新打开、XML 合法、目标文本已替换、**其余条目逐字节一致**；失败不产出/不覆盖原文件；
   - 成功输出一行 JSON（`ok:true`、改动部件、条目数、字节变化、`otherEntriesUnchanged:true`）；
     失败退出码非零 + stderr JSON（`ok:false, code, error`）。
2. `src/main/daemon/docx-patch.js`：调用封装（python 路径、引擎目录、超时、输出上限），
   解析契约、把错误映射为可读错误；不新增依赖。
3. 单测：契约解析、超时/截断、错误码映射；用 `tests/fixtures/docx-revision/` 的夹具真跑引擎
   （python3 标准库，无需 venv），验证成功、跨 run 拒绝、找不到/多处命中拒绝、其余条目不变。

## 非目标

- 不注册工具（#481）、不改工作台（#482）、不做结构编辑/跨 run（v1 明确拒绝）。
- 不引入 npm 依赖；不改现有 docx 生成/提取链。

## 红线

- `resources/**` **不参与**本项目 lint / 格式化 / 测试（红线 5）：新脚本自带说明，不挂到本项目工具链。
- 中文内容不得有 U+FFFD。
- 失败必须拒绝且不破坏原文件（宁可拒绝，不静默降级）。

## 验收

- [ ] 夹具 A/B 的正文、表格单元格、页眉替换成功；除目标条目外逐字节一致
- [ ] 跨 run / 找不到 / 多处命中 → 非零退出、不产出文件、错误 JSON 可读
- [ ] 目标不存在、非法 zip、缺 `[Content_Types].xml` → 明确错误
- [ ] 写后自检失败时原文件不变（模拟/注入）
- [ ] Node 封装：成功解析、超时/截断/非零退出映射为可诊断错误
- [ ] 单测全绿，且不依赖 venv（系统 python3 即可）
