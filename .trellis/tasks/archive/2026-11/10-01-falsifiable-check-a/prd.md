# 让 command-exec 的 check A 不为正确行为判红

## 问题（Issue #58）

这是「无法证伪 / 为正确行为判红」这条毛病在 `command-exec.mjs` 上的**第三处**
（B1 在 #56 修、C 在 #59 修）。

A（`沙箱不可用时命令被拒绝`）断言「审计里有 blocked 记录」。但若模型在该轮**自带
`sandbox_permissions` 参数**申请提权：

- 受限档 → 完全访问是**严格变宽**，属于**合法**提权
- 测试的审批处理器一律 allow → 档位变成完全访问
- 直通 spawn → `powershell.exe ENOENT`
- **审计里没有任何 blocked 记录** → **A 判红，而产品行为完全正确**

## 可达性有实测支撑

跑这个文件时，模型**两次**在 C 的第一轮里自作主张带了提权参数 ——
输出里能看到审计多出一条「用户批准本次提权到「danger-full-access」」。

A 用的是等价的提示词（**没有**「不要传提权参数」那句），只是那 13 次运行里没撞上。

## Requirements

- R1 把 C 那套手法搬到 A（**#59 里已经做出来了**）：
  - **收窄提示词** —— 明确不要传提权参数
  - **证据不是要找的那条就再催一次**（而不是等到超时）
- R2 断言落在「**沙箱拒绝**」这个可观察副作用上，而不是「审计里有没有 blocked」
- R3 **反向验证**：让模型带提权参数跑一轮，A **不应该**判红
- R4 不得削弱其他断言

## 可复用的现成资产

`tests/e2e/command-exec.mjs` 的**文件头**已有一张判别表（#59 里做的），
区分「沙箱拒绝」与「powershell 不存在」：

| | 沙箱拒绝 | powershell 不存在 |
| --- | --- | --- |
| 卡片 `outcome` | `blocked` | `error` |
| 卡片正文 | `本机的命令沙箱不可用` | `无法启动 powershell.exe` |
| 审计 detail | 以 `沙箱不可用，命令未执行` 开头 | **不写** |

A 直接用同一套即可。
