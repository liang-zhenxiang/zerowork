# PRD：docx 保真写回路径评估（#460）

## 背景

修订模式目前只支持 Markdown / 文本，但办公用户真实文档大多是 docx。必须先说清：docx 能不能保真写回、三条路径各会丢什么，再决定 v1 是否支持；否则「为什么 Word 不能修订」会反复被问。

## 目标

1. 对比三条路径：OOXML 包内段落/run 级修补、python-docx 全量重建、Markdown 中继再生成。
2. 用两个真实感夹具（含样式 / 编号 / 超链接；以及表格 / 页眉页脚）验证保真与丢失清单。
3. 给出明确结论：v1 是否支持 docx；不支持时用户看到什么、后续如何拆。
4. 结论落盘为 ADR，带可复现命令，不改应用代码。

## 验收

- [ ] `docs/adr/ADR-0001-docx-revision.md`：对比表、实验证据、决策与理由、否决方案
- [ ] 夹具与生成/验证脚本（不新增依赖，python3 或 node stdlib）
- [ ] 至少两条路径实际跑过，输出「保住了什么 / 丢了什么」
- [ ] 决策明确：支持或不支持，以及不支持时的用户提示与后续 Issue
- [ ] 与项目红线一致：宁可拒绝，不静默降级
