# PRD：hooks 生命周期事件（SessionStart / UserPromptSubmit / Stop）

- Issue：#373（v0.22.0）
- 分支：`feat/hooks-lifecycle-events`
- 日期：2026-11-12
- 前序：确定性 hooks MVP（#368 → PR #371，已随 v0.21.0 发布）

## 背景

MVP 只有两个**可阻断的工具事件**：`PreToolUse` / `PostToolUse`。用户可以在「工具调用」这一层
建立确定性边界，但无法在**会话与消息的生命周期**上「总是做某件事」：

- 会话开始时预热的脚本（拉取依赖、检查环境、写一条本地日志）无处挂载；
- 每条用户消息提交前的记录 / 分类 / 提醒无处挂载；
- 一轮真正结束后的收尾（跑测试、汇总、通知）无处挂载。

这三个事件在竞品里是最常用的形态（Claude Code / Cursor 的生命周期事件大多不可阻断）。
它们不改变安全边界，价值在**确定性发生**与**可审计**。

## 范围（MVP）

### 事件

| 事件 | pi 事件（已核实） | 触发时机 | 可阻断 |
| --- | --- | --- | --- |
| `SessionStart` | `session_start`（`reason: startup/reload/new/resume/fork`） | 会话装载完成、资源发现之后 | 否 |
| `UserPromptSubmit` | `before_agent_start` 且 `messageType === "user"` | 用户提交消息、本轮开始之前 | 否 |
| `Stop` | `agent_settled`（`aborted: boolean`） | 一轮彻底结束（无自动重试 / 压缩 / 排队续跑） | 否 |

**不做上下文注入**：hook 的 stdout 不进入提示词、不改变消息。理由见 design §二。
`SessionStart` 在 pi 里也没有可返回的注入结果，做了只会让两个事件的行为不一致。

### 配置与合并

- 沿用现有形状 `{ id, event, matcher?, command, timeoutMs? }` 与来源合并（用户级 + 已信任的工作区级）
- `matcher` 对这三个事件**只能**缺省 / `""` / `"*"`；写别的工具名在保存时就报错
  （没有工具名可比，接受它只会得到一条永不生效的配置）
- 工作区级仍默认不执行，按绝对路径信任；worktree 按源仓库根
- 配置损坏：工具事件仍 fail-closed；生命周期事件**不运行、不刷审计**（工具已被拦下，
  逐条消息重复记同一条错误没有诊断价值 —— 理由写进 design）

### 执行语义

- 顺序执行同一事件的 hooks；不阻断，全部跑完
- 超时沿用 1000–30000ms、缺省 5000ms；超时杀进程组 / 进程树
- 退出码 `0` 记 `allowed`；`2` 与其他非零、超时、启动失败**一律记 `failed`**，
  文案写「拒绝（未阻断）」或「失败（未阻断）」—— 不能让人以为会话/消息真的被拦下了
- hook 自身异常只写审计，不影响会话；pi 的事件派发本身也会吞 handler 异常，但仍自行兜底
- `UserPromptSubmit` 是**在用户等待路径上**的：最坏延迟 = 命中条数 × 超时，UI 必须写明

### 审计与可见性

- 每次运行写 `hook` 审计：事件、hook id、耗时、退出码摘要（不写命令原文与提示词正文）
- 设置页 Hooks 分组新增「最近运行」：从审计读最近 5 条，显示时间 / 事件 / 结论
- 设置页事件下拉出现三个新选项；选中生命周期事件时 matcher 输入框禁用并说明「该事件没有工具名」
- 试运行沿用「只认已保存 id」，按事件生成示例载荷；弹窗对非阻断事件不得显示「按 fail-closed 阻止」

### 装配点

与工具事件相同的三处：主会话、定时任务 / 自动会话、子代理 / 团队成员，使用同一个 hooks root。
子代理也会触发这三个事件（一致性优先于「少起进程」），开销写进文档。

## 验收

- [ ] 三个事件都能在设置页配置、保存、读回、试运行
- [ ] `SessionStart` 在会话创建时运行一次；`UserPromptSubmit` 每条用户消息运行一次；
      `Stop` 在无重试/压缩的结束点运行一次
- [ ] 任一 hook 失败 / 超时 / exit 2 都**不改变会话结果**，只留 `failed` 审计
- [ ] 生命周期事件配了工具名 matcher 在保存时被拒绝并给出原因
- [ ] 主会话、自动会话、子代理三处装配点都生效（至少单测覆盖工厂被三处复用）
- [ ] 设置页「最近运行」能显示这三类事件的结论
- [ ] 单测（事件表 / matcher 校验 / 载荷 / 扩展工厂 / 非阻断）、daemon 集成（真实子进程）、GUI（下拉 + 最近运行 + 截图）
- [ ] `SECURITY.md` 补三个事件与「不做上下文注入」的决定；CHANGELOG 记「新增」
- [ ] `lint:all`、`npm test`、`npm run test:gui` 全绿

## 不在本轮

- 上下文注入 / 自定义消息注入
- `agent_start`、`turn_start`、`message_end` 等更细粒度事件
- hook 市场、hook 分组、按项目覆盖

## 硬约束

- 零新依赖；daemon 不 import electron
- 非阻断事件**永远不能**改变工具结果、消息内容或会话结论（安全与可预测性）
- 不降低现有 hooks 的默认安全姿态（工作区默认不执行、fail-closed）
