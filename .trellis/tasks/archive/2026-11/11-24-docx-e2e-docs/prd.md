# PRD：docx 修订端到端与文档（#483）

## 背景

#479–#482 把 docx 修订从「引擎」接到了「工作台」：OOXML 修补、二进制版本、`docx_replace`
工具、`kind:"docx"` 建议与接受路由。但现有的端到端证据只有两条：

- 工作台展示与接受：建议由 `buildDocxProposal` **直接落种子**，没有经过「模型调用工具」
  这条真实链路；
- 接受后的保真断言只解压 `word/document.xml` 看文字，没有逐条核对「样式 / 编号 /
  超链接 / 表格 / 页眉页脚 / 其余条目逐字节不变」。

用户文档也还停在旧说法：「docx / xlsx / pptx 的修订尚未支持」。

## 目标

1. 真实链路 e2e：开启修订模式 → mock 模型调用 `docx_replace` → 目标文件**未变**、
   建议出现在工作台；
2. 接受后用 `inspect_docx.py` 的清单断言：正文文字已变，样式使用、编号、超链接、
   表格单元格、页眉页脚、其余条目 sha256 均未变；
3. 跨 run 目标：关闭修订模式后由模型调用同一工具 → 工具以可读原因拒绝（`cross-run`），
   原文件字节不变，模型收到「请在 Word 里手改」的引导；
4. 截图：工作台 docx 建议亮 / 暗各一张（已有一张亮一张暗，补真实链路那张）；
5. 文档：`docs/USAGE.md` 的修订模式一节改写为 docx v1 的真实范围与边界；
6. CHANGELOG 已有 docx 条目，检查措辞与 USAGE 一致。

## 非目标

- 多段替换、页眉页脚替换路由、Word 原生修订痕迹（v1 拒绝，见 ADR-0001）；
- xlsx / pptx；
- 运行时的安装流程本身（未就绪时用例显式 SKIP 并在报告里可见）。

## 验收

- [ ] e2e 覆盖「模型工具调用 → 建议 → 文件未变」，不依赖直接种建议
- [ ] e2e 接受后 `inspect_docx.py` 保真清单通过（正文变、其余特征不变）
- [ ] e2e 跨 run 拒绝：文件字节不变，工具结果里含可读原因
- [ ] 亮 / 暗截图各一张，工作台 docx 区域无遮挡
- [ ] `docs/USAGE.md` 不再声称「docx 修订尚未支持」，写清 v1 范围、环境要求与不做的事
- [ ] `npm run test`、`lint:all`、`check:unicode`、`check:renderer-assets` 全绿
- [ ] 反向验证：去掉单 run 守卫 → 跨 run 用例红；去掉版本先行 → 还原用例红
