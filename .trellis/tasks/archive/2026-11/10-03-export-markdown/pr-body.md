## 这个 PR 做了什么

会话此前只能导出成**单文件 HTML**（pi 的 `exportToHtml`）：自包含、双击就能看，
但**带不走** —— 贴进 Notion / Obsidian / 文档 / PR 描述都需要 Markdown，
而从 HTML 页面上复制出来的是带样式的 DOM。

现在会话行的 ⋯ 菜单把「导出」拆成两项：

| 菜单项 | 产出 |
| --- | --- |
| **导出为 HTML**（原「导出」改名） | 单文件、带样式，适合发给别人照着看 |
| **导出为 Markdown**（新增） | 纯文本，贴进任何编辑器都能继续改 |

Markdown 版渲染的是**当前分支**：标题 + 元信息（导出时间 / 工作空间 / 模型 / 消息计数），
正文覆盖用户与助手文本、思考（引用块）、工具调用与结果、命令执行、压缩摘要、分支摘要、
模型切换、以及**这次交付的产物清单**。文件落在与 HTML 导出**同一个** `exports/` 目录。

## 关键决策（完整版在 `.trellis/tasks/10-03-export-markdown/design.md`）

| 决策 | 理由 |
| --- | --- |
| 渲染**逐类对齐 pi 的 HTML 导出** | 两边对「哪些条目算内容」的认识必须一致，否则同一件事在 HTML 里看得见、Markdown 里凭空消失。对照表写在 design.md |
| 条目取自**活宿主的 `getBranch()`** | 自己 open 会话文件的话，pi 把「最后一条条目」当叶子（`_buildIndex`）——**回退或分叉过的会话会导出另一条分支**，而这在界面上几乎无从察觉。集成用例里专门放了一条「不在当前分支上的条目」当守卫 |
| 超长内容**按界面同一口径截断**（4000 字符 + 标明原长度） | 界面看到什么、导出就该是什么；一份十万字符的工具日志灌进用户正要发出去的文档里比「少几百行日志」糟糕得多。要全文可以先导出 HTML |
| 图片**不内嵌 base64** | 一张截图能把文档从几十 KB 变成几 MB，且多数 Markdown 阅读器并不显示它 |
| 代码围栏**长度按内容算** | 工具输出里只要出现三个反引号，写死围栏就会把整篇文档从那里截断 —— 导出功能最典型的「命令成功、打开是烂的」事故 |
| 技能调用只留一行、不搬注入的指令 | 那是应用的管道，不是用户写的话；Markdown 里没有「折起来」这回事 |
| 空会话**报错**而不是写一篇空文档 | 与 HTML 导出同一句「该会话还没有内容可导出」 |

## 独立评审轮（子 agent 审查 → 逐条处置）

实现完后请了一个独立上下文的审查者**只读**审查（它可以实跑单元与集成用例）。发现的问题已全部处置：

| 发现 | 处置 |
| --- | --- |
| **工具入参没截断**：`write` / `edit` 的 `arguments` 里装的是整个文件正文，一条调用就能把导出撑到几 MB（实测 200 KB 入参 → 200,224 字符文档）—— 只截结果不截入参，等于「与界面同口径」只兑现了一半 | 结果与入参现在走**同一个** `clampedBlock()`；截断后按纯文本渲染（内容已不是合法 JSON）；补了 200 KB `write` 的断言（现在文档 4,206 字符） |
| `ipc-functional` 新增那项的「跳过」写成裸 `return` → harness 记成 **PASS**（零断言的一行绿），而且它依赖的前提不成立（无模型时 pi 在 preflight 就抛错，不落 user message） | 改成**自给自足**：自己预置一条有内容的会话文件再导出，并断言文件里的用户 / 助手文本 |
| `hasExportableContent` 与渲染器**两处都不一致** | 判据改成**与渲染同源**（抽出 `renderSessionBlocks()`，空不空看渲染出来的段落），两个方向一起消掉 |
| 助手消息的块顺序与 HTML 导出不同（思考被一律挪到正文之后） | 改成按 content **原序**渲染 text / thinking、toolCall 收尾，与 HTML 的两遍结构一致，并补断言 |
| PRD / CHANGELOG 里的「产物面板」措辞不准（实际是 `shell.openPath` 交给系统默认程序） | 三处文档已改成准确说法 |
| 单元测试里 `md.length < long.length` 是弱断言 | 换成断言文档总长有上界 + 含截断标记 |
