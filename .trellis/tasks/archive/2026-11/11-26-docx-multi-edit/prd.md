# PRD：一次多处 docx 替换（#499）

## 背景

改一份文档常常是**多处**：同一措辞出现多次、几个段落各改一句。现在 `docx_replace` 每次只改一处，模型要反复调用、用户在工作台逐条接受；而 v1/v2 的「多处命中就拒绝」让「把这个词全文改掉」根本做不到 —— 这是用户最自然的请求。

**依赖**：#498（跨 run）先合并 —— 批量会放大多处命中与跨 run 的判定面。

## 目标

1. 工具支持一次提交多条替换：`edits: [{ find, replace }]`；每条**独立**做唯一命中校验。保留单条参数（`find` / `replace`）的兼容路径。
2. 建议结构升级为多条：`kind:"docx"` 携带 `edits` 数组（每条 `find` / `replace`）；列表报「N 处替换」。
3. 工作台逐条展示与勾选；**接受只应用勾选项**，未勾选按拒绝处理并在动作前提示；toast 报实际替换条数。
4. 过期判定仍按整份文件哈希：文件被改过 → 全部禁用。
5. **全有或全无**：任意一条应用失败（找不到 / 多条命中 / 格式冲突）→ 整次不写盘，错误指明第几条与原因。
6. 版本只备份一次、审计只记一条（含条数），不记正文；旧建议（单条）照常读取与应用。

## 非目标

- 正则 / 模糊匹配（仍逐字精确）。
- 跨段落的合并编辑（每条仍限一个段落内）。
- 上下文预览（#500）。

## 验收

- [ ] `docx_replace({path, edits:[{find,replace},{find,replace}]})` 生成一条含 2 条替换的建议；文件未变
- [ ] 工作台显示 2 条「替换前 / 替换后」，可分别勾选；接受只写勾选的
- [ ] 未勾选的条目按拒绝处理，界面在动作前提示
- [ ] 第二条若失败（如格式不同的跨 run），整次不写盘，错误说明是第 2 条
- [ ] 旧单条建议（无 `edits`）照常展示与接受
- [ ] 版本只有一条、审计只有一条，且包含替换条数
- [ ] 单测覆盖：参数归一化、建议结构、选择应用、全有或全无、兼容旧结构
- [ ] `npm test`、`lint:all`、`check:unicode` 全绿
