# PRD：计划书（Plan Book）

- 分支：`feat/plan-book`
- 日期：2026-11-10

## 背景

`plan` 模式已经存在（`resources/modes/plan.md`）：只读调研，模型输出一段「计划：1. 2. 3.」，
用户可以点消息下方的「执行计划」切回创作模式开始执行。

但它只是一条**普通消息**：

- 没有独立入口，翻两屏就找不到了；
- 不能改步骤、不能勾选完成、不能记录改过哪些版本；
- 不能只执行其中一步；
- 换会话回来，计划只存在于聊天记录里，不能被当作一件「东西」引用。

竞品调研（`.trellis/tasks/archive/2026-11/10-16-competitive-landscape-research`）的
GAP 分析把这件事列为「ZeroWork 缺失的最后一环」：Cursor / Warp / Claude Code / VS Code
都收敛到同两条机制——**执行前可编辑计划**、**从修订后的计划重跑而不是在混乱的对话里打补丁**；
Warp 还加了计划版本历史。对一个面向办公、强调可审计的本地 Agent，这比再造一个聊天装饰更贴合身份。

## 期望

### 一、计划成为一等产物

- 在 `plan` 模式完成一轮回答后，自动把计划文本捕获为当前会话的「计划书」
- 计划书持久化在本机（`<configDir>/plans/<sessionId>.json`），换会话、重启后仍在
- 结构化解析为标题 + 编号步骤；解析不出步骤时，整段作为一步（不丢内容）

### 二、可编辑、可版本化

- 计划书以右侧抽屉打开：标题、进度、步骤卡片
- 步骤可：编辑、勾选完成、上移/下移、删除、新增
- 每次保存（自动捕获或手动编辑）形成一个版本；最多保留 20 个
- 版本列表可查看快照，并与当前版本做**行级差异**；可恢复某个旧版本（恢复本身也形成新版本）

### 三、可执行

- 「执行全部」：沿用现有执行计划路径（切回创作模式并发送）
- 「执行这一步」：把该步骤填进输入框并聚焦，由用户确认后发送
- 「复制 Markdown」：把整份计划书复制为可粘贴的 Markdown

### 四、入口

- 会话页顶部工具条出现「计划书」按钮（带步骤数徽标）；无计划时在 `plan` 模式下也可见，
  提示「生成后在这里查看」
- 命令面板新增「打开计划书」
- 自动捕获后 toast 带「查看计划书」动作

## 验收标准

- [ ] `plan` 模式完成一轮后，计划书自动生成并可打开；再次生成新计划时形成新版本
- [ ] 步骤编辑/勾选/排序/删除/新增都能落盘，重启后读回一致
- [ ] 版本列表、差异视图、恢复旧版本可用
- [ ] 「执行这一步」把步骤文本填进输入框；「执行全部」走现有执行路径
- [ ] 浅色 / 暗色截图各一张；真实 Electron GUI 测试覆盖捕获、编辑、版本、执行
- [ ] 单元测试覆盖解析、步骤操作、版本上限、差异、存储校验
- [ ] `lint:all`、`npm test`、既有 GUI 用例全绿
- [ ] CHANGELOG `[Unreleased]`「新增」

## 硬约束

- 零新依赖；存储写在配置目录，不污染用户工作区
- 不新增 Electron 侧能力；daemon 只做校验与落盘
- 失败要可诊断：非法计划、写盘失败、读取失败都要有明确文案，不静默
- 样式只用设计 token；`app.css` 只追加
- 中文内容编辑后跑 `npm run check:unicode`
