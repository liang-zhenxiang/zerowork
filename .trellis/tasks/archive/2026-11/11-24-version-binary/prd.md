# PRD：二进制文件版本快照（#480）

## 背景

修订写回要求「版本先行」（#458），但 version-store 把前 8 KiB 含 NUL 的内容直接判为 binary 跳过 —— docx 写回前无法留旧版本，违背「可回退」。

## 目标

- 支持二进制版本（docx/zip）：单版上限内按字节保存，meta 标记 binary；
- list/read/restore 支持二进制：列表照常、还原按字节原子写回；
- 文本文件既有行为不变；超限仍如实 skipped；
- 文件历史 / 审阅台的文本 diff 对二进制保持现状（不新增预览）。

## 验收

- [ ] 二进制 version 往返：记录后可读回、可还原，字节一致
- [ ] 文本 version 往返不变（回归）
- [ ] 超过二进制上限 → skipped，不假装记录
- [ ] 还原原子：失败不破坏当前文件
- [ ] 单测覆盖二进制/文本共存、坏 meta、上限、还原
