# PRD：hooks 配置导出 / 导入（预检 + 按 id 合并）

- Issue：#387（v0.23.0）
- 分支：`feat/hooks-import-export`
- 日期：2026-11-13

## 背景

hooks 是用户自己维护的一组本地脚本，换机器或分享给同事只能手抄 JSON：

- 设置页能编辑、能试运行，但没有导入 / 导出；
- `preferences.json` 是内部存储，直接改它容易写坏，也绕过了写侧校验；
- 工作区 hooks 随项目走，用户级 hooks 搬不过去，而两层往往配套使用。

快捷短语已有「导出 JSON / 导入恢复」的先例（`QuickChipsEditor`），交互可复用。

## 需求

### 导出

- 设置页 Hooks 分组新增「导出」
- 导出**用户级** hooks，形状 `{ version: 1, hooks: [...] }`（与配置文件同构）
- **不含** `trustedWorkspaceHooks`（本机绝对路径，带出去既不安全也无意义）
- 文件名 `zerowork-hooks.json`

### 导入

- 新增「导入」：选择 `.json` 文件 → **先预览**（条数、每条的事件 / id / 命令首行）
- 预览阶段逐条校验，非法条目必须指出**第几条、为什么**；存在任何非法条目时**不允许导入**
  （不静默丢弃）
- 确认后与现有用户级 hooks **按 id 合并**：同 id 覆盖（保留原位置），新 id 追加；不整份替换
- 写入沿用 `assertHookConfig`（写进去的必须能原样读回来）
- 导入只落盘，**不执行**任何命令
- 文件上限 128KB；非 JSON / 结构错误给可诊断错误

## 验收

- [ ] 导出文件形状正确，且不含信任列表
- [ ] 导入预览显示条数与逐条摘要；非法条目指出 index 与原因，且阻止导入
- [ ] 合并语义：同 id 覆盖原位置、新 id 追加、其余保留
- [ ] 导入成功后列表与 `preferences.json` 一致；刷新后仍在
- [ ] 单测（导出形状 / 合并 / 文本解析：非法 JSON、超限、重复 id）
- [ ] GUI（真实启动：导出 → 清空 → 导入回读；非法文件预览报错；浅/暗截图）
- [ ] `SECURITY.md` 补一句「导出文件含本机命令、导入是不可信输入」
- [ ] `CHANGELOG.md` 记「新增」

## 不在本轮

- 工作区 hooks 的导出（它随项目走，文件本身就是分享格式）
- 导入时的冲突交互（逐条选择保留哪边）—— 本轮固定「同 id 覆盖」
- hooks 市场 / 模板库

## 硬约束

- 导入文件是不可信输入：整份校验通过才落盘，任何执行仍只能经用户显式「试运行」或真实事件
- 不新增依赖；daemon 不 import electron
