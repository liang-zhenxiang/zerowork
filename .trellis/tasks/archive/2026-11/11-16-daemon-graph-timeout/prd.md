# PRD：daemon-graph 重子进程用例显式超时

- Issue：#401
- 分支：`fix/daemon-graph-timeout`

## 背景

`tests/unit/daemon-graph.test.mjs` 的两条用例会真实起子进程跑
`tools/check-daemon-graph.mjs`（遍历 40+ 模块）。全量并行时 CPU 争抢，
它们会撞 vitest 默认的 5000ms：

- 2026-11-16 本机连跑 4 次：2 次红；失败时耗时 5.6s / 5.9s，其余 1309 条全绿
- 同文件里最重的一条（复制模块图 + 起 3 次子进程）**已经**显式设了 60s，
  说明「重子进程用例必须显式给超时」这件事已经被验证过一次，只是漏了两条

## 期望

- [ ] 给两条用例显式设置 timeout（20s；它们的正常耗时约 1s，留足负载余量）
- [ ] 不降低断言强度：仍然真实运行脚本、仍断言退出码与两行输出
- [ ] 注释写明「为什么需要显式超时」（默认 5s 在并行下会假红）
- [ ] 验证：全量连跑多次不再出现 5000ms 超时

## 不在本轮

- 不改 `check-daemon-graph.mjs` 的实现
- 不合并多次子进程调用（可选优化，收益不足以冒险改检查工具）
