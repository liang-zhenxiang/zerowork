# PRD：docx_replace 工具与修订模式接线（#481）

## 背景

#479 提供 OOXML 修补引擎、#480 提供二进制版本。但 AI 仍然没有在原文上改 docx 的入口：`docx_convert` 会重新生成并丢版式。本轮加受控工具，并接上修订模式。

## 目标

1. 新增工具 `docx_replace`：参数 `path` / `find` / `replace`；只接受工作区内 `.docx`，文件 ≤50 MiB；严格按引擎的拒绝面。
2. **修订模式开启**：不写盘，生成 `kind:"docx"` 的待审建议（路径、baseSha256、part、find/replace、来源会话），工具回执说明「已存为建议」。
3. **修订模式关闭**：直接写回，顺序固定：哈希守卫 → `recordBinaryVersion` 留旧版 → 引擎原子修补（写后自检）→ 审计 `file/allowed`；任一步失败不改原文件。
4. 权限：把 `docx_replace` 加入权限门的 MUTATING 集合（按 `path` 判定），只读档必须拒绝；craft 模式白名单加入工具名。
5. Proposal 模型扩展：`kind:"docx"` 的建议可 list/read；旧的文本建议不受影响。
6. 单元测试覆盖拒绝面、建议生成、直接写回、版本记录、审计、路径/大小/扩展名。

## 非目标

- 工作台展示/接受（#482）、端到端（#483）。
- 跨 run、结构编辑、页眉页脚路由；v1 只做正文 `word/document.xml`。
- 不改引擎脚本（#479）。

## 验收

- [ ] 修订模式开：文件字节不变、建议可读、工具回执带建议 id；不启动 Python 运行时
- [ ] 修订模式关：文件被替换、其余部件不变、版本可读回、审计有记录
- [ ] 非工作区 / 非 docx / 过大 / 跨 run / 多命中 / 找不到 → 工具报可读错误，文件不变、无建议
- [ ] 只读权限档下工具被权限门拒绝
- [ ] 建议 `kind` 字段与旧文本建议兼容
