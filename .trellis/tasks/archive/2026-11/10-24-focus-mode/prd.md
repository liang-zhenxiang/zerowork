# PRD：专注模式 —— 把会话从「工具界面」切成「一页纸」

## 背景

ZeroWork 的主界面是为了**操作**设计的：左侧 15 个入口、标题栏、状态栏、输入卡常驻。
但办公场景里有一半时间是在**读**——读 agent 写完的方案、读一份长报告、反复对照上一轮的结论。
这时候那些操作入口全是噪声：

- 正文列宽跟着窗口走，大屏上一行 120+ 字符，读起来眼睛要来回扫；
- 侧栏和标题栏一直占着 260px，而读的时候一次也不会点；
- 输入卡固定在底部，长回答被挤在一个矮窗口里滚动。

现行界面没有「我在读，先别打扰我」这个状态。

## 竞品怎么做的（2026-10-24 检索）

| 产品 | 做法 | 我们取什么 |
| --- | --- | --- |
| iA Writer 的 Focus Mode（[官方说明](https://ia.net/writer/support/editor/focus-mode)） | 高亮当前句/段、变暗其余；三种档（句/段/打字机）；`⌘D` 切换；官方建议「全屏 + 暗色下效果最好」 | **取「切换是一个按键的事」与「暗色下收益最大」**。不取「高亮当前句」——那是给写作编辑器用的，我们的正文是 agent 的回答，没有"正在写的那一句" |
| Bear / Notion 的专注/全宽 | 隐藏侧栏与工具条，正文居中 | 取「收掉操作界面」 |
| Cursor 的 Zen Mode | 隐藏一切非编辑区 | 取「退出必须是显式的、低干扰的」 |

融合后的判断：**我们不缺"隐藏侧栏"，缺的是"阅读度量"**。所以这一版的重点不是把东西藏起来，
而是藏起来之后**正文本身变得更好读**：列宽收到 720、行高与段距加一档、字号加半档，
并且背景极光降到几乎不可见（它很好看，但读长文时是干扰）。

## 期望

- [ ] 一个显式入口：侧栏按钮（与「搜索或跳转」同款位置与样式）+ 快捷键 `⌘⇧F` / `Ctrl+Shift+F`
- [ ] 进入后：侧栏与标题栏收掉、正文列宽 720、字号与行高加一档、极光降到极淡
- [ ] 退出路径有两条：右下角低干扰胶囊按钮、`Esc`
- [ ] 状态**记忆**：重开应用仍是上次的状态；首屏不闪变（在渲染前设好 `data-focus`）
- [ ] 无障碍：入口按钮 `aria-pressed` 反映状态；退出胶囊有 `aria-label`；动效遵守 `prefers-reduced-motion`
- [ ] 单测覆盖纯逻辑（存储值解析、切换、DOM 属性写入）；GUI 测试断言**真实渲染**（侧栏不可见、列宽变化、Esc 可退、重载后保持）
- [ ] 截图归档到 `artifacts/focus-mode/`，两个主题各一张

## 不做什么

- 不做「高亮当前句/段」——我们的正文是回答，不是草稿
- 不改 agent 行为、不加新的模型调用
- 不做「专注时隐藏输入卡」——读完往往要接着问，输入卡要留在手边
- 不引入新的依赖或字体
