# PRD：修订工作台（#457）

## 背景

#456 生成待审建议、#458 提供写回通道，但用户还没有地方**看见并决定**这些建议。没有工作台，修订模式只会让写入「消失」。

## 目标

1. 审阅台新增「待修订」队列：按文件分组，显示每条建议的 hunk（增删行与上下文）。
2. 逐段勾选：默认全选，用户可取消某段；「接受选中」只写回勾选的段落。
3. **过期保护**：建议基准与当前文件不一致时，显示「原文已变化」，禁用接受并给重新生成指引。
4. 「拒绝整条」：丢弃建议、不修改文件；二次确认。
5. 空态、加载、错误态齐全；键盘与读屏可用。

## 非目标

- 不生成建议（#456）、不实现写回（#458）、不做 docx。
- 不改审阅台「已发生的变更」的既有行为。

## 验收标准

- [ ] 有建议时，审阅台默认进入「待修订」；无建议时保持现有「已变更」视图
- [ ] 队列按文件分组；每条显示文件名、来源会话、时间、段数与 +/− 行数
- [ ] 详情按段列出增删行与上下文；勾选状态可见、可键盘操作
- [ ] 「接受选中」调用 applyDocEdit，成功后文件变化、建议消失、toast 报段数与行数
- [ ] 过期建议：接受禁用、显示「原文已变化」与「重新生成」指引；拒绝仍可用
- [ ] 「拒绝整条」二次确认，确认后文件不变、建议消失
- [ ] 接受/拒绝后队列与计数即时刷新；读屏播报变化
- [ ] 空态分两种：没有建议 vs 建议都已处理
- [ ] e2e：生成建议 → 打开审阅台 → 取消一段 → 接受 → 文件只含选中段
