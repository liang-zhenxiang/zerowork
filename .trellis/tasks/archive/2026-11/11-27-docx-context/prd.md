# PRD：docx 建议的上下文预览（#500）

## 背景

工作台只显示「替换前 / 替换后」两块文字，用户不知道它来自文档的**哪一段**。长文档里同一句可能出现多次（虽然要求唯一命中），仍然需要确认位置。竞品的修订痕迹直接显示在文档正文里；我们不做 docx 渲染，但可以给出**足够判断的上下文**。

**依赖**：#498（跨 run）已完成 —— 上下文按段落拼接文本计算，跨 run 命中也能给出正确位置。

## 目标

1. 引擎新增**只读** `--inspect` 模式：不写文件，输出命中位置的上下文 —— 段落序号（第 N 个段落）、该段落窗口文本（命中前后各约 60 字，超出用省略号）、命中的偏移与长度、最近的**前置标题**（若有）。
2. 修订模式生成**单条** docx 建议时，若内置 Python 运行时**已就绪**，调用 inspect 补全上下文并存进建议；运行时未就绪或调用失败时**照常生成建议、只是没有上下文**（不阻塞、不报错）。
3. 工作台单条 docx 建议显示位置徽标（「第 N 段 · 标题：…」）与一行「…前文…**旧文字**…后文…」，旧文字高亮。
4. 无上下文（旧建议 / 多条建议 / 运行时未就绪）时如实说明「位置信息不可用」，**不编造**。
5. 纯新增字段：旧的 docx 建议（没有 context）照常展示与接受。

## 非目标

- 多条建议的逐条上下文（批量时引擎要跑 N 次、收益低；如实显示不可用）。
- 文档内嵌渲染 / 缩略图。
- 标题识别只做保守判定（`Heading*` 样式或 `outlineLvl`），不解析目录域。
