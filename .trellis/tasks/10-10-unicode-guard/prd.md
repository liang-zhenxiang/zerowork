# U+FFFD 扫描从人工步骤变成 lint 门禁（#180）

## 背景：它已经滑过去一次，而且不可逆

`AGENTS.md` 的「中文内容质量」一节写着「每次编辑中文后都要扫一遍 U+FFFD」，
但那段 `python3 -c` **是人工步骤** —— 不进 `npm run lint:all`，CI 也不跑。

2026-10-10 实测发现 main 上就躺着一处：

```css
/* running 段：边框亮出轮廓，与呼吸点互为[两个 U+FFFD]线索（组件挂 trace-seg running 类； */
```

`#177` 写坏的。三个事实决定了这件事必须补机制：

1. **不可逆**：提交里的字节是 `ef bf bd ef bf bd` —— 合法的 U+FFFD，不是坏字节。
   原文（「与呼吸点互为线索」）已经从 git 历史里消失，只能靠提交信息反推
2. **它会随包发出去**：CSS 注释被压缩器保留，实测 `out/renderer/assets/app.css`
   里就有这一行 —— `#179` 合并前打出的 beta 包是带着乱码发的
3. **同类事故不是第一次**：早前还有过「`eslint.config.mjs` 与 `src/main/index.js`
   的注释里混入替换字符」。每次都是人眼或人工扫描发现

结论：缺的不是认真，是**机制**。

## 期望

新增 `scripts/check-unicode.mjs`，接进 `npm run lint:all` 与 CI 的静态检查 job。

验收标准：

- [x] 扫描**被 git 跟踪**的文本文件，命中 U+FFFD 即失败，输出 `文件:行号` + 行内容
- [x] 排除三个**合法字面量**文件（`code-preview.js` / `workspace.js` / `app.js`）——
      它们是 vendored 解码器与 XML 字符集里的正当 U+FFFD
- [x] 默认排除 `resources/**`（本项目工具链的边界，红线 5），但提供 `--all` 开关：
      需要时能扫，而不是把这个能力藏起来
- [x] 跳过二进制文件（前 8000 字节含 NUL），与 `git grep -I` 同口径
- [x] 与 `check-line-endings.mjs` 同形：`git ls-files` 取清单、彩色输出、退出码、
      不在 git 仓库时给出显式的「跳过」而不是假装通过
- [x] 单测覆盖纯函数（豁免判定 / 逐行定位 / 二进制判定）
- [x] 反向验证：往源码里塞一个 U+FFFD → 门禁变红；删掉 → 变绿
- [x] `AGENTS.md` 与 `docs/MAINTAINER_GUIDE.md` 同步：人工扫描改为「已由 lint:all 覆盖」，
      但**保留**「修的时候按行号整行重写、不要 `replace` 单个替换字符」这条坑记录

## 设计决策

**为什么用 `git ls-files` 而不是 `rglob`。**
原来那段人工脚本用 `Path.rglob('*')` + 一张 `SKIP` 名单，那是「先跑遍磁盘再过滤」——
漏一项就会扫进 `out/`、`release/`、本地缓存，而扫到构建产物里的乱码是**假警报**。
`git ls-files` 的语义正是「仓库里该被检查的东西」，不需要维护 SKIP 名单。

**为什么默认排除 `resources/**`。**
红线 5 写明它不参与本项目的 lint / 格式化 / 测试 —— 反向也成立：将来某份 vendored
内容里出现正当的 U+FFFD，我们不希望门禁变红却无从修（那是第三方字节）。
人工脚本当年没有排除它，所以 `--all` 保留了同一份覆盖能力。

**为什么顺带能抓非法 UTF-8。**
读文件时用 `Buffer.toString('utf8')`，非法字节序列会被解成 U+FFFD —— 于是
「字面 U+FFFD」与「坏字节」这两种乱码一次抓完。二进制已先跳过，不会误报。

## 不做

- 不做「自动修复」。原文不可恢复，能做的只有指出位置让人重写整行
- 不把三个合法字面量文件改成转义写法（`\uFFFD`）—— 那是 vendored 代码，动了会破坏
  与上游的可比性，而且 `AGENTS.md` 已经写明「不要动」

## 难度

低。半天的量，纯静态检查，零行为风险。价值全在「以后不用靠人记得」。
