# 修掉模态背板：`--overlay` 从未生效过

## Goal

**直挂 `.app` 的模态**，背板当前不是半透明遮罩，而是一块**不透明的 `--bg` 面板**。
实测共 **3 处**（设置面板 / 命令面板 / 权限审批，见 `design.md` §1 的实测表）；
其余 6 处背板嵌套在各自视图里、父元素不是 `.app`，**一向是正确的**。
本任务把它修回遮罩，并逐个模态确认。

## 背景：已核实的事实

### 怎么发现的

做命令面板（#103）时截了一张面板打开的图，发现**面板后面什么都看不见** —— 主页被完全盖住。
量了一下 `.modal-backdrop` 的计算样式：

```
bg:     rgb(255, 255, 255)   ← 应该是 rgba(0, 0, 0, 0.4)
margin: 6px
radius: 10px
```

为判定「新引入的还是既有的」，用同样方法量**设置面板**（既有模态，与 #103 无关）：

```
设置面板的背板： {"parentCls":"app","isDirectChildOfApp":true,
                 "bg":"rgb(255,255,255)","margin":"6px","radius":"10px"}
命令面板的背板： {"parentCls":"app","isDirectChildOfApp":true,
                 "bg":"rgb(255,255,255)","margin":"6px","radius":"10px"}
```

**两者一模一样 —— 既有的全站缺陷。**

### 根因

`src/renderer/src/app.css:892`：

```css
.app > :not(.titlebar):not(.sidebar):not(button):not(.panel-slot):not(.panel-toggle-group):not(.toast-stack) {
	margin: var(--space-2);
	border-radius: var(--radius-md);
	background: var(--bg);
}
```

这条规则的本意（注释原文）是「`.app` 的直接子项里，除外壳之外的就是各视图页 ——
它们是嵌在灰底上的圆角白卡」。它用**排除法**，而**排除清单里没有 `.modal-backdrop`**。

特异性对比（决定胜负，与书写顺序无关）：

| 选择器 | 特异性 |
| --- | --- |
| `.app > :not(…)` × 6 | **(0, 6, 1)** |
| `.modal-backdrop`（`app.css:8221`） | (0, 1, 0) |

于是 `background: var(--bg)` 压过 `var(--overlay)`，`margin` 与 `border-radius` 一并对背板生效。
**`--overlay`（40% 黑）从定义至今从未在 `.modal-backdrop` 上生效过。**

### 为什么一直没人发现

结果**不刺眼**：一块铺满窗口、内缩 6px、带 10px 圆角的 `--bg` 面板，看起来像是
「界面被让干净了」，而不像坏掉。而且它把底下内容**完全盖住** ——
没有对比，就没有「本该是半透明」的直觉。

代价是真实的：模态与页面之间**失去视觉分层**，用户不知道自己「在哪里」；
`--overlay` 这个已经登记过的设计 token 成了**死代码**（读代码的人会以为背板是 40% 黑）。

### 影响面（已初步清点，**实现时仍要逐处确认**）

用 `.modal-backdrop` 的模态共 **8 处**（`app.js`）：

| 行 | 模态 |
| --- | --- |
| 61972 | 权限审批弹窗（`.permission-card`）—— **安全相关，用户要看清自己在批准什么** |
| 63862 | 添加模型卡（`.add-model-card`） |
| 64897 | 设置面板（`.settings-card`） |
| 65235 | MCP 表单卡（`.mcp-form-card`） |
| 65368 | MCP 编辑器卡（`.mcp-editor-card`） |
| 67207 | 确认框（未逐行核实，实现时确认） |
| 67376 | 自动化表单卡（`.auto-form-card`） |
| 67724 | 命令面板（#103，随本任务的修复一并转正） |

另有**两个同类遮罩类需要一并核实**（它们也用 `var(--overlay)`，但挂载位置不同，
**很可能不受影响 —— 不要想当然**）：

- `.ex-modal-mask`（`app.css:9115`，专家详情弹窗）
- `.image-preview-overlay`（`app.css:4117`，全屏看图；它的 72% 是登记过的 token 例外，**不要动**）

## Requirements

### R1 先清点，再动手

- 把复用 `.modal-backdrop` 的模态**列全**（上面的表是初稿，实现时逐行核实）
- 把 `.ex-modal-mask` / `.image-preview-overlay` 是否受同一规则影响**实测确认**
  （不要靠推理：在真实应用里量 `margin` 与 `background`）

### R2 修掉规则冲突

两种做法，**二选一并在 PR 里写明选择理由与另一条为什么不如它**：

- **A**：把 `.modal-backdrop` 加进 `.app > :not(…)` 的排除清单
- **B**：提高 `.modal-backdrop` 自身的特异性 / 拆出「视图页」专属类

判断要点：这条排除法规则**将来还会遇到新的浮层**（每加一个直挂 `.app` 的浮层都可能再踩），
所以「补一个名字」与「换一种写法」的长期代价不同。

### R3 修完的判据（要有证据，不是目测）

- `.modal-backdrop` 的计算样式：`background-color` 是 `rgba(0, 0, 0, 0.4)`、
  `margin: 0px`、`border-radius: 0px`
- **背景内容透出来**：模态打开时能看见被压暗的页面。
  截「开」「关」两张同主题图，用 `diffGrids` 断言差异落在遮罩应有的量级；
  并断言背板区域的平均亮度**介于**「原页面」与「全黑」之间（不是被完全盖住）

## 约束

- **不动 `.image-preview-overlay` 的 72%**（登记过的例外，语义是沉浸式看图不是模态背板）
- **不改 `.app > :not(…)` 里其它排除项的既有行为**（视图页仍应是灰底上的圆角白卡）
- 不为 lint 通过而大规模重排 `app.css`（`AGENTS.md` 红线 6）
- 不顺手改别的观感问题（如深色下的输入卡发光边是 **#106**，不要混进来）

## 难度

**小**（改动一两行），**但回归面是广的** —— 本任务的主要成本在「逐个模态确认」上，
不在改代码上。**不要因为改动小就跳过回归。**
