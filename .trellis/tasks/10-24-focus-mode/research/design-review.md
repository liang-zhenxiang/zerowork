# 「专注模式」设计评审

> **评审对象**：ZeroWork 专注模式（`app.css §13` + `docs/DESIGN.md §12` + `focus-mode-core.js`）
> **材料**：`artifacts/focus-mode/focus-{off-light,on-light,on-dark}.png`（真实 Electron，2560×1720，DPR 2 ⇒ 窗口 1280×860 CSS）
> **口径**：所有尺寸 = 截图 png 像素 ÷ 2；对比度按 WCAG 相对亮度算；每条结论都指到文件:行号或截图坐标。
> 放大裁切图在 `artifacts/focus-mode/review/`。

---

## 0. 先看四件事的答案

| 问题 | 结论 | 一句话依据 |
| --- | --- | --- |
| 「像在读一页纸」吗 | **不像**，现在是「工具界面减去侧栏」 | 页的边界、天地头、工具条全都没变；视觉重心仍在四张发光封面和渐变描边输入卡 |
| 720 + 15px 真的更好读吗 | **会话页成立，首页不成立**；文档的数字还差 30% | 会话 832→720 方向对；首页 900→720 让案例卡掉到 162px、标题出孤字；「一行 34–38 字」实际是 45–46 字 |
| 退出胶囊恰当吗 | **位置错、存在感也错** | 它占了「发送按钮的家」，却只有 3.45:1 / 3.80:1 —— 唯一鼠标出口最不显眼 |
| 浅色 / 暗色成立吗 | 浅色成立一半；**暗色不成立** | 暗色右栏实测 `#12152c`，等于满强度（45% 应到 `#0c1022`）；即便降到位，暗色 45% 也只剩 2~3 个色阶的温差 |

## 1. 证据与一处硬缺口

### 1.1 我量到了什么

| 量 | 普通模式 | 专注模式 | 差 |
| --- | --- | --- | --- |
| 侧栏宽度 | 264px（column 右缘 x=263） | 0 | −264 |
| 首页内容盒 | 852px（x 346–1196） | 672px（x 304–974） | −21% |
| 案例卡宽度 | 207px | **162px** | −22% |
| 视图卡外环 | 6px | 6px | 0 |
| 退出胶囊 | — | 94×30 @ (right 24, bottom 24) | — |

关键的一条：**`.titlebar` 那条 30px 带子在两张专注截图里都不存在**——整张图只有 png y=0–11（css 6px）那一圈外壳缝，css y=30 处没有第二条缝。所以 `.titlebar{opacity:.55}`（`app.css:14634`）作用在一个被视图卡整条盖住的元素上，没有可见对象。详见 P0-2。

### 1.2 硬缺口：没有一张会话页的截图

三张图全是**首页**。而「专注」真正发生的地方是会话页：15px 正文、720 列、玻璃头部、胶囊与 composer 的关系——这些一样都没被拍到。也就是说这一版可以做出一条绿得发亮的 e2e（`tests/e2e/focus-mode.mjs` 全过），但**没有任何人看见过它的阅读状态**。这是 P0，不是流程问题。

## 2. 四个必答问题的展开

### 2.1 「像在读一页纸」吗 —— 不像

三条具体原因，都能指到位置：

**(a) 页的边界不存在。** 视图卡仍是一张 `border-radius: var(--radius-md)` + 8px 外边距的浮卡（`app.css:1123` 那条 (0,7,1) 规则），会话页顶部仍是 `background: var(--glass-bg)` + `backdrop-filter` + `border-bottom: 1px solid var(--border)` 的通栏玻璃条（`.chat-header`，14406 附近，§13 没有覆盖它）。换句话说：**专注模式把导航拿掉之后，剩下的仍然是一个"应用窗口"，不是一张纸。** 页的四条边、页的留白、页眉的层级——一条都没动。

**(b) 视觉重心仍在「操作」，不在「读」。** 专注模式下首页最亮的东西是四张案例封面（teal 描边 + 径向光），第二亮的是输入卡的渐变发丝描边。一页纸的纸面上不该有发光按钮。裁切对比见 `review/case-titles-on-light.png`：四张卡挤成一排，封面被压到 16:9 的 162×91，卡片的光晕彼此叠在一起，形成一条断续的亮带——这正是阅读时最碍眼的东西。

**(c) 垂直节奏一模一样。** `.home-main` 的 `padding-bottom: 268px`（13942 起那段）在专注模式下没动，天头也没动。用户按下 ⌘⇧F 之后，页面的"高度感"没有任何变化，只有宽度变了 264px。人感知"换了一个语境"靠的是空间节奏，不是列宽。

**最小可信的「一页纸」（都很便宜，我建议进 P1）**：

```css
/* ① 会话页：页眉从"工具栏"降为"页标题" —— 卸掉玻璃与通栏横线 */
html[data-focus="on"] .chat-header {
	background: transparent;
	backdrop-filter: none;
	-webkit-backdrop-filter: none;
	border-bottom-color: transparent;
}
html[data-focus="on"] .chat-header .chat-title { color: var(--text-secondary); }

/* ② 输入卡退到背景里，写字时才回来（和胶囊用的是同一套"低干扰"逻辑） */
html[data-focus="on"] .chat-composer { opacity: .82; transition: opacity var(--dur-fast) var(--ease-standard); }
html[data-focus="on"] .chat-composer:hover,
html[data-focus="on"] .chat-composer:focus-within { opacity: 1; }
```

### 2.2 720 + 15px 在 1280 宽窗口下真的更好读吗

**会话页：方向对，但没走到位。首页：错。**

| 表面 | 普通 | 专注 | 15px 下一行 |
| --- | --- | --- | --- |
| 首页内容盒 | 852 | 672 | 672 ÷ 15 ≈ **45 字** |
| 案例卡标题 | 207 / 13px | 162 / 13px | ≈ **12 字** |
| 会话正文 | 832 − 24 = 808 | 720 − 24 = **696** | 696 ÷ 15 ≈ **46 字** |
| 会话正文（14px 时） | 808 ÷ 14 ≈ 58 字 | — | — |

- **会话页**：中英混排 15px 的舒适行长大约 30–40 字（450–600px）。832/14 ≈ 58 字确实偏宽，720/15 ≈ 46 字属于「略宽但可接受」。所以这个改动**是对的方向**，只是还差一档——如果真要「一页纸」，列宽应该在 600–640，而不是 720。
- **首页**：它是启动器，不需要行长。900→720 是在给一个不需要收的东西收，代价立刻显形：案例卡 207→162px，标题 13px 一行只能装 12 字，于是「《思考，快与慢》精读笔记卡」折成第二行只剩一个「卡」，「八十二亿之后：全球人口结构与趋势图志」折成「…人口结 / 构与趋势图志」（`review/case-titles-on-light.png`；普通模式下这四张标题全是单行）。**孤字行是排版事故，不是风格。**
- **文档的口径和实现对不上**：「一行 34–38 字」在 720/15 下是不可能的（那是 510–570px 的列宽）。要么改口径写「45 字上下」，要么把列宽真的收到 570——我会选改口径，570px 对中文来说偏窄到病态。

### 2.3 退出胶囊

**位置**：右下角 (right 24, bottom 24)，94×30。这个角是**发送按钮的家**——`.chat-composer` 的下内边距 16px、发送按钮 32px 见方。1280 窗口下两者不打架，但项目最小窗宽 900 时：composer 右内缘 ≈ x 786，胶囊左缘 x 782，垂直方向 806–836 正好压在发送按钮的上沿——约 4×24px 的擦边。阅读时你的手会往右下角去按回车/发送，退出按钮住在同一个格子里。

**存在感**：实测浅色 3.45:1、暗色 3.80:1（12px 文本需要 4.5:1）。它太隐蔽了，而它是**唯一的鼠标出口**——键盘出口 Esc 在输入框里被刻意豁免（§12.1 的合理设计），所以正在打字的人只剩这个胶囊可以点。这不叫"克制"，叫"读不出"。

放大证据：`review/exit-pill-on-light-3x.png`、`review/exit-pill-on-dark-3x.png`。

### 2.4 浅色成立一半；暗色不成立

- **浅色**：撤掉 hero 光晕这件事是真的发生了（顶部中央 chroma 23.8 → 9.3），页面从「三团极光 + 光晕」变成「一片很淡的冷白」——方向对。但列变窄之后页面的重心落到了四张案例卡上，而它们现在是挤的。所以浅色「成立一半」：底色对了，主体没跟上。
- **暗色**：不成立，而且是两重不成立。
  1. **45% 根本没生效**。暗色右栏实测 `#12152c`，按 token 算满强度是 `#131731`、45% 应到 `#0c1022`——页面上画的是 100%。原因见 P0-1。
  2. **就算降到位也太狠**。`#070b14` 的画布上，`--aurora-2`（紫，0.13）混到 45% 只剩 2~3 个色阶，肉眼不可辨。浅色 45% 刚好，暗色 45% 等于「关灯」。暗色要么 60% 左右，要么别动。
- 还有一件被顺手丢掉的事：§13 那组极光**只留了 `--aurora-1`（青）**，紫和橙全没了。「极光墨」的品牌签是三团，砍掉两团之后它只是一片青色渐变。

## 3. P0 必须修

### P0-1 极光降档改在了错的层，页面上仍是 100%

**问题**：`app.css:14639` 把 45% 写进 `.app` 的 `background`。但真正画极光的是每个视图卡——`app.css:1123` 那条排除法规则（特异性 (0,7,1)）给 `.app > :not(.titlebar)...` 设了 `background-image: var(--aurora-field)`，它**整条盖住了 `.app` 自己的背景**（该规则上方 2026-10-22 的注释就是为此而写）。同一条规则的受害者还有 `.chat{background:transparent}`（14406），它是死代码。
**实测**：暗色右上 `#12152c`（满强度 `#131731`，45% 应 `#0c1022`）⇒ 100%。

**改法**：改 token，不改背景。

```css
/* app.css §13 —— 删掉对 .app 的 background 覆盖，换成覆盖真正被画出来的 token */
html[data-focus="on"] {
	--aurora-field:
		radial-gradient(1200px 620px at 16% -10%, color-mix(in srgb, var(--aurora-1) 45%, transparent), transparent 62%),
		radial-gradient(1000px 560px at 90% 2%,  color-mix(in srgb, var(--aurora-2) 45%, transparent), transparent 60%),
		radial-gradient(820px 480px at 64% 112%, color-mix(in srgb, var(--aurora-3) 45%, transparent), transparent 64%);
}
/* .home(13926) 与 .settings(14267) 各自又画了一组满强度极光 —— 用同一 token 收口，否则首页仍不降 */
html[data-focus="on"] .home,
html[data-focus="on"] .settings { background-image: var(--aurora-field); }
```

**为什么**：token 是唯一入口，改层永远会被下一层的特异性打回来；而且现在这条 e2e（`focus-mode.mjs:77`）读的是 `.app` 的计算背景，它能变绿、屏幕上什么都不会发生——测试在给一个看不见的改动背书。

### P0-2 专注模式下全屏最亮的东西，是一个按不动的按钮

**问题**：左上角 `.sidebar-toggle-btn`（`app.js:72730`）是 `.app` 的直接子节点，不在 `.titlebar` 里，所以不吃 `opacity:.55`；而专注模式下 `.sidebar{display:none}`，点击只改 `sidebarOpen` 状态，屏幕上毫无反应。它还是 Tab 序的第一站，`aria-label` 仍然是「展开侧栏」。
**证据**：`review/topleft-on-dark-2x.png`——纯白，是整张暗色截图里最亮的像素。浅色版同样满对比度（`review/topleft-on-light-2x.png`）。

**改法**：

```css
/* 专注模式的左上角不该是"退出不掉的开关"：这块位置让给退出（见 P1-4），先把它关掉 */
html[data-focus="on"] .sidebar-toggle-btn { display: none; }

/* 顺带把一条空转的规则说清楚：视图卡把标题栏整条盖住，实测 y=30 处没有缝。
   要么删掉 .titlebar{opacity:.55}，要么承认它只对 Windows 的菜单栏生效并注明 */
```

**为什么**：一页纸的第一印象由「最亮的那一点」决定。现在那一点是个失效控件——用户会先点它，然后再找出口。而 §12.2 把 `opacity:.55` 记为「标题栏降权」的成绩，实际它降的是一个看不见的对象，真正的干扰项（这个按钮）没被碰到。

### P0-3 退出胶囊两个主题都过不了 4.5:1，而它是唯一的鼠标出口

**问题**：`.focus-exit`（14665 起）`font-size: var(--text-meta)=12px` + `opacity: .72` + `--glass-bg` 底。
**实测**：浅色 `#838b8c` on `#f3f4f7` = **3.45:1**；暗色 `#6e6b6e` on `#0a0d16` = **3.80:1**。12px 文本的 AA 线是 4.5:1。
**为什么算 P0 而不是 P1**：Esc 在输入框内被刻意豁免（§12.1），正在写东西的人没有键盘出口；这时胶囊是唯一出路，而它读不出来。这是可访问性，不是审美。

**改法**：

```css
.focus-exit {
	opacity: 1;                      /* 0.72 → 1：浅色 ≈6.4:1、暗色 ≈6.3:1，两版都过 AA */
	color: var(--text-secondary);
	font-size: var(--text-list);     /* 12 → 13：它是出口，不该和 meta 同级 */
	border-color: var(--border);     /* --glass-border 是 rgba(255,255,255,.75)，白底上等于没边 */
	box-shadow: var(--shadow-sm);    /* 让它从白卡上浮起来，而不是融进去 */
}
.focus-exit:hover,
.focus-exit:focus-visible { color: var(--text); }
```

### P0-4 没有会话页的证据，这一版的「读感」从未被看见

**问题**：三张截图全是首页。15px 正文、720 列、玻璃头部、胶囊与 composer 的真实关系，一条都无法验证。而这一版的核心主张恰恰是「读起来像一页纸」。
**要补的图**（进 `artifacts/focus-mode/`，同一套 1600 设计像素窗口）：

1. `focus-chat-light.png` / `focus-chat-dark.png`：**有正文的会话页**（≥3 轮、含代码块与表格），专注模式；
2. `focus-off-chat-light.png`：同一会话的普通模式对照；
3. `focus-on-light-900w.png`：窗口拉到最小 900 宽，验证胶囊与发送按钮的关系。

每张顺手量三个数：正文行宽（px ÷ 字号 = 每行字数）、胶囊与发送按钮的间距、`.chat-header` 的可见边界。

**为什么**：现在的 e2e 全绿（`focus-mode.mjs`），但它断言的 `appBackground`（第 77 行）读的是一个被盖住的层——**测试在证明一个看不见的改动**。没有会话页截图，这个特性就无法对外声称「更好读」。

## 4. P1 应该修

### P1-1 进入是硬切，没有「翻页」

**问题**：`display:none` 让侧栏 0ms 消失 264px；同一个「侧栏让位」动作在普通模式是有过渡的（`DESIGN §5 受控例外 ④` 已经为它登记了 `flex-basis` 过渡）。同一语义两种体感。加上胶囊、列宽、字号同时跳到终态，整屏只闪一下。
**改法**：不碰布局属性（§5.1 禁止过渡 `width`），只做一次入场淡入（§5.8：入场照做、离场不做）：

```css
/* 入场：像翻到下一页，而不是侧栏被抽走 */
html[data-focus="on"] .app > :not(.titlebar):not(.sidebar):not(button) {
	animation: focus-page-in var(--dur-base) var(--ease-out);
}
@keyframes focus-page-in {
	from { opacity: .78; transform: translateY(3px); }
	to   { opacity: 1;   transform: none; }
}
/* 新增动画必须进 §10.3.1 的 reduced-motion 关停清单 */
@media (prefers-reduced-motion: reduce) {
	html[data-focus="on"] .app > :not(.titlebar):not(.sidebar):not(button) { animation: none; }
}
```

**为什么**：264px 的瞬时位移会被读成「闪了一下」，而不是「进入了另一个空间」；入场动画是这一版最便宜的「像一页纸」投资。

### P1-2 案例卡挤到 162px，标题出孤字行

**问题**：`.case-grid` 固定 4 列（3643），内容盒 672 减 3×8 gap ⇒ 每张 162px；标题 13px（14216 覆盖为 `--text-list`）一行约 12 字，「《思考，快与慢》精读笔记卡」13 字必然折行，第二行只剩「卡」。
**改法**（保守，推荐）：

```css
html[data-focus="on"] .case-grid { grid-template-columns: repeat(2, minmax(0, 1fr)); } /* 162 → 332 */
html[data-focus="on"] .case-title { text-wrap: balance; }                                /* 万一还折，至少不孤字 */
```

（更彻底的做法是让案例区在专注模式下整块撤掉 + `html[data-focus="on"] .home-main { padding-bottom: var(--space-6); }` 把为它预留的 268px 还回去——但那要先确认「专注模式下首页是否还承担启动器职责」，属于产品判断，我不替你定。）

**为什么**：162px 的卡在截图里已经是「四张封面挤成一条亮带」，标题再折成孤字，用户第一眼会认为界面坏了。

### P1-3 `--text-body` 的作用域太宽，把「过程信息」也顶到了正文档

**问题**：`html[data-focus="on"] .chat { --text-body: var(--text-emphasis) }`（14660）是作用域级覆盖，于是 `.entry.tool`（5083）、`.markdown td`（5052）、`.todo-list-box`、`.task-agent-box` 一起从 14 升到 15。正文和工具行的字号差被抹平了，层级只剩颜色。
**改法**：

```css
/* 只给正文一档，不再动整个 token */
html[data-focus="on"] .entry.assistant { font-size: var(--text-emphasis); }
/* 上一行生效后，删掉 .chat 的那条 token 覆盖 */
```

**为什么**：`DESIGN` 的档位纪律是靠字号差拉层级的；工具行 14 / 正文 15 才是「过程信息」与「内容」的差，两者都 15 之后，长会话里过程块会更抢戏——恰好和专注模式的目标相反。

---

### P1-4 胶囊占了「发送按钮的家」

**问题**：右下角是主操作角（composer 下内边距 16px、发送按钮 32px）。1280 时不打架，900 最小窗宽时擦边约 4×24px。
**改法**：把它搬到左上角——原来那个死掉的开关就在那儿，胶囊 94×30 正好接管：

```css
.focus-exit { top: var(--space-3); left: var(--space-3); right: auto; bottom: auto; }
html[data-focus="on"] .sidebar-toggle-btn { display: none; }   /* 与 P0-2 同一条 */
```

**为什么**：① 不占主操作角；② 入口（侧栏里的「专注模式」）与出口在同一侧，位置记忆成立；③ 「离开沉浸态」在阅读器里普遍在左上（Escape 的视觉对应物）；④ 顺手让 P0-2 那个最亮的死按钮变成最亮的可用按钮。

---

### P1-5 暗色的 45% 太狠，而且只留了一团极光

**问题**：`#070b14` 上 45% 的紫只剩 2~3 个色阶；§13 那组只留 `--aurora-1`，紫/橙全丢。
**改法**：

```css
[data-theme="dark"][data-focus="on"] {
	--aurora-field:
		radial-gradient(1200px 620px at 16% -10%, color-mix(in srgb, var(--aurora-1) 62%, transparent), transparent 62%),
		radial-gradient(1000px 560px at 90% 2%,  color-mix(in srgb, var(--aurora-2) 58%, transparent), transparent 60%);
}
```

**为什么**：同样的百分比在暗背景上的视觉振幅约为浅色的 1/3（同样的色相混合，暗色的绝对色差更小）。暗色要「有温度」得比浅色高 15~20 个点；橙色（`.05`）本来几乎不可见，撤掉无损失，紫必须留着——它是「极光」而不是「青色渐变」的理由。

## 5. P2 可以留

| # | 问题 | 改法 | 为什么 |
| --- | --- | --- | --- |
| P2-1 | 状态跨启动持久化，与 §12.4「此刻的姿势」的定性矛盾：下次开机侧栏不见了，用户第一反应是坏了 | 改 `sessionStorage`，或启动时不恢复（`readFocus` 只在同一次运行内有效） | 「姿势」的语义是会话级；跨会话记忆一个隐藏导航的状态，收益小于困惑 |
| P2-2 | Esc 抢占：模态/命令面板打开时，一次 Esc 同时关模态和退专注（两处都没 `stopPropagation`） | keydown 里先判 `document.querySelector(".modal-backdrop")` 再看 focusMode | 一次按键一个后果 |
| P2-3 | 快捷键用 `event.key.toLowerCase()`（`app.js:71616`），中文输入法或非拉丁布局下 `key` 不是 `"f"`，⌘⇧F 会静默失效 | 改 `event.code === "KeyF"` | 物理键位才是快捷键应匹配的东西 |
| P2-4 | 进入/退出无 `aria-live` 播报；侧栏入口的 `aria-pressed` 在侧栏隐藏后不可达 | 用一个 `role="status"` 播报「已进入专注模式」；入口改为在侧栏恢复时反映状态 | 屏幕阅读器用户需要知道语境变了 |
| P2-5 | 右侧预览面板在专注模式下没有定义行为：它照常展开，把 720 列挤到左边，胶囊落在面板上 | 专注模式下默认收起面板（复用 `setPanelOpen(false)`），或至少让列宽以「剩余空间」计算 | 「读 artifact」才是专注模式的主场，现在这条路是坏的 |
| P2-6 | 会话页顶部通栏玻璃条 + `border-bottom` 在专注模式下原样保留（CSS 上如此，截图未验证） | 见 §2.1 的 ① | 它是「应用」的语言，不是「页」的语言 |

## 7. 值得留下的

不是全都要改。这四件事我建议保留：

1. **会话列 832→720 + 正文 15px**——这一版最对的决定，方向正确，只是还没走到 600–640。
2. **Esc 在输入框内不生效**——比很多成熟产品想得清楚。
3. **`focusContentWidth` 的「只收不扩」契约**——在 4K 上不会把正文拉到 2000px，这是纪律。
4. **状态不进 `preferences`**——专注模式不该污染设置面板。

## 8. 总评

**方向是对的，但这一版是「把侧栏关掉」，不是「把页面点亮」。** 三个 P0 里有两个是照着规范写、没照着屏幕看的产物：45% 改在了被盖住的那一层，降权的却是看不见的标题栏，而全屏最亮的东西是一个按不动的按钮——它们都能让测试变绿，却都没让用户看到任何东西。修完 P0 它才是一个**可用的**专注模式（能退出、能看清、极光真的降了）；修完 P1 那三条「页」的功夫（页眉、输入卡、案例卡），它才配叫「一页纸」。
