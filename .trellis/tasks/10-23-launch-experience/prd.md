# 启动体验三项改进：图标重设计 / 应用内更新 / 网络代理

## 背景

用户在 macOS 上安装 ZeroWork 后提出三项体验问题（2026-10-23）：

1. **Dock 里的应用图标辨识度低**：当前 `build/icon.svg` 是近白底 + 细黑线圆环/文档，
   在 Dock 的深色壁纸上几乎「消失」，在同类应用（彩色底 + 高对比标记）之间显得单薄。
2. **更新必须跳转到 GitHub 发布页**：设置 → 通用 → 更新在 macOS 上只能显示
   「有新版本，请到发布页下载」，用户需要自己找版本、找安装包。虽然 macOS 未签名
   确实不能自动安装，但「应用内下载并打开安装包」是可行的，能省掉大半步。
3. **没有代理设置**：无法直连模型 API（或被墙的服务）时，应用内没有任何入口，
   只能改系统代理或环境变量；而 daemon（模型请求）、主进程（更新）、
   运行时下载三处网络栈互相独立，改一处不生效。

## 任务地图

| 子任务 | 目录 | 交付物 | 依赖 |
| --- | --- | --- | --- |
| 应用图标重设计 | `10-23-app-icon-redesign` | 新 `build/icon.svg` + 重新生成的 icns/ico/png | 无 |
| macOS 应用内下载更新 | `10-23-mac-in-app-update` | 设置页「下载更新」→ 应用内下载 dmg 并打开 | 无 |
| 设置通用页新增网络代理 | `10-23-network-proxy-settings` | 通用页代理配置 + 三处网络栈接管 | 无 |

三个子任务**互不依赖**，可独立实现、独立 PR。父任务只负责：

- 维护这份需求集合与验收口径
- 三项全部合并后做一次集成复核（同时装包验证图标、更新、代理互不打架）

## 共同约束

- **不降低安全默认值**：代理默认「跟随系统」，手动配置是显式选择；
  代理认证信息不得出现在日志、审计事件或渲染层可读的任意位置。
- **如实降级**：平台能力不足时（如 macOS 无法自动安装）必须说明原因与下一步，
  不允许伪装成「已自动更新」。
- **文档与代码同等重要**：用户可感知的行为变化写进 `CHANGELOG.md [Unreleased]`，
  涉及设置的写进 `docs/` 对应文档。

## 验收标准（父任务）

- [ ] 三个子任务的 PR 均已合并，`main` 的 `CI 总览` 为绿
- [ ] 三处改动同时存在于一个安装包中时互不影响：图标正常、更新可检查、代理可配置
- [ ] `CHANGELOG.md [Unreleased]` 记录了三项用户可感知的变更
