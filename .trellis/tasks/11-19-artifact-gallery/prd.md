# PRD：成果展厅（#423）

## 背景

WorkBuddy 的核心承诺是「交付可验收的成果」；ZeroWork 已有资料库（跨会话汇总交付过的
产物），但它是一张行式清单，视觉上像设置页，缺少「成果感」；看到一份报告后，
下一步只能自己回会话里描述「接着改」。

## 目标

1. **画廊**：交付物以卡片呈现，按类型画第一方封面（文档 / 表格 / 幻灯片 / 研究笔记 /
   图片 / PDF / 代码 / 链接），网格与列表两种视图可切。
2. **筛选**：按类型、来源会话、时间范围（全部 / 7 天 / 30 天）筛选；搜索文件名。
3. **详情**：预览（沿用现有通道）、版本历史（与文件历史联动）、来源会话、复制路径、
   在文件夹中显示。
4. **继续修改**：以该产物的来源工作目录新建会话，并预填「先读这份文件，再按要求修改」
   的提示；路径必须落在来源工作目录内（不新开任意路径读取通道）。

## 非目标

- 缩略图渲染（不跑 Office 渲染、不截图）；封面是类型示意图，不是文件内容预览。
- 文件内容搜索（只搜文件名）。
- 跨设备同步 / 云端展厅。
- 修改文件历史页本身的交互（只加「定位到某个文件」的初始选中）。

## 约束

- 数据面只用现有 `library:list`（必要时只增字段），不新增读任意路径的 IPC。
- 预览仍走「切到来源会话再打开预览面板」的既有路径。
- 「继续修改」只在产物位于某个来源会话的 cwd 内时可用；否则禁用并说明原因。
- 第一方封面：复用 `case-cover.js` 的确定性几何（seed/lines/bars），不引入图片资源、
  不出网、不新增颜色 token。
- 亮暗一致；网格与列表都要键盘可达；空态/筛选无结果/失效文件都有可读呈现。

## 验收标准

- [ ] 网格视图：每张卡有类型封面、文件名、类型标签、大小、交付时间、来源会话；
      失效文件有「文件已不在」标记且不可预览。
- [ ] 类型/来源/时间筛选与文件名搜索可叠加；无结果给「清除筛选」。
- [ ] 网格 / 列表切换保留筛选与搜索；列表视图保持现有行能力。
- [ ] 详情抽屉/弹窗：预览、版本历史（有版本时跳到文件历史并选中该文件）、
      来源会话、复制路径、继续修改。
- [ ] 「继续修改」：在来源 cwd 新建会话、切到 chat、预填提示；产物在来源工作区外时
      按钮禁用并说明（不提供任意路径读取）。
- [ ] 单测：类型判定、封面稳定性、筛选/搜索/时间范围、路径归属、继续修改提示。
- [ ] e2e：真实 Electron 造出交付物 → 网格截图（亮/暗）→ 筛选 → 详情 → 版本历史
      跳转 → 继续修改打开新会话（断言 cwd 与预填）。
- [ ] `CHANGELOG` 记「新增」；`docs/USAGE.md` 的资料库一节更新。
