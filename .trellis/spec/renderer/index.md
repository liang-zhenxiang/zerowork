# renderer（渲染层）编码规范

> `src/renderer/` —— React 19 SPA，跑在 sandbox 渲染进程里。
> **改界面之前先读完本页，再读 `docs/DESIGN.md`。**

---

## 动手前的检查清单

- [ ] **视觉值是否来自 `app.css` 的 `:root` token？** 不许硬编码颜色 / 间距 / 圆角
- [ ] **档位够用吗？** 不够要**先改 `docs/DESIGN.md` 写明理由**，不许在组件里临时加档
- [ ] **是否新增了类名 / 复制了视觉值？** 优先用既有类或抽共享组件
- [ ] **四种交互状态齐了吗？** normal / hover / active / disabled
- [ ] **加载 / 空 / 错误三态是否互斥且可辨？**
- [ ] **改动是否会导致大规模重排？**（见下「禁止事项」）
- [ ] 改完跑 `npm run build && npm run check:renderer-assets`

## 一、当前状态：chunk 粒度，不是组件粒度

`src/renderer/src/` 下的文件对应**构建时的 chunk**，不是逐组件的源文件。
`app.js` 单个文件就有约 68,000 行、1,700+ 个顶层声明（含 React 及其它内联库）。

**这不是待修的欠债，是有意保持的现状。** 自动区分「哪些是第三方库、哪些是应用代码、
哪些是组件」需要语义判断，工具做不到；强拆会产出既不可读也不可靠的划分。

要拆到组件级需要**人工判断组件边界**。已知的模块切分线索：

| 模块 | 作用 |
| --- | --- |
| `lib-chat-ui` | 对话 UI 组件库（`cr-` 前缀类名） |
| `home` | 首页 |
| `ui-docs-viewer` | 文档查看器 |
| `safe-delete-events` | 安全删除事件处理 |

> `app.css` 的注释引用这些模块里的类名来交代取值来由 —— 类名本身都还在
> `app.css` 里，可直接搜索核对。

## 二、产物命名契约（真实事故，不要"优化"它）

**渲染层产物必须用无哈希的语义名**（`app.js` 而不是 `app.a1b2c3.js`）。

原因：懒加载依赖表是**字面量字符串**（`m.f||(m.f=[...])`），构建工具**不会改写它们**。
带上内容哈希后所有引用立刻断链 —— 而 CSS 那条断链会让**整个渲染层落进错误边界**。

`npm run check:renderer-assets` 就是守着这条契约的。

## 三、设计 Token：单一真源与档位纪律

**Token 的单一真源是 `src/renderer/src/app.css` 的 `:root`。**
`docs/DESIGN.md` 规定的是**这些 Token 怎么用、哪些做法被禁止**。

### 档位数量是固定的，不允许在组件里临时加档

| 类别 | 档位数 |
| --- | --- |
| 间距 | 7 |
| 字号 | 5 |
| 文字色 | 3 级 |
| 圆角 | 4 |
| 阴影 | 3 级 |
| 时长 | 3 档 |

- 档位不够用时：**先改 `docs/DESIGN.md` 写明理由，再改 Token**
- 数值相同但**语义**不同时必须各开一个语义名，不能因为「值一样」就复用
- 圆角按**用途**归档（模态 / 问卷卡 / 案例封面归 `--radius-lg`），不按数值大小挑

### 关键纪律

- **文字色三级**：主 / 次 / 弱。停用态用「降一档灰度」表达，不新造颜色
- **状态色只表状态**：只有成功 / 警告 / 错误 / 进行中用状态色；
  「分支」「分类」这类**不是状态**的信息不许借状态色表达
- **正文行高基准 1.6**；字重只有 400 / 500 两档
- **动效三档**只用于*交互*；*动画*（非交互触发）要单独登记
- **四态过渡统一走 `--dur-fast`**，变色类用 `--ease-standard`；不在单个组件里另立时长
- **按压缩放**：图标按钮 active 叠 `scale(.96)`；次级按钮 / chip / 卡片叠 `scale(.98)`
- **进出场不对称**：离场比入场快

### 加载 / 空 / 错误三态

| 态 | 判据 |
| --- | --- |
| 加载中 | 数据为 `undefined` |
| 真空 | 数据为 `[]` |
| 错误 | 就地呈现，并给出重试动作 |

**数据到达前不得显示「无数据」类文案。** 结构已知的等待用骨架屏：骨架行与真行
同尺寸、同类名，使列表到达时是「同一片区域被填上」而不是整块替换。

## 四、禁止清单（`docs/DESIGN.md` §6，摘要）

- 硬编码颜色 / 间距 / 圆角，绕过 token
- 原生 `<select>` —— 用既有的自定义下拉外观
- 过渡**布局属性**（`width` / `height`）—— 要表现长度变化用 `scaleX`
- 把「加载中」和「空」混为一谈
- 在组件里新造类名 / 复制视觉值
- 隐藏核心功能
- 用 `outline: none` 抹掉焦点环

已登记的例外（**新增例外必须登记并编号**）：`flex-basis` 过渡（侧栏折叠）、
`height` 过渡（轨道高度）。**未登记的布局属性过渡一律不放行。**

---

## 五、可访问性

- **焦点指示**用 `--text-secondary`，与全局焦点环同色；**焦点环不得被抹掉**
- **状态不只靠颜色**：位置、文字、形态各自都能独立表达
- 骨架自身用 `role="status"` 承担「在读取」语义

---

## 六、禁止事项

- **不为了 lint 通过而大规模重排本目录**（`AGENTS.md` 红线 6）：
  这里是大 chunk 文件，重排会产生淹没真实改动的巨型 diff
- **不删除 `$1` `$2` 这类变量名后缀**（红线 7）
- **不改变渲染层产物的命名规则**（见上「产物命名契约」）
