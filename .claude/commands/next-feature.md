## 动手之前(必做)

1. **先更新合并最新代码**:确认本地 `main` 与远端一致,再从最新 `main` 切分支。
2. **了解近期做过的功能**(至少看其中两样,避免重复造轮子):
   - 最近的 PR:`gh pr list --state all --limit 10`
   - 最近的 commit:`git log --oneline -15`
   - `.trellis/tasks/` 里做过与已归档的任务
3. **走 Trellis 流程**:执行本命令即视为同意创建 Trellis 任务,不必再追问;
   但规划产物(`prd.md`,复杂任务加 `design.md` / `implement.md`)仍要先落盘
   再动手。仓库操作(分支 / 提交 / PR / CI / CHANGELOG)遵循 `AGENTS.md`
   与 maintain-loop skill。

## 功能要求(优先级从高到低)

1. **界面美观度是第一位的**——在此之上才谈好用、想用。
2. **敢于创新**:做有特色、有想象力、与众不同的功能,不做平庸的增量。
3. **竞品调研与融合**:自行检索其他同类项目,对比它们与我们的差异,
   把优秀的内容吸收过来——但**不能一味复制**,必须经过融合改造,
   与本项目的架构、交互和视觉风格无缝融为一体。

## 质量门槛(缺一不可,全部自动化)

- **单元测试、端到端测试、GUI 测试全部补齐**,且必须是全自动的。
- **证明没有破坏老功能**:合入前跑全量测试,确保每一个新功能都不影响老功能。
- **GUI 测试必须真实启动 app 验证**(`npm run test:gui`),并**配合截图**
  确认实际界面效果——不接受只看代码就下结论。
- 用 Agent 工具派遣一个**资深 UI/UX 设计师**角色的 subagent 参与界面评审,
   按其意见迭代,把界面美观度打造成精品。
