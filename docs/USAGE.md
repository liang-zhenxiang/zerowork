# 使用指南

从零把 ZeroWork 跑起来，以及把它的主要功能用起来。

> ⚠️ **刚下载的安装包打不开？先看这条。**
> 安装包**没有代码签名**，所以 macOS 会提示「已损坏」、Windows 会弹 SmartScreen ——
> **这是正常的**，文件本身是完好的，也不是打包出错。
> 两个平台各自怎么打开，见下方[安装](#安装)；介意未签名的话可以从源码构建。

- 只是想快速看到界面 → [快速开始](#快速开始)
- 配置模型供应商 → [第二步：接上模型](#第二步接上模型)
- 某个功能不会用 → 按界面上的功能区找：[助理](#助理) / [项目](#项目) / [专家·技能·连接器](#专家技能连接器) / [自动化](#自动化) / [资料库](#资料库) / [诊断](#诊断) / [统计](#统计)
- 出错了 → [docs/TROUBLESHOOTING.md](TROUBLESHOOTING.md)

## 快速开始

### 安装

从 [Releases](https://github.com/liang-zhenxiang/zerowork/releases) 下载对应平台的安装包。

> ⚠️ **当前安装包没有代码签名 —— 首次打开被系统拦下是正常的，不是文件坏了。**
> 这是没有代码签名证书时的必然结果，不是打包出错：
>
> | 平台 | 现象 | 怎么打开 |
> | --- | --- | --- |
> | macOS | 双击提示「已损坏，无法打开」或「无法验证开发者」 | **右键点图标 → 打开** → 在弹窗里再点 **打开**；若仍被拦下，到「**系统设置 → 隐私与安全性**」的「安全性」一栏点 **仍要打开** |
> | Windows | SmartScreen 提示「Windows 已保护你的电脑」 | 点 **更多信息** → **仍要运行** |
>
> dmg 的 **arm64 与 x64 两个包要各自放行一次** —— 放行过其中一个，不代表另一个不再被拦
> （两个包是两个独立的下载产物，各自带着自己的隔离属性）。
>
> 介意的话可以自己从源码构建（见 [CONTRIBUTING.md](../CONTRIBUTING.md)）。

### 从源码运行

```bash
npm ci
npm run dev     # 开发模式，渲染层热更新
npm run build   # 构建
npm start       # 运行构建产物
```

未打包运行时主进程找不到资源与配置目录，需要显式指定：

```bash
ZEROWORK_CONFIG_DIR=/tmp/zerowork-dev \
ZEROWORK_RESOURCES_DIR=$PWD/resources \
npm start
```

### 配置目录

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `ZEROWORK_CONFIG_DIR` | `~/.zerowork` | 配置、会话、审计、自动化任务都落在这里 |
| `ZEROWORK_WORKSPACE_DIR` | `~/ZeroWork` | 工作区根目录 —— Agent 读写文件的地方 |
| `ZEROWORK_RESOURCES_DIR` | 打包环境自带 | 场景、模式、技能等内容资源目录 |

> 💡 **开发时务必把 `ZEROWORK_CONFIG_DIR` 指向临时目录。** 否则你的实验会写进真实的
> `~/.zerowork`，而里面的会话与审计记录不是设计来被反复重置的。

### 第一次打开：首页的三步清单

首页输入框上方有一张清单，把「跑起来需要哪三件事」摊开说：

| 那一项 | 怎么算完成 | 点它去哪 |
| --- | --- | --- |
| 有工作空间 | 工作区列表非空 | 打开工作空间下拉，可新建一个 |
| 有可用模型 | 当前模型在服务商目录里可用 | **设置 → 模型** |
| 发出第一条消息 | 存在至少一个会话 | 把光标放进输入框 |

**清单不需要你手动打勾，也不能手动打勾** —— 三项状态都是每次现读现推的，
所以它永远与真实情况一致（不会出现「标记完成但其实没配好」）。三项都完成后
整块隐去，只在首页留一个「上手清单」的小按钮，想看时点开、看完收起。

清单末尾那句「本地优先 · 对话、文件与配置都在这台机器上」是字面意思：
逐条出站请求清单位于 [EXTERNAL_REQUESTS.md](../EXTERNAL_REQUESTS.md)。

### 首页的案例卡会连专家一起选好

输入框下方那排案例卡（「不知道做什么，试试最佳实践案例」）每张都绑了一个专家。
点一张卡会**同时**做两件事：把它的提示词填进输入框，并把当前专家设成它绑定的那个。
所以点「Orders API 接口文档」就真的在用接口文档专家，不用自己再想一遍该选谁。
不想用这个专家时，输入框里那个专家 chip 上的 × 可以取消。

## 第二步：接上模型

应用**不内置模型**，需要你配一个供应商。这是有意的：绑定单一供应商的项目，
在供应商改价、改协议、下线模型时没有退路。

打开 **设置 → 模型**，填入：

- **接入地址**（`baseUrl`）：任何 OpenAI 兼容的端点，包括自建网关
- **API Key**
- **模型名**

配好之后在「助理」里发一条消息，能收到回复就通了。

### 常见供应商怎么填

| 供应商 | 接入地址 | 备注 |
| --- | --- | --- |
| Anthropic 官方 | 按其文档给出的兼容端点填写 | 也可以走网关 |
| 自建网关 / 代理 | 你的网关地址 | 只要能说 OpenAI 兼容协议即可 |
| 本地模型（Ollama / vLLM 等） | `http://127.0.0.1:<端口>/v1` | 本地端点通常不需要 Key，留空即可 |

> **验证协议对接是否真的正确**：仓库里有一层端到端测试专门做这件事 ——
> 它用真实端点跑一轮对话，并校验回复里带**真实的 token 用量**
> （那是「确实调用了真实模型」的硬证据，而不是本地 mock 编出来的）。
> 见 [docs/MAINTAINER_GUIDE.md](MAINTAINER_GUIDE.md) 的测试分层。

## 界面结构

侧边栏有七个功能区，一次只展开一个：

| 功能区 | 作用 |
| --- | --- |
| **助理** | 会话列表与对话主界面 —— 你大部分时间待在这里 |
| **项目** | 按工作区/项目组织的视图 |
| **专家·技能·连接器** | 专家、技能开关、MCP 连接器 |
| **自动化** | 定时任务 |
| **资料库** | 工作空间文件与产物 |
| **诊断** | 运行时探测、环境体检 |
| **统计** | 用量与会话台账 |

设置对话框里有九个分组：**通用 / 个性化 / 记忆与进化 / 模型 / 内置运行时 / 数据管理 /
审计中心 / 提示词预览 / 关于**。

**通用**分组的第一项是**外观**：三档界面配色——**浅色 / 深色 / 跟随系统**。选择立即生效
（整个应用换装，含消息流里的 HTML 预览），并保持到重启之后；「跟随系统」会在系统切换
深浅色时自动换装。首次安装默认浅色。

**快捷键**：**⌘./Ctrl+.** 折叠/展开侧栏（专注模式，把内容区让到最宽）；顶栏按钮同样可切。

**更新**：通用分组里还有「更新」区——当前版本徽章、更新渠道（**稳定版** / **Beta 尝鲜**）、
「立即检查」。Beta 渠道在每次功能合并后自动构建（尝鲜但可能不稳），稳定版只在维护者确认
后发布；发现新版本时会有通知。Windows 支持下载后一键「重启并安装」；macOS 未签名，
有新版本时引导到发布页手动下载。

首页在你有过会话之后会出现**最近会话**区（输入框上方）：最近 3 条会话各一行，显示标题与
最后活动时间，点一下直接回到那个会话——「继续昨天的事」不再需要先进会话列表翻找。

## 助理

对话主界面。几个与「普通聊天框」不同的地方：

### 数学公式

模型回复里的公式按 LaTeX 排版：**围栏式 `$$`**（独立一行开、独立一行闭）渲染为居中的
印刷级公式，积分、上下标、希腊字母都正常。**单个 `$` 不会被当作公式**——「预算在 $500
与 $800 之间」这样的金额原样保留。让模型「用 LaTeX 写出公式」即可。

### 场景

场景决定 Agent 的默认工作方式。内置两个：

| 场景 | 定位 |
| --- | --- |
| **办公**（`work`） | 日常办公：文档处理、资料整理、汇报 |
| **代码**（`code`） | 代码开发：读写仓库、跑命令、调试 |

场景的提示词是**内容资源**，放在 `resources/scenes/<场景>/prompt.md`，
可以自己改 —— 改完重启生效。

### 模式

每个会话可切换三种模式（`resources/modes/`）：

| 模式 | 行为 |
| --- | --- |
| **ask** | 只回答，不动手 |
| **plan** | 先给方案，等你确认 |
| **craft** | 直接动手做 |

### 风格

七种表达风格（`resources/styles/`）：专业 / 高效 / 友好 / 直白 / 创意 / 苏格拉底 / 毒舌。
纯表达层，不影响能力。

### 会话的几件事

- **归档**：会话会保存成可检索的记录
- **分支**：可以从历史里的**任意一条消息**分叉出一个新会话，母会话不受影响
- **用量**：每轮对话的 token 用量会被记录，在「统计」里看

### 子代理与团队

Agent 可以把一件事委派给**隔离子会话**（子代理）去做，也可以组建**Agent 团队**
让多个成员各自在独立会话里并行推进，最后回收产出。

这两件事的产物都留在各自会话里，可以在「助理」的会话列表里翻到。

## 项目

按工作区组织的视图。

工作区是 Agent 读写文件的范围。**移除工作区不会删除磁盘上的目录** ——
那是你的真实文件，应用只把它从列表里去掉，并把该空间下的会话移进回收站。
这条行为反直觉，但方向是「宁可少做，也不误删用户文件」。

## 专家·技能·连接器

### 专家

专家是**打包好的能力组合**（提示词 + 技能 + 工具偏好）。内置十余个，
覆盖数据分析、研报、产品设计、前端、文档等场景。每个专家是一份 `resources/experts/` 下的目录。

### 技能

技能是可以按需加载的能力包，用 `/skill:<名称>` 触发。
技能的正文是**在提示词入口处展开**的 —— 也就是说它真的进了模型上下文，
而不是只在界面上显示了一个名字。

技能可以单独开关（**设置 → 通用** 一带的技能开关）。

> 随包的一部分技能来自第三方（Anthropic / Vercel / MiniMaxAI 等），
> 它们各自的许可证与再分发状态见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。

### MCP 连接器

MCP（Model Context Protocol）连接器让外部工具接入。支持 stdio 与 HTTP 两种传输。

配置可以从 **设置 → 模型 / 专家·技能·连接器** 里的入口打开，
格式参考仓库根目录的 [`resources/mcp-example.json`](../resources/mcp-example.json)。

**两条必须知道的安全事实：**

1. **MCP server 等同于「执行你配置的任意命令」** —— stdio 传输会启动一个外部进程。
   只接入你信任的 server
2. MCP 工具的权限判定是 **每次询问**（`ask`），不是默认放行。
   如果它没问你就执行了，那是一个安全缺陷，请按 [SECURITY.md](../SECURITY.md) 报告

配置里可以用 `${VAR}` 形式展开环境变量。**不要把密钥明文写进配置文件** ——
它会被原样读入。

## 自动化

定时任务。到点之后应用会**起一个会话**、跑你写的提示词、把运行记录落盘。

任务三要素：**提示词**、**时间**（一次性 / 间隔 / 每天 / 每周）、**开关**。

运行记录在「自动化」里可以查，也可以在「统计」的台账里看到。

> ⚠️ 定时任务会在你不在的时候执行提示词 —— 而提示词能驱动工具调用。
> 涉及写文件、跑命令的任务，请确认权限档位与任务是匹配的。

---

## 资料库

工作空间文件与**产物**。

Agent 完成任务时可以把成果文件「交付」出来（内部叫 `present_files`），
交付成功之后「资料库」里会出现对应的卡片。这条链路是端到端测试覆盖的
（包括「模型返回对了但界面没接上」这种失败形态）。

支持预览的文件类型：**xlsx / pptx / js / json / PDF / 图片**。
预览失败时会降级到文本或下载。

## 统计

用量与会话台账：token 消耗、会话数、自动化任务的运行台账。

## 权限与命令执行（必读）

这是本项目最需要提前理解的一节。

### 两层控制

```
你的指令 → Agent 决定调工具 → ① 权限判定（独立于模型）→ ② 沙箱执行
                                      ↓ 拒绝
                                  不进沙箱，直接不执行
```

**① 权限判定不依赖模型的自述。** 模型说「这是安全的只读命令」不算数 ——
判定逻辑自己看命令内容与路径。它对凭据目录（`.ssh` / `.gnupg` / `.aws` / `.kube` / `.docker`）、
目录穿越、不透明命令（`-EncodedCommand`、`python -c`）都有专门规则。

### 三档权限

| 档位 | 意图 |
| --- | --- |
| `read-only` | 只读 |
| `workspace-write` | 只能改工作区（**默认档**） |
| `danger-full-access` | 不设限 |

### 沙箱是 Windows 专有的

命令沙箱靠 `koffi` 调 Windows 的 `kernel32` / `advapi32`。所以在 macOS / Linux 上：

| 权限档 | 行为 |
| --- | --- |
| `read-only` / `workspace-write`（**含默认档**） | ⚠️ **命令被直接拒绝执行** |
| `danger-full-access` | ✅ 可以执行（不经沙箱、直接 spawn） |

**这是有意的安全设计：宁可不执行，也不静默地无约束执行。**
否则「受限档」就成了摆设 —— 用户以为有约束，实际没有。

命令被拒时界面会给出理由与逃生指引。若要在 macOS / Linux 上正常用命令执行，
需要把权限档切到「允许完全访问」，或为该平台实现一个等价的沙箱后端
（见 [ARCHITECTURE.md](ARCHITECTURE.md)）。

### 托管运行时

应用可以下载并托管 Node / Bash / Python 运行时，让脚本不必依赖用户预装的环境。
但它是**可选加速器**：运行时没就绪时会**跳过注入**，脚本照常用系统 `PATH` 里的工具执行。

| 运行时 | 平台 |
| --- | --- |
| Node | Windows / macOS（`win32-x64`、`darwin-arm64`、`darwin-x64`） |
| Bash（PortableGit） | **仅 Windows** |
| Python（docx 引擎） | 跨平台 |

非 Windows 平台上 Bash 运行时**根本不会出现在清单里** ——
否则界面会显示「bash 运行时：未安装」并给一个安装按钮，
用户点下去下载的是一个跑不起来的 Windows 专有产物。这是修过的界面误导问题。

## 平台支持

| 能力 | Windows | macOS | Linux |
| --- | :---: | :---: | :---: |
| 应用本体 / 界面 / IPC | ✅ | ✅ | ✅ |
| 模型对话 / Agent 循环 | ✅ | ✅ | ✅ |
| 文档解析（PDF / Office） | ✅ | ✅ | ✅ |
| docx 引擎（Python） | ✅ | ✅ | ✅ |
| 命令执行 | ✅ 沙箱内 | ⚠️ 受限档拒绝 | ⚠️ 受限档拒绝 |
| 系统文件对话框 | ✅ | ✅ | ✅ |
| 托管 Node 运行时 | ✅ | ✅ | ➖ 未适配 |
| 托管 Bash 运行时 | ✅ | ➖ 不适用 | ➖ 不适用 |

**只有 Windows 是完整支持的平台。** macOS 上除命令沙箱外都可以用（开发环境已验证）。
Linux 未做适配，也因此没有发布 Linux 安装包 ——
发一个「界面能开、命令执行被拒」的包，等于对外承诺一个不成立的平台支持。
