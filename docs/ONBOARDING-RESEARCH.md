# 首次运行体验：同类产品调研

本文件是 `.trellis/tasks/10-01-onboarding` 中 **R1（调研同类项目）** 的产出，
目的是回答一个具体问题：**一个陌生人第一次打开 ZeroWork 时，别人是怎么做的，我们该抄哪几条。**

结论的用法是**输入后续路线**，不是实现方案 —— 每条建议的落点与成本都写在第四节。

---

## 调研范围与方法

**怎么查的**：只用公开可查的材料 —— 官方文档、官网、GitHub Issue 与 README、第三方实测教程与评测。
过程是 WebSearch 定位、WebFetch 读原文，不依赖记忆里的产品印象。

**查了哪些**（8 个，分三类）：

| 类别 | 产品 | 为什么选它 |
| --- | --- | --- |
| 本地优先的桌面客户端 | AnythingLLM | 形态最接近：本地优先 + 有 Agent 能力 + 有工作空间概念 |
| | Msty | 「一键本地 AI」的典型做法 |
| | LM Studio | 分步引导 + 可跳过的典型做法 |
| | Jan | 反面对照：没有引导会怎样 |
| 中文 / 国产 | Cherry Studio | 中文形态最接近，且**有一份在讨论的新手引导设计** |
| 能执行任务的 Agent 桌面端 | Cursor | 通用 Agent 桌面端的首启处理 |
| 对照（不单独展开） | Witsy / Open WebUI / Claude Desktop / Manus | 分别提供「最小配置」「账号墙的反面」「prompt starters 的反模式」「首个任务该多低风险」四个视角 |

**局限（先说清楚）**：

1. **没有逐个下载安装实测。** 结论来自文档与第三方描述，与最新版本可能有出入。
   一个直观证据：LM Studio 的首推模型在不同来源里从 Llama 3.2 3B 变到 gpt-oss-20b，
   可见这类产品的首启细节变动有多快。
2. **Cherry Studio 的四步引导是一份 Feature Issue（#13421）的设计稿**，不是已发布行为。
   该 Issue 已关闭并挂进 v1.8.1 里程碑，但**不能保证当前发布版就是这样**。
   引用它是因为**它的判断**（引导负责什么、不负责什么）比它的截图更有价值。
3. 查不到的会明确写「查不到」，不做补全。

## 逐个产品

### AnythingLLM

- **第一屏**：首次启动是一个**独立的全屏向导**，顺序是
  欢迎页（点「Get started」）→ 选 LLM 供应商 → **Data Handling & Privacy（数据处理与隐私）声明页**
  → 可跳过的登录 / 问卷 → **创建第一个工作空间**（起个名）→ 进主界面。
  主界面首页带一个 getting-started 清单，并已默认存在一个叫 `My Workspace` 的空间。
  供应商选项里的默认项「AnythingLLM」**内置了一个由 Ollama 驱动的本地模型运行器**。
- **降低门槛的做法**：
  - 把「隐私」做成引导里**必须翻过的一页**，而不是设置里的一条。声明写明模型与对话只在本机、
    文档用内置 embedder 在本地生成向量、向量存在本地 LanceDB。
  - 引导**强制用户先建一个工作空间**才放行 —— 而工作空间正是它组织文档与会话的核心单位。
  - 内置供应商，用户一个 Key 都不填也能走到聊天（但要先下个模型，否则报 `model is required`）。
- **值得借鉴的**：
  1. **把「本地优先」在首次运行时讲清楚。** 我们有一份 `EXTERNAL_REQUESTS.md`，
     但用户第一次打开时看不到任何一句。可以把它压成首屏一句话加一个入口。
     （来源：MakeUseOf 实测描述 / AnythingLLM 官方隐私文档页）
  2. **首屏的 getting-started 清单**：把「还没做的事」摊在主界面上，而不是等用户自己找。
     （来源：AnythingLLM_Guides 走查）
  3. **引导里有「创建第一个工作空间」，且它是核心概念。** 我们也有工作空间
     （`WorkspacePicker`），但首次运行时它只是输入框下方一个写着「选择工作空间」的下拉，
     没有任何解释。（来源：同上）
- **不适用于我们的**：
  - **内置 Ollama**：那要么替用户装一个运行时、要么绑死一个本地推理引擎，两者都要下载大体积产物。
    我们不内置模型是**有意的**（`docs/USAGE.md`：「绑定单一供应商的项目，在供应商改价、
    改协议、下线模型时没有退路」）。
  - **可跳过的登录 / 问卷，以及默认开启的匿名遥测（PostHog）**：我们没有服务端，
    也不该有这类默认开启的出站行为。
- 来源：
  - <https://github.com/attilaszasz/AnythingLLM_Guides>
  - <https://www.makeuseof.com/switched-everything-to-local-ai-stopped-sending-documents-to-cloud/>
  - <https://docs.anythingllm.com/features/privacy-and-data-handling>

### Msty

- **第一屏**：onboarding 页给三条路 —— 「Setup Local AI」（一键）、「Add Remote Models Provider」、
  「Use Ollama Models (Advanced)」（自动探测本机已有的 Ollama，用你现有的模型）。
- **降低门槛的做法**：Setup Local AI 会自动装推理引擎并下载一份起步模型。
  官方文档写默认是 Gemma 2（约 1.6 GB）；第三方实测里出现过 Gemma3 1B、Qwen3 0.6B ——
  版本之间会换。模型名可以点开换成别的，换完再开始下。下完直接进 chats 页。
  Msty Studio 的版本还会**先检查硬件、推荐一个兼容的引擎与模型，并允许在 Light 到 Powerful 之间调整**。
  官方文档明确写出「对不确定从哪开始的用户，建议先选 Local AI」。
- **值得借鉴的**：
  1. **「检查硬件，然后给一个推荐」这个动作本身，不必附带下载。** 我们完全可以只做前半段：
     探测本机（是否已有 Ollama、内存档位），在引导或「设置 → 模型」里给一句
     「你这台机器适合跑哪一档模型」。这**不需要联网**，也不违反「不内置模型」。
     （来源：Msty Studio 官方文档描述）
  2. **把最省事的那条路明确标出来**，而不是把三个选项平铺给用户自己判断。
     （来源：Msty 官方 onboarding 文档）
- **不适用于我们的**：**替用户下载并安装推理引擎与模型**（体积 + 联网 + 我们不做模型分发）。
- 来源：
  - <https://docs.msty.app/getting-started/onboarding>
  - <https://docs.msty.ai/studio/getting-started/quick-start>
  - <https://msty.ai/resources/blog/getting-started-with-msty-studio/>

### LM Studio

- **第一屏**：欢迎页加功能演示，**右上角始终有「Skip onboarding」**；点 Get Started 之后
  **先问一个自我定位**（User / Power User / Developer），再推荐第一个可下载的模型，
  这一步同样能 Skip。
- **值得借鉴的**：
  1. **「先问水平，再决定披露多少」** —— 这是渐进式披露最直白的实现。
     我们没有引导，但同一个问题可以换个位置问：默认停在「能直接动手」的档，
     把高级项（模式、专家、权限档）收在输入框的加号菜单里 —— 现在的结构已经是这样，
     这条的价值是**提醒别在加引导时把它冲掉**。（来源：ITmedia / unwire 实测 / UU 学生指南）
  2. **每一屏都能 Skip，且 Skip 之后功能仍然可用** —— 引导不是门禁。
     （来源：同上）
  3. **首推一个模型而不是给一整个目录** —— 它没有让用户在几十个模型里自己挑，
     而是先给一个默认推荐。（来源：同上）
- **不适用于我们的**：模型目录加下载管理（Hub、量化档位、模型文件的增删）。
  那是「本地推理客户端」的核心，不是办公 Agent 的核心。
- 来源：
  - <https://www.itmedia.co.jp/pcuser/articles/2509/08/news047_4.html>
  - <https://unwire.hk/2025/03/12/lm-studio-ai/ai/>
  - <https://www.uu.nl/sites/default/files/UU-Instructions-Running-a-LLM-Locally-Student-Version.pdf>

### Jan

- **第一屏**：**没有独立的引导向导** —— 有来源明确指出它缺少 LM Studio 那样的 onboarding 场景。
  实际路径是：落在首页 → 点「Explore Models」进模型目录 → 下载 → 在「My Models」里 Start → Chat。
  模型列表里有一个 `Compatible with my device` 的过滤开关。
- **值得借鉴的**：
  1. **反面对照：有功能入口不等于有上手路径。** Jan 的首屏直接把人丢进模型目录，
     多方评测都把它记为「没有 onboarding」。我们的首页有场景页签、能力胶囊、案例卡 ——
     可点的东西不少，但如果没有人告诉用户「先做这三件事」，用户看到的仍是一片可点的东西。
     （来源：utupub.fi 学位论文对比 / Jan 官方文档）
  2. **把「能不能用」标在选项旁边。** 官方文档的原话是：每个模型显示一个带颜色的适配标签
     （**Fits** / **May be slow** / **Won't fit**），依据是你的硬件；量化档位分
     Small / Balanced / Large，默认下载项带 `Recommended` 标记；
     并且特别注明「判断适配不下载任何数据」。我们有对应物可做：
     `ModelCard` 已经显示「连通正常 · 123ms」或失败原因（`src/renderer/src/app.js:63175`），
     可以确认首页的模型引导也带上这层信息。
     （来源：<https://raw.githubusercontent.com/janhq/jan/refs/heads/main/docs/src/pages/docs/desktop/manage-models.mdx>）
- **不适用于我们的**：HuggingFace 模型 Hub 集成、GGUF / MLX 导入。
- 来源：
  - <https://raw.githubusercontent.com/janhq/jan/refs/heads/main/docs/src/pages/docs/desktop/manage-models.mdx>
  - <https://www.utupub.fi/bitstream/handle/10024/182260/Kivimaki_Teemu_opinnayte.pdf>

### Cherry Studio（中文 / 国产，最贴近我们的形态）

- **现状**：官方文档与第三方教程描述的是**手动配置**路径：下载安装 → 左下角设置 → 模型服务
  → 选或加供应商 → 填 Key → 获取模型列表 → 设默认模型 → 开始对话。
  内置 30 多个行业助手；它自家的 CherryAI 供应商**默认启用且带免费模型**。
- **正在讨论的做法**（Issue #13421，`New User Onboarding — Guided Setup from First Launch to First Chat`，
  已关闭并挂进 v1.8.1 里程碑）—— 一个四步全屏引导：
  1. **语言 + 主题**
  2. **连供应商**：CherryIN 走 OAuth 登录；其它供应商填 Key → 验证 → 拉取模型列表 →
     **默认全选**，可取消；Ollama 等本地模型不需要 Key
  3. **设默认模型**：默认助手 / 快速模型 / 翻译模型三行，对应现有设置项
  4. **完成页**：给一份配置摘要（语言、主题、供应商、模型数）加一个开始按钮

  布局是全屏独立页、无侧栏、固定 560×520 卡片、内容可滚、底部固定、有进度点与上一步 / 下一步。
  **每一步都可跳过**，跳过即置 `onboardingCompleted = true` 进主界面；
  之后可以从 设置 → 关于 →「重新开始引导」再进。设计目标里写着「快路径 2 分钟内完成」。
- **它最有价值的一句判断**（原文大意）：CherryAI 默认启用且带免费模型，
  所以**即使全部跳过也能立刻聊天** —— **「引导是用来帮用户配更好的模型，不是为了解锁基础功能」**。
- **值得借鉴的**：
  1. **「引导不负责解锁功能」这条原则。** 我们现在的首页在缺模型时会给一条横幅，
     这个形态是对的；要改的是**当它出现时用户除了「去设置里填 API Key」没有别的可做** ——
     首页那些案例卡此刻点了也发不出去，等于把用户推进一个死胡同。
  2. **引导的克制**：只做**四件事、两分钟、每步可跳过**，不做功能导览。
     我们的引导应该是三件事：接模型、选工作空间、发第一条消息。
  3. **完成页给一份「配置摘要」**：低成本变体是引导做完后在首页留一条可关闭的小结
     （当前模型是哪个、工作空间是哪个）。
  4. **之后可以「重新开始引导」** —— 给用户一条回头路。
  5. **拉回来的模型默认全选** —— 少一次勾选就少一次放弃。
- **不适用于我们的**：
  - **免费模型额度**（CherryAI）：需要我们有服务端与计费，且是云端依赖，
    与「不绑定供应商 / 本地优先」正面冲突。
  - **第一个引导步做语言 + 主题**：i18n 是 PRD 的明确非目标；主题选择没必要占一个引导步。
  - 它是**一份提案而不是既成事实** —— 借鉴它的判断，不要照抄它的布局参数
    （560×520 这类数字对我们没有意义，我们的视觉纪律在 `docs/DESIGN.md`）。
- 来源：
  - <https://github.com/CherryHQ/cherry-studio/issues/13421>
  - <https://docs.cherryai.com.cn/docs/jp/pre-basic/providers>

### Cursor（能执行任务的 Agent 桌面端参照）

- **第一屏**：启动时检测本机已有的 VS Code，问是否导入设置、快捷键、主题与兼容扩展；
  之后是遥测询问与登录 / 注册。
  **注意：多方来源对「导入入口在哪」说法不一致** —— 有的说在首次运行向导里，
  有的说在 `Cursor Settings → General`，**不是**首启向导。这点我没能确证，
  只能记下结论：它至少把「带着既有配置进来」当成一件需要在首启处理的事。
- **值得借鉴的**：
  1. **「检测本机已有环境并预填」这个模式可以换成我们的版本。** 我们不从别的编辑器导入，
     但可以检测本机是否已有 Ollama 或常见兼容端点（`http://127.0.0.1:11434/v1`）并在引导里预填。
     这是**纯本机探测，不联网**。（只借这个模式，不借它的具体实现）
  2. **失败要可见**：社区里有一条真实缺陷 —— 点「Import Settings from VS Code → Import」之后
     **没有任何成功或失败提示**，用户以为坏了。这正好对上我们 `docs/DESIGN.md` §4 的三态纪律。
     （来源：forum.cursor.com 的 bug 报告帖）
- **不适用于我们的**：VS Code 扩展生态导入、账号登录。
- 来源：
  - <https://www.learncursor.dev/learn/cursor-basics/migrate-from-vscode>
  - <https://forum.cursor.com/t/import-vsc-settings/170503/7>

### 对照：Witsy / Open WebUI / Claude Desktop / Manus

不单独展开，但各有一个直接有用的点：

- **Witsy**（BYOK 桌面助手 + MCP 客户端）：首启有 setup wizard，**最小配置就是「选一个 LLM」**；
  设置入口在左下角齿轮。它的 changelog 把「Onboarding experience」列为一个已完成特性。
  借鉴：把「最小可行配置」压到**一步**，其余延后。
  （来源：<https://github.com/Kochava-Studios/witsy>）
- **Open WebUI**：首启要求创建账号，**第一个账号自动成为管理员**；登录后模型列表可能是空的，
  要去 Admin Panel → Settings → Models 手动 `Pull a model`。借鉴的是反面：
  把「拉模型」放在管理员面板深处，普通用户会卡在「能进界面但没有模型」。
  **我们的 `ModelGuide` 至少在首页就把这件事顶出来了 —— 这是我们对的地方，别在加引导时改掉。**
  （来源：<https://mintlify.wiki/open-webui/open-webui/quickstart>）
- **Claude Desktop**：首屏是空对话加 **prompt starters（示例提示词）**。
  AI UX Playground 把这个模式的反模式列得很清楚，其中两条对我们直接有用：
  (a)「展示产品其实还做不到的能力」是反模式；(b)「没有关闭或换一批的方式」是反模式。
  **我们首页的案例卡两条都躲过了** —— 12 条真实可跑的提示词，加「换一批」与关闭按钮
  （`src/renderer/src/app.js:15882-15886`）。同页还建议 starters 最好
  **按角色 / 历史使用 / 最近行为个性化**（「continue where you left off」），
  我们目前是固定 12 条按场景切，这是一条可选的进阶方向。
  （来源：<https://www.aiuxplayground.com/pattern/empty-state/>）
- **Manus**（云端 Agent，仅作对照）：明确建议**首个任务要低风险、10 到 15 分钟能跑完**
  （读一篇公开文章 → 写一篇 500 字解读 → 列出用到的 URL），先跑通再上强度；
  官方另有大量新手提示词模板。借鉴：**首屏第一个可点的任务应该是低风险的。**
  我们首页的案例卡（做一份精读笔记卡 / 写一份接口文档）恰好是这类，
  但可以更明确地表达「第一次先跑这个」。
  （来源：<https://manus.im/fr/blog/manus-beginner-prompts>）
  不适用：credits 计费、Cloud Browser、Chat / Agent 双模式切分 —— 都是云端形态的产物。

## 横向对比表

| 维度 | AnythingLLM | Msty | LM Studio | Jan | Cherry Studio | ZeroWork（现状） |
| --- | --- | --- | --- | --- | --- | --- |
| 首次打开看到什么 | 全屏向导（含隐私页） | onboarding 三选一 | 欢迎演示，可 Skip；先问水平 | 直接落首页 / 模型目录 | 直接进主界面（引导为提案） | 首页 hero + 场景页签 + 能力胶囊 + 输入卡 + 案例卡；侧栏 6 项 |
| 有没有独立引导流程 | 有，全屏 | 有 | 有，分步 | 查不到（有来源说它没有） | 提案中：4 步全屏 | **没有** |
| 引导可否跳过 | 部分步骤可选 | 未查到 | 每屏可 Skip | 不适用 | 每步可跳过 | 不适用 |
| 模型配置门槛 | 内置 Ollama；或填 Key | 一键装本地 AI | 下载即用 | 目录里下载 | CherryAI 默认带免费模型 | **必须手填 baseUrl + Key + 模型名** |
| 一键本地模型 | 有（内置 Ollama） | 有 | 有 | 有 | 有（Ollama 免 Key） | 无（有意不做） |
| 示例任务 / 模板 | 工作空间引导 + 首页清单 | 未查到 | 模型目录 | 模型目录 | 30+ 内置助手 | 有：12 条案例卡（真实可跑） |
| 空状态是否给下一步 | 首页清单 | 引导里给 | 引导里给 | 弱 | 提案里给 | 侧栏「暂无历史任务」；**只有缺模型时**给一条横幅 |
| 渐进式披露 | 引导步 → 主界面 | 有 | 问水平决定披露程度 | 未查到 | 引导可跳过 | 加号菜单收着模式 / 专家 / 连接器（已在做） |

**表里读出来的三件事**：

1. **只有我们没有独立引导流程**，而且唯一的「下一步」指引只覆盖三个必要条件里的一个。
2. **「一键本地模型」这一列我们注定是空的** —— 这是有意的取舍，不是缺陷。
   所以不要在这些产品最强的那一列上比，要在「讲清楚该做什么」这一列上比。
3. **我们的案例卡是表里少见的强项**（12 条真实可跑的提示词，多数产品只有模型目录或空对话），
   问题不在缺内容，而在**它出现的位置与时机**：它躺在首屏下半屏，且在用户还没有模型时点了也发不出去。

## 我们能吸收什么（按性价比排序）

每条都落到具体文件或界面区域，并给出成本量级（小 / 中 / 大）。

### 1. 侧栏：把 4 个「敬请期待」从「可点但弹提示」改成真正的禁用态

**现状**：`NAV_ITEMS$1`（`src/renderer/src/app.js:13229`）里 6 项有 4 项 `ready: false`
（助理、项目、资料库、更多）；渲染在 `app.js:13646` 给非就绪项挂了 `nav-item-pending` 类
与 `title="随版本迭代开放"`，但 `onClick` 仍是 `onTodo(label)`，
最终落到 `showToast("「X」待做，随版本迭代开放", "info")`（`app.js:67321`）。

**为什么值得改**：问题不在「点不了」，而在**它长得像一个正常按钮**。
用户点一下得到一个「待做」弹窗 —— 那正是 PRD 验收标准要消掉的「功能缺失错觉」。
更麻烦的是这 4 项里的两个名字：`助理` 是用户最该去的地方，`资料库` 是产物交付
（`present_files`）的落地处 —— **它们被写在最显眼的位置却按不动**。

**做法（二选一，都不隐藏核心功能）**：

- (a) 把 4 项从 `NAV_ITEMS$1` 移出，收进一个「更多」入口，导航从 6 项压到 3 项
  （专家·技能·连接器 / 自动化 / 更多），点开「更多」是一个列明「还有哪些在迭代中」的列表。
  这是**重组**而不是隐藏 —— `docs/DESIGN.md` §6 禁的是隐藏**核心功能**，这四项不是已交付的功能。
- (b) 保留 6 项，把 `ready: false` 的渲染改成真禁用态：不加 `onClick`（点不弹提示）、
  `aria-disabled="true"`、去掉 hover / active 反馈，并用文字或角标说明状态
  （`docs/DESIGN.md` §7.6「状态不只靠颜色」要求同时有文字）。

**建议先做 (b)**：成本更小，且不改动信息架构。

**成本**：小（一个数组 + 一段渲染 + 少量既有类名的样式）。

### 2. 首次运行：把「下一步」做成首页上的三步清单（复用 `.home-guide` 形态）

**现状**：`ModelGuide`（`app.js:14949`）只在「没有可用模型」时出现一条横幅，
文案来自 `guideText()`（`app.js:14943`）：「还没有可用模型，现在还不能开始对话 / 去设置里填 API Key →」。
**这是我们唯一的下一步指引**，而它只覆盖三个必要条件里的一个。

一个能跑起来的 Agent 需要三件事：

| 必要条件 | 现有判据 | 落点 |
| --- | --- | --- |
| 有可用模型 | `judgeModelReadiness`（`app.js:14937`） | `ModelGuide` 已覆盖 |
| 有工作空间 | `cwd` 未绑定 → `UNBOUND_LABEL`「选择工作空间」（`app.js:15431`） | `WorkspacePicker`，无引导 |
| 发出第一条消息 | 无判据 | 案例卡可一键填词（`app.js:15888`），无引导 |

**做法**：把 `ModelGuide` 泛化为 `OnboardingChecklist`，**位置与样式不变**
（仍在 `composer-zone` 内，`app.js:15819`；复用 `.home-guide` 的既有类，见 `app.css:1918`）：
三行，每行一个状态标记、一句说明、一个直达按钮 ——
模型指向 `onOpenSettings("models")`，工作空间指向打开 `WorkspacePicker`，第一条消息指向下方案例卡。
**三项都完成时整个组件返回 `null`**（与 `ModelGuide` 现在的判据写法一致，
符合 `docs/DESIGN.md` §4「数据到达前不得显示无数据类文案」的同一条纪律）。

**为什么适合我们**：它是渐进式披露（没做完才出现、做完即消失）、不联网、不引入新概念 ——
三件事都是既有功能，只是**第一次把顺序讲了出来**。

**成本**：中。判据可以写成纯函数（照 `judgeModelReadiness` 的样子），单元测试可直接覆盖。

### 3. 案例卡：点一下就真的能跑 —— 顺手带上它绑定的专家

**现状**：点案例卡只做 `composerRef.current?.setText(c.prompt)`（`app.js:15888`）。
而 `resources/welcome/README.md` 自己写明了：「`expert` 目前只进数据与校验，
**尚未参与交互** —— 点卡片时顺带安装 / 启用该专家这一步还没做。」

**做法**：`resources/welcome/cases.json` 每条已经有 `expert` 字段（12 条全有），
加载器也已在 `resources.test.ts` 里断言它指向真实存在的专家目录。
点卡片时在 `setText` 之外再调一次 `onSelectExpert(expert)` ——
`HomeView` 已经收到这个 prop（`app.js:15698`），`ExpertChip` 也已存在（`app.js:15867`）。

**为什么适合我们**：这是**把已经躺在数据里的东西接上**，不是新功能；
它把「选案例 → 还要自己想到去选专家」两步压成一步，与 Cherry Studio 引导里
「拉回来的模型默认全选」是同一种省事。

**风险**：专家的「启用 / 安装」语义要先核实（README 写的是「立即启用」；
若某些专家需要安装，就要在点击时给出进度或降级路径）。**实现前先核实，再动手。**

**成本**：小。

### 4. 缺模型时，别只把用户推去设置页

**现状**：`guideText()` 的两条文案都指向设置页。用户去填完回来，首页仍然是空的。

**借鉴**：Cherry Studio 的判断 —— 引导的任务是「配更好的模型」，不是「解锁基础功能」；
Witsy 的「最小配置就是选一个模型」。

**做法（不联网、不内置模型）**：
在「设置 → 模型」的添加模型表单里，把**本地端点**做成可点的预设 ——
预填 `http://127.0.0.1:11434/v1`（Ollama），并带上「本地端点通常不需要 Key，留空即可」
（这句话 `docs/USAGE.md` 里已经有了，只是藏在文档里）。
再往前一步（可选）：像 Cursor 检测本机已有 VS Code 那样，
在填地址前探测本机 `127.0.0.1:11434` 有没有服务在听，有就把预设标成「检测到本机 Ollama」。
设置里已有「测试」按钮（`app.js:63219`）与「刷新模型目录」（`app.js:63250`），
**不需要新建验证能力**。

**明确不做**：「一键帮用户下载模型」—— 那是 Msty / LM Studio / Jan 的做法，
需要联网下载大体积产物，且与我们「不内置模型」的有意取舍冲突。

**成本**：小（一个预设 + 一次本机探测）。

### 5. 首次运行要有一句「本地优先」，而不是一份文档

**现状**：我们有一份很好的 `EXTERNAL_REQUESTS.md`（逐条列出运行时向外的每一个请求），
README 也说了本地优先；但**用户在应用内第一次打开时看不到任何一句**。

**借鉴**：AnythingLLM 把「数据处理与隐私」做成引导里必须翻过的一页。

**做法**：在三步清单（建议 2）的末尾，或者「设置 → 关于」的第一屏，
放一句静态文案加一个入口：「数据留在这台机器上。出站请求逐条可查 →」。
**不要**做成必须点「我同意」的拦截页 —— 我们没有要用户同意的条款。

**顺带解决一个已知缺口**：首页案例卡的封面图此刻会去 `static.workbuddy.cn` 拉图
（见 `EXTERNAL_REQUESTS.md:84-90` 与 `resources/welcome/README.md` 的「封面是远程图」一节），
断网时回落到图标底。**更彻底的解法是把这 12 张封面降采样后随包**，
或首屏改用 CSS 渐变加图标底 —— 那样「本地优先」就不需要解释任何例外。
两件事一起做，比只写一句说明更诚实。

**成本**：一句话是小；换封面是中（要准备 12 张图，或改 `CaseCover` 的降级策略）。

### 6. 给「重新看一遍上手清单」留一条回头路

**借鉴**：Cherry Studio 可从 设置 → 关于 →「重新开始引导」再进；LM Studio 每屏可 Skip。

**做法**：建议 2 的清单状态本来就是**推导出来的**（不是存下来的），
所以「重新看」天然成立：换掉模型或清掉工作空间绑定，清单会自己回来。
需要显式加的只有一条**手动召回**入口（设置 → 关于 →「显示上手清单」），
给那些「做完了但现在想找回来」的人。

**成本**：很小。

## 明确不做

按「看着好但不适合本项目」记录，写明理由，避免下一轮重新讨论一遍。

1. **内置免费模型额度 / 云端免费试用**（Cherry Studio 的 CherryAI 模式）。
   需要我们有服务端与计费，且是云端依赖 —— 与「本地优先、不绑定供应商」正面冲突。
2. **一键下载并安装本地推理引擎与模型**（Msty / LM Studio / Jan / AnythingLLM 的路径）。
   联网下载大体积产物，且我们不做模型分发。
   **半吸收的边界**：只做「探测本机已有的 Ollama」与「预填本地端点」，**不做下载**。
3. **强制账号、登录或默认开启的遥测**（Open WebUI 的首启建管理员账号、
   AnythingLLM 默认开 PostHog）。我们没有服务端；`EXTERNAL_REQUESTS.md` 的克制
   是我们已经有的资产，不能倒退。
4. **独立的「功能导览 / feature tour / 视频教程」**。Cherry Studio 的提案里也把这两项
   列为 out of scope。理由：与渐进式披露相反（一次性倾倒），且视频教程要联网托管。
   注意这不违反 `docs/DESIGN.md` §6 —— 那条禁的是**隐藏**核心功能，
   而不是要求把每个功能都讲一遍。
5. **引导第一步做语言 + 主题选择**。i18n 是 PRD 的明确非目标；主题选择不值得占一个引导步。
6. **模型目录 / 量化档位 / 模型文件的增删**（Jan 的 Hub 与 Fits / Won't fit 适配标签、
   LM Studio 的模型库）。那是本地推理客户端的核心，不是办公 Agent 的核心 ——
   我们要的是「填一个端点」。
   **半吸收的边界**：适配标签背后的**思路**（把「能不能用」讲在选项旁边）可以借，
   但我们没有本地模型文件，能标的只有「这个端点连不连得通」—— 而那个 `ModelCard` 已经在做了。
7. **照抄别人的视觉参数**（Cherry Studio 提案里的 560×520 固定卡片、全屏独立页）。
   我们的视觉纪律在 `docs/DESIGN.md`；引导应复用既有类（如 `.home-guide`），不新造一套。
8. **为了让首屏「看起来全」而打开还没做好的导航项**。
   见建议 1 —— 名字摆出来却按不动，比收起来更伤。
   同理，不因为别人有引导就把「敬请期待」的功能写成引导里的一步。
