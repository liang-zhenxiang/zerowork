# 设计规范

渲染层 UI 的设计规范。**设计 Token 的单一真源是 `src/renderer/src/app.css` 的
`:root`**；本文档规定的是这些 Token 怎么用、以及哪些做法被禁止。

改本文档时，同步检查引用它的注释：`rg 'docs/DESIGN.md' src/`。

---

## §2 Token 档位纪律

档位数量固定，**不允许在组件里临时加档**：

| 类别 | 档位数 |
| --- | --- |
| 间距 | 7 |
| 字号 | 5 |
| 文字色 | 3 级 |
| 圆角 | 4 |
| 阴影 | 3 级 |
| 时长 | 3 档 |

档位不够用时，先改本文档并写明理由，再改 Token —— 不许在组件里加第 8 个间距档。
数值相同但**语义**不同时必须各开一个语义名，不能因为「值一样」就复用。

### §2.0 主题：双块同构，属性驱动

Token 真源有两块：`:root`（亮色基准）与 `[data-theme="dark"]`（暗色，2026-10-02 起接线生效）。
**两块必须同构**——亮色块里所有随主题变化的 token（颜色 / 阴影 / 遮罩 / 分类板），
暗色块都要有对应覆盖；间距 / 字号 / 圆角 / 时长等档位类**不随主题变**，只在 `:root` 定义。
这条由 `scripts/check-theme-tokens.mjs`（`npm run check:theme-tokens`，已收编 lint:all）守护：
加新颜色 token 忘配暗色会在静态检查就红，不用等暗色截图。

> **检查有两项，缺一不可**：
>
> 1. **同名 token 对**：亮色块随主题变的名字，暗色块必须有覆盖。
> 2. **字面量逃逸**（2026-10-04 起，#105）：token 块**之外**的声明里出现
>    hex / `rgb()` / `hsl()` / 命名色 → 报错，除非在 `scripts/check-theme-tokens.mjs`
>    的 `COLOR_LITERAL_ALLOWED` 里（每条必须写明理由与出处，**过期条目同样报错**）。
>
> 第 2 项是被第 1 项的真实盲区逼出来的：首页输入卡外槽的渐变曾是裸字面量
> （`#f0f0f0` / `#f5f5f5`），暗色块漏配 → 深色下输入卡外圈炸出一圈发光边，
> 而检查全绿 —— 因为那个块里**一个 token 名字都没有**，无从比对。
> 同一形态 2026-10-04 又抓到一处：markdown 里的路径徽章底色（`.clickable-path`）
> 是写死的 `#e9eef2`，深色正文里会冒出一块近白亮片。

驱动方式是**单一路线**：渲染层挂载前同步设 `documentElement` 的 `data-theme` 属性
（`app.js` 的 `initTheme`；三档 `light` / `dark` / `system`，`system` 档由 JS 求值成显式的
`light` / `dark`——app.css **没有** prefers-color-scheme 版暗色块，widget 的 CSS 才有双路）。
防闪变的两级：主进程建窗口前按偏好设 `nativeTheme.themeSource`（决定渲染层媒体查询取值
与 `backgroundColor` 首帧底色），渲染层用 localStorage 镜像同步初值。持久化真源是
`preferences.json` 的 `theme` 字段（daemon 写），**缺省 `light`**——存量用户升级后界面不变。

### §2.1 文字色三级

主文字 / 次文字 / 弱文字共三级。停用态用「降一档灰度」表达，不新造颜色。

**「降一档」是字面意思**：三档是 `--text`(100%) → `--text-secondary`(50%) →
`--text-faint`(30%)，从主文降**一档**就是 `--text-secondary`。
降到 `--text-faint` 是降两档，只在「文字本身是唯一的状态信号」时才用。

**当状态已经由位置或文字独立承担时，颜色不必再往深处压。**
`docs/DESIGN.md` §7.6 要求状态「不看颜色也读得出」，所以状态信号的**第一顺位
是形态与文字（分组、组标题、对勾、`disabled`）**，颜色是补充。
反例（2026-10-01 修）：侧栏 4 个「未开放」项曾用 `--text-faint`(30%) 表达状态 ——
那既是降两档，又让 16px 的线稿图标淡到几乎看不见，读起来像「一半图标没加载出来」。
现在这 4 项收成连续一组 + 组标题「即将开放」（状态由位置与文字承担），
颜色回到 `--text-secondary`。

### §2.4 状态色只表状态

只有真正的状态（成功 / 警告 / 错误 / 进行中）用状态色。
「分支」「分类」这类**不是状态**的信息，不许借状态色表达。

### §2.6 正文基准

正文行高基准 1.6。为单行元素引入档外行高不划算。

### §2.7 圆角按语义归档

圆角按**用途**归档，不按数值大小挑：模态、问卷卡、案例封面归 `--radius-lg`。
同类情形一旦登记为例外，后续复用它，不要每次重新决策。

### §2.8 交互动效三档

*交互*动效时长只有三档。*动画*（animation，非交互触发）不计入这三档，需单独登记（见 §10.3）。

## §3 四态过渡

按钮与可点元素的 normal / hover / active / disabled 四态过渡**统一**走 `--dur-fast`，
变色类用 `--ease-standard`。禁止在单个组件里另立时长。

### §3.1 按压缩放

图标按钮（小控件）active 叠 `scale(.96)`；次级按钮、常规按钮、chip、tab 胶囊、卡片
active 叠 `scale(.98)`。

### §3.2 缓动只有两条曲线，且**裸 `ease` 不许出现**

| 用途 | 取值 |
| --- | --- |
| `transition`（变色 / 透明度 / 位移 / 旋转等一切纯视觉反馈） | `var(--ease-standard)`（= CSS `ease-out`） |
| `animation` 入场 | `var(--ease-out)` |
| 动画语义的曲线（逐字节奏、扫光、回弹） | 在 §10.3 单独登记 |

**CSS 关键字 `ease`（`cubic-bezier(0.25, 0.1, 0.25, 1)`）不在允许之列** ——
它与 `ease-out` 是两条不同的曲线，混用会让「同样的 150ms」在不同控件上手感不一致。
2026-10-01 把全文 40 处过渡声明里的 49 个裸 `ease` 收口到 `--ease-standard`
（含 `background` / `color` / `box-shadow` / `transform` / `opacity` /
`border-color` / `scrollbar-color` / `stroke-dashoffset`，以及 §5.1 的
`width` / `height` 两类布局属性例外）。
守卫就是验收命令，命中数应为 0：

```bash
rg 'transition:[^;]*\bease\b' src/renderer/src/app.css | grep -v 'var(--ease'
```

> 注释里引用**第三方**取值（如 cr-input-container 的 `.15s ease`）不算违规 ——
> 上面这条命令只认「同一行里 `transition:` 之后跟裸 `ease`」的形状，
> 写注释时把 `transition:` 前缀去掉即可。

### §3.3 卡片级别

内容容器走**卡片级别**，不新开组件级别：底用 `--bg`，边界由卡片自身的圆角与底色承担。
卡片 meta 行（版本 / 来源 / 导入时间等）沿用同一套口径。

### §3.4 文字层级

列表正文用 `--text-list`，副行用 `--text-meta`。
禁用行**只改透明度，不置灰背景**。

**但淡出不得把「必须读得出的那一句」压到次文基准以下。** 行级 `opacity` 是乘法：
作用在已经降过一档的 `--text-secondary`（50%）上会直接击穿基准 —— 2026-10-15
「文件历史」页实测到 **1.96:1（亮）/ 2.75:1（暗）**，而那一行恰好承担
「**为什么**这一版用不了」。判据：淡出是**补充**通道，不是替代 ——
当禁用语义已由形态（空心圆点）与文字各自承担时，必须读得出的那一句要走 `--text`
（同页实测 4.74:1 / 5.27:1，回到次文基准之上）。这与 §2.1「降到 `--text-faint`
是降两档，只在文字本身是唯一状态信号时才用」是同一条精神，只是淡的是整行而不是颜色。

### §3.6 字重

字重只有 400 / 500 两档。刻意偏离通用字重表时，在注释里写明差异与理由。

### §3.7 内容卡与跨进程几何

内容卡：圆角 `--radius-md` + 底色 `--bg`。
与主进程共享的几何值（如 `titleBarOverlay.height` 的「菜单条高」）以主进程为准，
渲染层不另记一份。

**次级辅助面走 `--bg-raised`。** `--bg-raised` 的 token 注释原文就写着
「抬升面：**次级卡片**、选中底、代码块底」——所以「不是内容卡、但需要一个
可辨的底面」的块（如首页上手清单）用它，是引用这个 token 的自有语义，
不是新开一档。这类面**一律不带边框**：边框是内容卡的身份，次级面靠底色区分。

### §3.8 首页主列的垂直节奏

首页英雄区（标题 → 场景胶囊 → 能力 chip → 上手清单 → 输入卡）的间距**固定为**：

| 相邻两段 | 档位 | 理由 |
| --- | --- | --- |
| 标题 → 场景胶囊 | `--space-4` (12) | 同一个头部单元：标题是身份，胶囊是它的作用域限定 |
| 场景胶囊 → 能力 chip | `--space-4` (12) | 同一个控制簇的第二行：chip 是选中场景的**下钻** |
| 能力 chip → 上手清单 | `--space-6` (24) | 控制簇结束、任务区开始 —— 主列里最大的一档 |
| 上手清单 → 输入卡 | `--space-5` (16) | 清单的按钮指向输入卡，故比 24 亲密；但必须 **> 清单内部行距（`--space-3`）**，否则两者读成同一块 |

三条推论：

- **12 : 12 : 24 : 16 只用三档**，不新增档位。`--space-7`(32) 留给模态与大弹层。
- **`64px` 这类档外值不得再出现在这里。** 这里曾经有一个 `margin-bottom: 64px`，
  它是给「场景胶囊 → 输入卡」标定的；能力 chip 那一行后来被插进了这段空白里，
  64 却从没被重新分配 —— 结果主列**最大的一段空白落在两个本该挨着的控件之间，
  两件不同的事之间却是 0**。节奏失衡几乎都长这样：不是数错了，是**分组变了而间距没跟着分**。
- 英雄区在「扣掉案例槽预留」的区域内垂直居中，所以
  `.home-main` 的 `padding-bottom` 同时决定**上游留白与下游间隙的配比**。
  案例区高度变了要跟着改（案例区实测高 + 底距 56）。

### §3.9 盒子预算

**一个页面只允许一个「内容卡」级的主盒子。** 首页主列就是输入卡：
唯一的白底、唯一的 `--shadow-input`、唯一的渐变槽。其余元素要么是
**填色无边的次级面**（上手清单），要么是**细边胶囊**（能力 chip），
要么纯排版（标题、案例标题）。

这条不是审美偏好，是「没有视觉重点」的处方：盒子越多，每一个越轻，
整页就越像没做完。加一个新盒子之前先问「能不能不加，只靠间距和字号」。

**上手清单的三态是这条的一个实例**（2026-10-11，issue #148）：清单槽在「加载中」
（骨架）与「读失败」（就地错误 + 重试）时**复用同一块填色无边的次级面**，
错误靠**图标 + 文案 + 重试按钮**表达而**不加边框** —— 加边框等于在主列里放进第二个盒子，
而「读失败」并不是一个新物种，它只是这个地方的另一种状态。三态换形态**不换槽**，
所以 §3.8 的底距（`--space-5`）不动。

## §4 加载 / 空 / 错误三态

**三态必须互斥且各自可辨**：

| 态 | 判据 |
| --- | --- |
| 加载中 | 数据为 `undefined` |
| 真空 | 数据为 `[]` |
| 错误 | 就地呈现，并给出重试动作 |

数据到达前不得显示「无数据」类文案；错误态与「数据还没回来」在视觉上必须可区分。
结构已知的等待场景用骨架屏：骨架行与真行同尺寸、同类名，使列表到达时是
「同一片区域被填上」，而不是整块替换。骨架自身用 `role="status"` 承担「在读取」语义。

**首页上手清单是这条的一个完整实例**（2026-10-11，issue #148）：它的结构是固定的三行
加一句说明，所以有「加载中」（同结构骨架 + `role="status"`）与「读失败」
（`role="alert"`：原因 + 重试）两态，「三步完成」时收成一枚「上手清单」小按钮 ——
**只有那一态才是什么都不显示（只剩按钮）**。此前三者共用一句 `return null`，
读失败与「还在读」都长得像「这个应用没有引导」，是本条最典型的反面教材。
它没有「真空」态：三行是固定结构，不是列表。

## §5 受控例外

§5.1 禁止的布局属性过渡**默认不放行**。确需破例的必须在这张表里**登记并编号**，写清理由；
代码里引用一律写 `docs/DESIGN.md §5 受控例外 ③` 这种**编号**形式，
**不要另起说法**（「第二条 width 例外」这类描述性叫法一律不认）。

**编号是全局序号** —— 一条一个号，按登记顺序往下编，不按禁止项分组、不按组件分组。三条理由：

- 本节只有「编号」一列；禁止项本身在 §5.1 是**一条总则**（`width`、`height` **等**
  触发布局与重排的属性），没有可以拿来分组的多个禁止项。再分「width 组第 2 条」
  只会让同一个例外有两个名字。
- **这不是假想的风险**：`app.css` 里曾同时出现「受控例外 ④」与「第二条 width 受控例外」，
  指的是同一件事。两套编号并行时，读的人无从判断哪个才是权威。
- 全局序号还让引用可以**机械校验**（`scripts/check-design-exceptions.mjs`）：
  代码里的编号都能在表里查到，表里的编号都在代码里有出处。

**编号从 ③ 起，且一律不复用。** ①② 在本项目没有对应实现（本节的编号历史上就不是从 ①
连续开始的），号位**留空**，以免与既有引用错位。同理，条目日后作废时**保留号位**并写明
「已撤销」—— 让后一条补上来，会让历史提交里的引用指向另一件事。

| 编号 | 例外 | 理由 |
| --- | --- | --- |
| ③ | `width` 过渡 —— 右侧栏开合与全屏（`.panel-slot`、`.preview-panel`） | 面板是**让位栏**（把消息列推开），不是浮层 —— `transform` 不改变布局宽，表达不了「让位」。`.panel-slot` 是常驻的动画载体（面板本体条件挂载，挂载即终态、没有起点可跑），宽度由 TSX 内联 style 驱动；`.preview-panel` 的同一条 `width` 还兼管**全屏扫开**（panelWidth → 100%）与停靠态调宽（sash ±10px / 键盘）。三条附则：`display:flex` + 子项 `flex-shrink:0`（否则面板高度塌成内容高，内部滚动区失效）；`visibility` 参与过渡（滑动中保持 visible，收成 0 后才移出 Tab 序与 a11y 树）；`overflow:hidden` 常驻（滑动期间面板仍按 panelWidth 渲染，靠容器裁掉溢出）。**sash 拖拽中**与**窗口 resize 手势期间**停过渡（否则面板追不上鼠标 / 与窗口边缘错拍）。代价：滑动期间消息列每帧重排（约 12 帧布局），已知并接受。 |
| ④ | `flex-basis` 过渡 —— 左侧栏折叠（`.sidebar`） | 折叠同样是**让位**语义（推开内容，不是浮层覆盖），`transform` 表达不了；元素常驻 DOM（`data-sidebar` 状态，不再条件挂载）才有「起始态→终态」可跑。`padding-inline` / `border-right-width` **不参与过渡**、在 t=0 就归零 —— border-box 下它们会顶住 `flex-basis`（只归零 flex-basis 时理论值 25px、实测渲染盒 24.8px，而不是 0），而 `artifact-panel` 的 `maxPanelWidth` 正是量这个盒子，归零才保住「收起时量到 0」的既有契约。`visibility` 参与过渡只服务 a11y。代价与 ③ 同款：折叠期间侧栏内容随宽度重排，已知并接受。 |
| ⑤ | `height` 过渡 —— widget iframe 高度（`.widget-frame`） | 跨文档的 iframe **只能由宿主改盒子高度** —— `transform: scale` 会缩放内容，并错位 iframe 内部的点击 / 滚动坐标。高度由 TSX 内联 style 驱动（ResizeObserver 上报 + clamp + 防抖），是离散值，无过渡即逐跳变，故用 `--dur-fast` 让微增长平滑。**轨道（`.turn-nav`）的高度不过渡** —— 它曾有一条同类例外，本项目判定「收益不抵一条例外」已撤销（见 `app.css` 该处注释），所以 ⑤ 只对 widget iframe 成立。 |

同性质的元素不做退场动画、入场照做。
未登记的布局属性过渡一律不放行。

### §5.1 禁止过渡布局属性

`width`、`height` 等触发布局与文字重排的属性**不参与过渡**。
需要表现「长度变化」时用 `scaleX`，不要过渡 `width`。

### §5.8 进出场不对称

离场比入场快 —— 用户已决定离开时收得快。同类 hover 浮起元素同规矩，
不许一处硬闪、一处渐变。

## §6 禁止清单

- 原生 `<select>` —— 一律用 `settings/select-field.tsx` 的自定义外观
- 过渡布局属性（见 §5.1）
- 把「加载中」和「空」混为一谈（见 §4）
- 在组件里新造类名 / 复制视觉值 —— 应抽共享组件或收敛到既有类
- 隐藏核心功能

「新造类名」属待办：需要共享组件（如 Switch）时优先抽组件，而不是复制样式。

## §7 组件行为

### §7.1 焦点指示

焦点指示用 `--text-secondary`，与全局焦点环同色。

### §7.3 非模态浮层

「外点即关、不阻断页面」的浮层**不声明 `dialog`** —— 声明了就变成模态语义。

### §7.6 状态不只靠颜色

状态必须能**不看颜色也读得出**：位置、文字、形态各自都能独立表达。
载入指示（转圈）全局只有一个 class，直径由组件内联给出，且不借状态色 ——
转圈只表「进行中」，语义由相邻文字承担。

### §7.8 滚动

滚动容器的行为与「跟着滚」的场景保持既有口径。

### §7.9 hover 浮现的控件：`opacity` + `pointer-events`，**不用 `visibility: hidden`**

行内操作钮（`.task-item-ops`、`.space-group-actions`）只在 hover / 焦点进入时浮现，
**隐藏态一律写 `opacity: 0` + `pointer-events: none`**：

- `visibility: hidden` 会把子树里的按钮**移出 Tab 序列**，于是 `.foo:focus-within`
  **永远不可能触发**（够不着就进不去焦点）—— 键盘用户彻底没有入口，
  而视觉上一切正常，截图断言也看不出来。
  2026-10-03 修：会话行的「导出 / 重命名 / 置顶 / 归档 / 删除」与空间组头的
  「+ / ⋯」此前正是这种状态，键盘完全够不着。
- `pointer-events: none` 是配套的**硬要求**：只降透明度的话，透明按钮仍然接得到点击，
  点行尾那一格空白就会误触一个看不见的按钮。
- 进出场时长仍按 §5.8（淡回 `--dur-fast` / 浮现 `--dur-base`）；
  不再过渡 `visibility`，因为它已不参与控制。

守卫见 `tests/e2e/session-pin.mjs` 的③：Tab 从行主体走进操作钮，
并断言它**真的可见**（`visibility: hidden` 会让这条同时拿不到焦点、等不到淡入）。

> **例外：命令面板的收藏星标（`.palette-star`，2026-10-04）** —— 它是嵌在行
> `<button>` 里的 `span`（button 套 button 非法），点击**照样冒泡到行**；
> 「点星标会不会误触收藏」由 JS 的前置判断守着 —— 未收藏的行上，星标那一格
> 等于「点行」（执行条目）。因此这里**不写** `pointer-events: none`，依据是实测：
> 加上它会让 `.palette-star:hover` 永远不触发（拿不到命中目标的元素也没有 `:hover`），
> 白白丢掉悬停变淡的反馈，而点击行为**毫无变化**。两者的等价性与「去掉前置判断
> 会怎样」都记录在 `tests/e2e/palette-memory.mjs` 的文件头反向验证里。

### §10.3.1 减弱动态效果（`prefers-reduced-motion: reduce`）

**系统开启「减弱动态效果」时，`app.css` 里的动画必须全部停掉。** 规则块在
`app.css` **文件末尾**（`@media (prefers-reduced-motion: reduce)`），分四组：
打字机与光标、无限循环动效（转圈 / 呼吸点 / 扫光）、一次性入场动画、
以及沿袭下来的 `.turn-nav` 过渡豁免。

**关的是「动画」还是「过渡」要把准**：第 ③ 组只写 `animation: none`，**关不到
`transition`** —— 凡是用过渡做的入场（如 `.case-cover img` 的封面淡入）必须在
第 ④ 组（`transition: none`）单独列一行，别以为进了这一块就自动被关掉。

**位置是硬约束，不是排版偏好**：`@media` 不提高优先级，同级选择器靠源码顺序裁决；
动画宿主的声明遍布全文（`.toast` / `.pop-menu` / `.questionnaire-card` …），
规则块放在中段会被它们盖掉。新增动画时**去那里补一行**。

> 已覆盖的入口（2026-10-01）：15 个 `@keyframes` 的全部宿主 —— `.home-title-char`、
> `.home-title-caret`(±`::after`)、`.spinner`、`.text-shimmer`、`.tool-dot.running`
> 以及 33 个入场动画宿主（`page-in` / `pop-layer-in` / `fold-in` / `backdrop-in` /
> `toast-in` / `jump-to-bottom-in` / `stream-reveal` / `questionnaire-slide-up`）。
> 此前只覆盖 `.turn-nav` 一处。
>
> 命令面板（2026-10-03）：`.command-palette` 的入场 + 退场两条一并加入关停清单。
> 退场那条选择器带 `[data-closing]` 属性，特异性高于本块的 `.command-palette`，
> 因此**单列一行**才关得掉（关停后元素停在基础态 = 正常可见，随后按 `--dur-fast`
> 的定时器卸载，等于直接消失 —— 对 reduced-motion 是正确形态）。
>
> 案例封面淡入（2026-10-03）：`.case-cover img` 的 `opacity` 过渡**不是动画**，
> 加进第 ④ 组（`transition: none`）—— 关掉后实图直接出现，不再从兜底暗底淡入。

**关动画 ≠ 回到「正常样子」。** `animation: none` 只是让元素回到**基础态**，
而基础态不一定是它本该显示的样子。**每关一个动画都要问一句：关掉之后元素停在
基础态，那个状态对吗？** 本案里三条都不是：

| 元素 | 基础态 | 关掉动画后该给的终态 |
| --- | --- | --- |
| `.home-title-char` | `opacity: 0`（靠动画淡入、`both` 填充） | **`opacity: 1`** —— 少了它，首页标题永久不可见 |
| `.home-title-caret`(±`::after`) | 无（恒亮） | **`opacity: 0`** —— 它的终态是「收笔后隐」，不是停成一支恒亮的光标 |
| `.text-shimmer` | 背景定位 0%，文字被 `background-clip: text` 裁在 26% 的极浅色上 | **改回实色** `color: var(--shimmer-color)` —— 停在基础态等于这行字没写 |

反过来说，一次性入场动画的基础态**就是**终态（它们的 keyframes 只管「从哪来」），
所以那一组只写 `animation: none`；写多余的终态反而会掩盖真正的陷阱。

这条有 e2e 防线：`tests/e2e/gui-smoke.mjs` 用 `emulateMedia({ reducedMotion: 'reduce' })`
断言「标题文字非空且 `opacity` 为 1」「`.spinner` / `.text-shimmer` 的 `animation-name`
为 `none`」，并先用未开启状态做反向对照；去掉终态那行，断言会红。

### §10.3.2 档外色彩与阴影（**登记在案，不为了「统一」去动**）

下列取值**刻意**不走 `--cat-*` 六槽或 `--shadow-*` 三档，各有语义，已登记：

| 项 | 取值 | 为什么 |
| --- | --- | --- |
| **控件 scrim**（`.attachment-remove`） | `rgba(0,0,0,.55)`、hover `.78` | 挂在缩略图上的删除键要**压住它下面那张图**才能让白 ✕ 可读。语义是「控件 scrim」不是模态背板 —— 收编进 `--overlay` 会把「模态遮罩」的语义污染掉（`app.css` 的 `--overlay` 注释里写了它当时被留下的理由，但**登记一直没落到本表**，2026-10-04 补上） |
| **全屏看图沉浸遮罩**（`.image-preview-overlay`） | `rgb(0 0 0 / 72%)` | 看大图时要的是「画面外全部退到幕后」，比模态背板的 40% 重一档。同理不并入 `--overlay` |
| 文件类型分色 | 9 个选择器、7 个色值：`.doc-file-pdf` `#c94f4f`、`.doc-file-word` / `.file-icon-code` `#4a7bc8`、`.doc-file-excel` / `.file-icon-markdown` `#4b9e6b`、`.doc-file-ppt` `#d98a3d`、`.file-icon-config` `#b7903d`、`.file-icon-image` `#8b6bc8`、`.file-icon-media` `#c85a8f` | 按**族**分色（族来自 `shared/doc-formats.ts` 的 `docBadgeOf`），**信息性**不是状态。`--cat-*` 只有 6 槽，塞不下；且这组色要能与各主题共存，塞进分类槽会挤掉真正的分类语义 |
| 专家头像底 | 8 色（`EXPERT_AVATAR_COLORS`，`app.js`） | 由名字哈希取色、只为「同屏可区分」，**没有语义**。走 token 反而会暗示它有语义 |
| 档外阴影（5 处声明） | `.preview-panel.fullscreen` `-8px 0 24px rgb(0 0 0 / 6%)`；`.preview-menu` `0 8px 24px rgb(0 0 0 / 18%)`；`.preview-pdf-body .react-pdf__Page` 与 `.office-docx .docx-wrapper>section.docx` 的纸张阴影 `0 1px 4px rgb(0 0 0 / 15%)`（同值两处）；`.mcp-switch-thumb` / `.skill-switch-thumb` `0 1px 3px rgb(0 0 0 / 20%)` | 都是**场景值**：全屏面板向左的投影、预览菜单、「纸」的抬升、开关滑块的贴边投影。归 `--shadow-sm/md` 会让轻的变重、重的变轻 —— 收编的代价大于收益。（原第 6 处 `.capability-chip` 的 `0 12px 32px -8px rgba(0,0,0,.02)` 已于 2026-10-02 收编为 `--shadow-sm`：浅色下两值几乎等值，而暗色下 2% 黑完全不可见——暗色主题接线后这处不再成立，是收编的直接动因） |

> **中性面阶梯的已知倒挂（登记在案，不为了「统一」去改值）**：白底上的等效值是
> `--bg` 255 → `--bg-raised` 247 → `--bg-hover` 242 → `--bg-chip` 240 → `--border` 230。
> `--bg-chip`(6% 黑) **比** `--bg-hover`(5% 黑) **还深** —— 静态 chip 底比 hover 底重，
> 方向是反的。这是既有的一处系统内倒挂，牵动全站 chip 的 hover 反馈，
> 改它要让一批组件的悬停「变浅」。**登记在此，本轮不动**；将来若要收口，
> 正确的动作是让 `--bg-hover` 成为最深的**交互**面（非静态面），
> 并逐个复核把 `--bg-chip` 当基线用的组件。

> 这 5 处**没有暗色版**（暗色变量块只覆写 `--shadow-sm/md/lg/input`）。
> 暗色主题已于 2026-10-02 接线（设置 → 通用 → 外观，三档；`data-theme` 属性驱动，
> 持久化在 `preferences.json` 的 `theme` 字段，缺省 `light`）。接线时的复审结论：
> 纸张与开关滑块的 3 处落在**自带亮底**的元素上（纸永远是白纸、滑块有自绘底），暗色下依然成立；
> 预览菜单与全屏面板的 2 处在暗色下的分层由底色差与边框承担（`--bg` 对 `--bg-raised`），
> 阴影弱化可接受——若暗色实测中发现分层不足，优先给这两处补暗色版而不是动档位。
## §11 「极光墨」视觉语言（2026-10-22）

首页、侧栏、设置页、会话页共用一套新的视觉语言，代号**极光墨（Aurora Ink）**。
本节只写「新增了什么、哪些旧规矩被它替代、哪些红线仍然不许越」，取值真源仍是
`app.css` 的 `:root`（§2.0 的双块同构不变）。

### §11.1 新增的 token 家族（都已进 `:root` 与暗色块）

| 家族 | 成员 | 语义 |
| --- | --- | --- |
| 画布 | `--canvas` / `--canvas-warm` | 页面底色（冷调，不再是纯白）。**纯白只允许出现在卡片内部** |
| 面 | `--surface` / `--surface-1` / `--surface-2` 与 `--bg-sidebar` | 抬升面阶梯。侧栏是其中**最低**的一层，卡片最高 |
| 品牌 | `--brand` / `--brand-soft` / `--primary-text` / `--ring` | 唯一的强调色（teal）+ 它上面的文字色 + 焦点环 |
| 极光 | `--aurora-1` / `--aurora-2` / `--aurora-3` | 三团径向渐变的**颜色**，以及由它们合成的 `--aurora-field`（一整张背景层）。两者都只许出现在「视图卡」的背景层（`.app` 的直接子元素那条 `margin/border-radius` 规则），不许进组件 |
| 薰衣草 | `--iris-*` | 次强调（紫）。命名刻意避开 `violet` —— 那与 CSS 命名色同名，会让 `check:theme-tokens` 的字面量检测误判 |
| 玻璃 | `--glass-bg` / `--glass-bg-strong` / `--glass-border` / `--glass-blur` | 雾面层。`--glass-bg-*` 必须带透明度，`--glass-blur` 是 blur 半径 |
| 渐变 | `--grad-primary` / `--grad-brand` / `--grad-sheen` / `--grad-ring` | 四个固定配方。**不要在组件里现写 linear-gradient** |
| 展示字 | `--text-display` | 46px，仅首页主标题与同类欢迎语使用 |

### §11.2 盒子与描边的契约变更（重要）

**输入卡外槽（`.composer-slot`）从「渐变底色」改为「实心底 + 1.5px 渐变发丝描边」**：

- 底色 `background` 用 `--surface-1`，`background-image` 必须是 `none`；
- 渐变只出现在 `::after`（`inset: -1px` + `mask-composite: exclude` 只留一圈边）；
- 理由：渐变铺满底色时，槽内除输入卡以外的工具行（工作空间 / 默认权限）坐在色带上，
  读起来「脏」；把渐变收到边缘之后，页面只在一个地方有光。

`tests/e2e/dark-polish.mjs` 的断言已随之改写（底色 `none` + 描边渐变随主题变），
它盯的仍是**旧缺陷**（#105 的暗色亮边），只是换了正确的观测点。

### §11.3 侧栏的三级文字色必须保住

`.nav-item` 用 `--text`（已就绪），未就绪项（`.nav-item-pending` / `:disabled`）用
`--text-secondary` —— 差值就是 §2.1 的「降一档」。**不要把两者统一到同一个档位**：
`tests/e2e/onboarding.mjs` 有一条断言专门盯着这件事。

侧栏背景是 `--bg-sidebar` + `backdrop-filter: blur(--glass-blur) saturate(170%)`，
它是一条**性能敏感**的规则：`--glass-blur` 不许超过 20px，也不许在滚动容器上重复叠加。

### §11.4 动效

零新增时长档位（仍是 §2.8 的三档）。新增的只有「眉标圆点的呼吸」一条无限动画，
它必须出现在 `prefers-reduced-motion` 的第 ④ 组关停清单里 ——
`tests/e2e/ui-aurora-ink.mjs` 会真的开一次减弱动效去验。

### §11.5 禁止

- 不许在组件里写 `hsl()` / `rgb()` / hex / 命名色（`check:theme-tokens` 会报错）。
- 不许为了「更炫」再加第四团极光或第二种强调色：视觉重心只能有一个。
- 不许把玻璃面用在内容滚动区（`backdrop-filter` 在滚动时逐帧重绘）。

### §11.6 字体策略：不随包任何 web font

`--font-body` 是**系统字体栈**（`-apple-system` / `SF Pro Text` / `Segoe UI Variable` /
`PingFang SC` / `Microsoft YaHei`），刻意**不写 Inter 之类的 web font**：
本项目不发字体二进制，写了也会在 macOS 静默回退到 SF、在 Windows 回退到 Segoe UI，
而文档上的「Inter 负字距」就成了空话。展示标题的个性靠**字号 + 负字距 + 字重**建立，
不靠换字体 —— 这是「不承诺没做到的事」在本层的具体落实。

## §12 专注模式：把会话从「工具界面」切成「一页纸」

办公场景里有一半时间是在**读**（读 agent 写完的方案、读长报告、反复对照上一轮结论）。
普通界面是为操作设计的：侧栏 264px、标题栏、常驻输入卡。§12 定义的是另一个界面状态。

### §12.1 入口与退出

- 入口两个，缺一不可：侧栏「专注模式」（`aria-pressed` 反映状态）、`⌘⇧F` / `Ctrl+Shift+F`。
  快捷键不能是唯一入口——它不可发现。
- 退出两个：**左上角** `.focus-exit` 胶囊、`Esc`。**只进不出是最糟的失败形态**，
  所以胶囊与 `Esc` 两条都要有；`Esc` 在输入框/文本域里不生效（那里是「放弃编辑」）。
- 胶囊为什么在左上（2026-10-24 评审实测后从右下搬过来）：右下角是发送按钮的家，
  900px 最小窗宽下两者擦边约 4×24px；而且入口（侧栏里的「专注模式」）本来就在左上，
  进出口同侧才有位置记忆。它同时接管了那个被隐藏的侧栏开关腾出来的位置。
- 模态/命令面板开着时，`Esc` 归它们 —— 一次按键只允许有一个后果。
- 快捷键匹配 `event.code === "KeyF"` 而不是 `event.key`：中文输入法或非拉丁键盘布局下
  `key` 不是 `"f"`，用 `key` 判断会让 ⌘⇧F 静默失效。

### §12.2 收什么、不收什么

| 收（进入后不渲染） | 理由 |
| --- | --- |
| 侧栏 | 读的时候一次也不会点 |
| 首页案例区（`.cases`）与它的 252px 底部预留 | 见下 §12.2.1 |
| `.home-main` 的 hero 光晕 | 它固定在内容列上，换底色后会留下矩形硬边；读的时候也没有信息量 |
| 左上角的侧栏开关（`.sidebar-toggle-btn`） | 侧栏已经 `display:none`，点它只改状态、屏幕上毫无反应；它是暗色截图里最亮的像素 |
| 极光强度（`--aurora-field` 在浅色混到 45%、暗色 62%） | 读长文时是干扰，但要留住这套语言的余温 |

| 不收 | 理由 |
| --- | --- |
| 输入卡 | 读完往往要接着问，它要在手边 |
| 标题栏 | 它是窗口拖拽区，藏了就没法拖窗口 |

> **标题栏这条曾经写过「只把 `opacity` 降到 0.55」——那是一条空转的规定。**
> 2026-10-24 实测：视图卡（`.app` 的直接子元素）整条盖住了 30px 的标题栏，
> 截图里 css y=30 处根本没有第二条缝。作用在一个被完全遮住的元素上的降权，
> 屏幕上看不见，测试也测不出来 —— 已删掉，别再写回来。

### §12.2.1 为什么案例区是「撤掉」而不是「改两列」

`.cases` 在首页里是**绝对定位**的，`.home-main` 用 `padding-bottom: 252px` 为它留位。
所以任何让案例区变高的改动都会直接压到输入卡上：

- 把四列改成两列，案例区从 220px 长到 **478px**，实测压住 `.composer-zone` **27px**
  （`.cases` y=324 vs `.composer-zone` 232–583）；
- 而它本来只是「不知道做什么」的启动器，四张封面又恰好是首页最亮的四块矩形 ——
  和「少被打断」正好相反。

撤掉之后把 252px 的预留归还给英雄区（`padding-bottom: var(--space-6)`），
首页才真的是一页纸。**代价写在明处：专注模式下首页不再承担引导职责**，
要案例按 `Esc` 出来。

**2026-10-24 二轮修正（设计师复核 + 真实截图各抓到一处）：**

1. **胶囊必须验「落在哪」**，不是只验「在哪一边」。第一版把退出胶囊搬到左上后，
   它完整盖住了返回键（css 22…50）与标题前三个字 —— 位置对、结果错。
   `.chat-header` 的右让写在 `html[data-focus="on"] .app .chat .chat-header` 上，
   因为 `.sidebar~.chat .chat-header`（(0,3,0)）比 `html[data-focus="on"] .chat-header`
   （(0,2,1)）高，短选择器会被静默盖掉。测试里对应一条**矩形不相交**断言，
   不许再用 `top < 120` 这种恒真判据。
2. **页眉之外还有四处常驻操作 chrome**：右上浮标组（`.panel-toggle-group`，它被
   「卸玻璃」的排除法专门摘出去了，够不到）、右侧轮次导航（`.turn-nav`）、底部遥测行
   （`.session-stats`）、消息操作行（`.entry-toolbar`）。专注态统一降到 `opacity: 0.4`，
   hover / `:focus-within` 回到 1 —— **不许用 `display: none`**：鼠标用户会永远拿不回来。
3. **暗色的底光要一起收**：极光只活在顶上四分之一，而 `--canvas-floor` 从 46% 压到最底，
   正文所在的垂直中段实测比画布还黑（`#06090f`）。专注态设 `--canvas-floor: .28`，
   并让橙（`--aurora-3` 32%）留在底部 —— 换的是同一组 `--aurora-*` 的强度，不违反 §12.5。
4. **专注态下「折叠侧栏」不再生效**：`⌘.` 与命令面板那条会改 `data-sidebar`，
   而 `.app[data-sidebar="collapsed"] .chat .chat-header` 会把页眉右移 32px ——
   一次按键一个看不见的后果。`toggleSidebar` 在 `data-focus="on"` 时直接返回。

### §12.3 阅读度量（本模式唯一真正改变读感的地方）

- 列宽：首页 `900 → 720`（内容盒 852 → 672），会话 `832 → 720`（正文可用宽 696）。
  **一行中文约 45 字**（672 ÷ 15 ≈ 45；会话侧 696 ÷ 15 ≈ 46）——这是量出来的数，
  不是「34–38 字」。想要 34 字左右得把列宽收到 570 以内，那是另一个取舍，本轮不做。
- 会话列宽走 `focusContentWidth()`：**只收不扩**，窗口本来就比 720 窄时保持原值——
  否则窄窗口下会直接出横向滚动条。
- 正文字号：`html[data-focus="on"] .entry.assistant { font-size: var(--text-emphasis) }`。
  **只给正文一个元素**，不整片覆写 `--text-body` —— 那样会把工具行、markdown 表格、
  todo、task-agent 一起顶到 15px，正文与「过程信息」的字号差被抹平，长会话里
  过程块反而更抢戏，与专注模式的目标相反。复用已有档位，不新造第 5 档字号。
- 会话页眉（`.chat-header`）从「工具栏」降为「页标题」：卸掉雾面玻璃与那条通栏横线，
  标题降到 `--text-secondary`。不卸掉它，拿掉侧栏之后剩下的仍然是一个「应用窗口」。

### §12.4 状态与持久化

- 真源是 `localStorage` 的 `zerowork.focusMode`，**不进 `preferences.json`**：
  专注模式是「此刻的姿势」，不是跨设备偏好。
- 首屏不闪变：初值同步读 localStorage，效果里写到 `<html data-focus>`，
  CSS 只认 `html[data-focus="on"]`，所以第一次绘制前属性已经就位。
- 坏值 / 写不进（隐私模式）都按「关」处理，且不让界面崩——失败方向是回到普通界面。

### §12.5 禁止

- 不许在专注模式里加第二种强调色或第二处动画。
- 不许用「改某一层的 `background`」来降极光强度：真正画极光的是视图卡那条 (0,7,1) 的
  排除法规则，它会整条盖住 `.app`。**只能改 token**（`html[data-focus="on"]` 上重定义
  `--aurora-field`）。第一版就是写错了层：屏幕上 100% 没变，而 e2e 因为读 `.app` 的
  计算背景反而变绿 —— 断言要读**被画出来的那一层**。
- 不许把「专注」做成永久全屏：它是可逆的姿势，不是模式切换。
- 不许用 `!important` 盖会话列宽（那是 `--chat-content-width` 内联变量，走 JS 传值）。

## §13 开局模板：自定义内容与内置内容的同一族感（2026-10-25）

首页案例区第一次出现「用户自己的内容」与「随包分发的示范」并排。规则只有一条：
**两者必须像同一个抽屉里的东西，但不能长得一样。**

### §13.1 身份由色相承担，徽标只做确认

- 自定义模板的封面用 `--brand`（青），内置案例按 `--cat-N` 分类色；
- 「我的」徽标是**玻璃白底**（`--glass-bg-strong` + `blur(12px)` + `--border-strong`），
  不染 accent。第一版写成 `color-mix(accent 12%, var(--bg))`，亮色下实测 **1.05:1** ——
  等于一个看不见的形；`border` 也只有 1.41:1。
- 徽标偏移必须是 `--space-4`（12px）。封面圆角半径 20px 时，`--space-2`(6px) 的
  圆心距 √2×14≈19.8 与圆**恰好相切**，视觉上像贴歪了。

### §13.2 列表行是容器，不是控件

- `.starter-list` 出一圈 `--border` 边框 + `--radius-md`，行之间只留一条分隔线；
  与同页「更新渠道」（`.provider-list` / `.provider-row`）完全同一套语言。
- 反面教材（第一版）：每行套一只圆角描边白盒 —— 亮色行底 `--bg` 与面板同色，
  只剩 1.20:1 的边框；暗色行底比面板更暗，整条变成凹坑。一个面板里两套行的语言。

### §13.3 编辑就地展开，删除必须二次确认

- 编辑器渲染在**被编辑的那一行下面**（`is-editing` 用 `--row-selected` 标记），
  不是列表末尾：12 条模板时，放末尾会让「点第一行编辑」在视口里毫无反应。
- 删除按钮的 `--danger` 语义**常驻**，点击后进入 `confirming` 态（就地出「确认删除 / 取消」）。
  模板是用户自己写的一段话，误点一次就没了。

### §13.4 首页页头不承诺做不到的事

「从你的模板开始」只在自定义模板 **≥ 4 条（铺满一行）** 时才用；否则保留
「不知道做什么，试试最佳实践案例」。1 条模板 + 3 张内置时，前者是在承诺一件不成立的事。

### §13.5 校验口径的单一真源

标题 40 字 / 提示词 2000 字 / 最多 12 条，三个数只在
`src/shared/starter-prompts.js` 里定义一次；daemon 用它判真假，渲染层用它出计数与
`maxlength`，测试用同一份常量。**不要在界面里另写一份数字。**

## §17 十连视觉补丁（2026-10-25）

这一节记录一批「只加不减」的视觉改造，每条都写清它解决什么问题、以及**踩过的坑**，
因为其中两条的实现方式是被实测推翻过一次才定下来的。

### §17.1 主题配色预设

五款预设只换**强调色与极光色相**，明暗档位、间距、字号、对比度一律不动：

| id | 名字 | 强调色 | 极光 |
| --- | --- | --- | --- |
| `aurora` | 极光墨 | 青 | 青 / 靛 / 橙 |
| `dusk` | 暮光 | 紫罗 | 紫 / 紫罗 / 粉 |
| `sunset` | 落日 | 琥珀 | 琥珀 / 橙 / 朱 |
| `pine` | 松林 | 松绿 | 松绿 / 绿 / 金 |
| `graphite` | 石墨 | 中性 | 中性灰 |

**驱动方式**：`<html data-palette="dusk">`，CSS 在 `:root` 段按属性选择器覆盖
`--accent` / `--brand` / `--aurora-1|2|3` / `--aurora-field`。
**不允许**让预设去改 `--canvas` / `--text` / 阴影档 —— 那样五个预设会变成五个主题，
对比度就没法统一保证。

### §17.2 极光漂移：必须画在外壳自己的 `::before` 上

第一版给外壳加 `animation: aurora-drift-a`，实测动画名仍是 `backdrop-in` ——
外壳已经有一条入场动画，同一属性写两次会互相顶掉。

第二版改成 `.app` 下的独立覆盖层 `<div class="aurora-drift">`，结果是**整页被冲淡**：
覆盖层带 `opacity: .72`，又压在内容之上（`z-index: 0`），卡片全被洗白。

**最终做法**：画在外壳的 `::before` 上，`z-index: -1`、`inset: -30px`、`filter: blur(8px)`，
这样它落在「外壳底色之上、内容之下」，既有位移又不会盖住任何文字。
`prefers-reduced-motion` 下整条关停。

### §17.3 空态插画

`EmptyState` 按标题里的名词自动选图（任务 / 模型 / 文件 / 通用），
**不再让调用方逐处传 art** —— 传参的写法必然会漏，而漏掉的那几处正是最常看到的。
插画走 `currentColor` + `.art-accent`，跟随主题色，不需要额外 token。

### §17.4 代码块行号

行号由 `CodeBlockCard` 自己按 `text.split("\n")` 算，**不把行号作为文本存进界面**：
存进去会让「复制代码」把行号一起复制走。行号槽 `user-select: none`、`aria-hidden`。

### §17.5 设置页阅读进度

每条设置页的滚动容器并不统一（有的在 `.settings-body`，有的在页面自身），
所以用**捕获阶段的 `scroll` 事件**统一处理，而不是给每个页面挂 ref。
进度条 `aria-hidden`，不播报——它是装饰性的方向感，不是数据。

### §17.6 撤下的两项（留档，避免下次再踩）

- **首页「今日回顾」条**：`.cases` 是 `position: absolute; bottom: 56px` 钉在首页底部的，
  任何加在 `.home-inner` 里的兄弟节点都会被它压住（实测：节点在、`getBoundingClientRect`
  有尺寸、但一个像素都画不出来）。要加必须先进 `.home-main` 的流或重排案例区。
- **首页快捷动作卡**：同上，与今日回顾条一起撤下。

两条都写在这里而不是直接删掉，是因为它们是**结构约束**而不是「这次没做」。

## §18 第三轮微交互（2026-10-25）

十个「小而可见」的交互补丁。实现要点与坑：

### §18.1 拖拽高亮：dataTransfer.types 不是数组

DOM 里 `dataTransfer.types` 是 **DOMStringList**（有 `.contains`、没有 `.includes`），
而合成事件里又可能是数组。判断必须两个都接，否则测试里合成 DragEvent 就会抛
`types.includes is not a function`（第三轮实测踩到）。

### §18.2 dragenter/dragleave 计数配对

dragleave 在子元素之间穿行时也会触发。必须 dragDepth 计数，归零才熄灭高亮；
直接布尔置位会闪烁。

### §18.3 token 迷你条：不拿占位常数糊弄

比例的分母必须取 heatmap 的真实单日峰值（含今天），第一版写死 `6e4` 占位被自查拦下。
峰值拿不到（0）就不画整条——空数据比假比例好。

### §18.4 呼吸/跳动动画的关停

`composer-breathe`、`typing-dot`、`toast-progress-drain`、`send-ripple` 全部挂
`prefers-reduced-motion: reduce` 关停；关停后功能语义不变（进度条直接满格消失、
打字点静态显示）。

### §18.5 侧栏折叠

`.sidebar` 的 `flex-basis` 过渡在 §7 就有，本轮核实无需重做——**先查再写**，
避免同一动画声明两次互相顶掉（§17.2 的教训）。

### §19.1 已存在、无需重做（留档防重复造轮子）

- **回到最新浮动按钮**：`.jump-to-bottom` + `showJumpToBottom`（app.js 33188 起），

  `pointer-events: none`，不会把正文挤动。
